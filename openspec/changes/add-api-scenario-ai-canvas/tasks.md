# Tasks

## 1. 建立图模型和兼容层

- [ ] 定义场景图节点、边、位置和 `graph_version` 的 Pydantic schema 与 TypeScript 类型。
- [ ] 为场景增加可选图元数据存储；保证旧场景无需迁移即可读取。
- [ ] 实现 `step_order` 到线性图的派生转换、图到步骤配置的兼容序列化。
- [ ] 增加图校验：环、孤立节点、不可达节点、悬空连线、非法出口和跨项目接口引用。
- [ ] 为图模型编写后端单元测试和前端契约测试。

## 2. 接入自由画布

- [ ] 安装并锁定 `@xyflow/react`；复用已有 `@dagrejs/dagre`，不引入重复布局库。
- [ ] 将 `api-scenario-editor.tsx` 的编排视图拆分为画布、资源栏、节点配置栏和底部校验栏。
- [ ] 实现 API 请求、条件、赋值、等待、轮询、开始、结束和汇聚节点。
- [ ] 实现受约束连线：端口类型、条件出口、变量依赖和禁止环路。
- [ ] 实现拖拽添加、节点移动、节点删除、连线删除、框选、缩放、适应画布和自动布局。
- [ ] 实现画布视图与现有步骤列表视图双向同步，并保留无障碍键盘操作。
- [ ] 增加图快照撤销/重做和未保存状态提示。

## 3. 升级保存、校验、发布和运行

- [ ] 扩展场景保存和步骤替换接口以接受图数据，并保持旧请求兼容。
- [ ] 在保存前服务端规范化节点顺序、边 ID 和位置数据，避免客户端顺序影响执行。
- [ ] 让校验接口返回图错误及其节点/边 ID，前端可定位并高亮问题。
- [ ] 在发布流程中同时检查图结构、接口资产变更和现有变量/断言规则。
- [ ] 为运行快照记录图版本、拓扑顺序、节点状态、边条件和跳过原因。
- [ ] 保证旧线性场景的发布、执行、版本恢复行为不变。

## 4. 实现 AI 场景规划

- [ ] 新增 `POST /projects/{project_id}/api-scenarios/ai-plan` 请求和响应契约。
- [ ] 实现候选接口检索、项目范围校验和敏感字段脱敏。
- [ ] 定义 AI 规划输出 schema：节点、边、绑定、提取器、断言、假设、警告和未解决项。
- [ ] 让 AI 计划先通过服务端图校验，再返回前端预览；拒绝未经资产校验的 URL 或接口 ID。
- [ ] 在空场景和编排工具栏增加“AI 编排”入口。
- [ ] 实现 AI 计划预览、局部重新规划、应用到草稿、放弃计划和错误恢复。
- [ ] 确保 AI 生成场景默认不发布、不执行写操作，并记录计划版本和确认人。
