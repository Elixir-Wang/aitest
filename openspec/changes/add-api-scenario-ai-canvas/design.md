# 设计方案

## 总体方案

采用“画布主视图 + 步骤列表辅助视图 + 右侧节点配置面板”的混合编辑器。

```text
┌────────────────────────────────────────────────────────────┐
│ AI 编排  添加节点  自动布局  适应画布  检查  保存  发布     │
├──────────────┬──────────────────────────────┬──────────────┤
│ 节点资源库   │ @xyflow/react 画布            │ 节点配置     │
│ 接口请求     │                              │ 请求参数     │
│ 条件判断     │  注册 → 登录 → 创建订单      │ 数据绑定     │
│ 数据赋值     │          └→ 清理             │ 响应提取     │
│ 等待/轮询    │                              │ 断言/失败策略 │
├──────────────┴──────────────────────────────┴──────────────┤
│ 图校验结果 · 未配置节点 · 运行状态                          │
└────────────────────────────────────────────────────────────┘
```

画布只允许编排当前项目已有接口资产和内置辅助节点。节点配置继续复用现有 `ApiScenarioStepConfig` 的字段语义；画布只负责编辑图结构、位置和选择状态。

## 技术选型

- 画布：`@xyflow/react`。
- 自动布局：已有 `@dagrejs/dagre`，默认从开始节点向结束节点布局。
- 状态：复用 Zustand 或当前编辑器状态边界；避免把服务端 API 调用放进画布节点。
- 节点样式：使用现有 shadcn/Radix 组件和 Tailwind，不引入另一套视觉系统。
- 撤销/重做：以图快照为粒度，至少覆盖节点、连线、位置和节点配置变更。

## 图模型

现有 `ApiAutomationScenarioStep` 保留作为节点业务配置，新增场景图元信息：

```json
{
  "graph_version": 1,
  "nodes": [
    {
      "id": "step-login",
      "step_id": "step-login",
      "position": { "x": 320, "y": 180 },
      "width": 260,
      "height": 120
    }
  ],
  "edges": [
    {
      "id": "edge-login-order",
      "source": "step-login",
      "target": "step-order",
      "source_handle": "success",
      "target_handle": "input",
      "condition": null
    }
  ]
}
```

节点类型与现有步骤类型对应：`api_request`、`condition`、`wait`、`poll`、`assign`。开始和结束节点是图层控制节点，不落为接口步骤。

图模型规则：

1. 图必须是有向无环图；保存和发布时必须做拓扑检查。
2. 必须存在一个开始节点和至少一个可达的结束节点；孤立节点、不可达节点和悬空连线为错误。
3. `api_request` 和 `poll` 节点必须绑定当前项目接口资产。
4. 节点的 `bindings` 只能引用其上游可达节点的输出、场景变量或环境变量。
5. 条件节点的出口使用稳定的 handle，例如 `true`、`false`；没有明确出口的条件节点不能发布。
6. 汇聚行为在边或汇聚节点上显式声明 `all` 或 `any`，第一版默认 `all`。
7. 节点位置是展示数据，不参与业务执行排序；执行顺序由服务端拓扑排序决定。

## 线性兼容

读取没有图数据的旧场景时，按 `step_order` 生成节点和相邻 `success` 连线，并使用默认的 Dagre 布局。保存后写入图版本，但保留 `step_order` 作为兼容字段和确定性排序的后备值。

旧场景的条件步骤在没有显式边时仍按现有线性语义运行；用户第一次编辑条件出口或创建分支时，场景升级为图模式并要求通过图校验后才能发布。

## AI 编排流程

新增 AI 规划入口，生成结果只作为草稿预览，不直接覆盖当前场景：

1. 用户输入业务目标、步骤上限、运行环境和写操作限制。
2. 后端仅从当前项目接口资产、接口测试用例和项目知识中检索候选接口。
3. AI 输出场景名称、节点、边、绑定、提取器、断言、假设、警告和未解决项。
4. 服务端校验接口 ID、项目归属、图无环性和变量依赖。
5. 前端以预览状态显示节点和连线；用户可逐节点修改或要求 AI 重新规划局部链路。
6. 用户点击“应用到草稿”后，才写入场景编辑器；仍需经过现有检查、保存、发布和运行流程。

建议接口：

```http
POST /projects/{project_id}/api-scenarios/ai-plan
```

请求至少包含 `goal`、`source_scope`、`constraints` 和可选的 `scenario_id`。响应包含 `plan_id`、`graph_version`、`nodes`、`edges`、`assumptions`、`warnings`、`unresolved_items` 和 `confidence`。AI 不能返回未经资产校验的 URL 作为可执行接口。

## 执行与发布

第一版后端执行采用确定性拓扑顺序，暂不承诺真正并行；图结构先完整表达依赖，为后续并行执行保留模型。执行器必须：

- 在运行快照中记录图版本、节点顺序和边条件。
- 条件节点只放行匹配出口，未匹配分支标记为 `skipped`。
- 汇聚节点按 `all`/`any` 规则等待上游结果。
- 失败传播遵循节点的 `on_failure`，不得因画布布局顺序改变执行语义。
- 运行结果包含节点 ID、边条件、输入、输出、断言和跳过原因，便于画布高亮。

发布前必须同时通过现有场景校验和图校验。存在未配置节点、资产变更未确认、未解析变量或不可达节点时禁止发布。

## 风险与回滚

- 数据迁移风险：先增加可选图字段，旧场景按 `step_order` 派生图；迁移失败时仍可使用线性模式。
- 执行风险：第一版不改变旧场景的运行路径；图模式使用新执行入口并保留运行快照。
- 画布性能：单场景首期限制 100 个节点、200 条边，超限提示拆分场景。
- AI 风险：AI 结果只写入预览对象，服务端再次校验接口归属和敏感字段。
- 回滚：通过 `graph_version` 和场景版本记录恢复到上一个已发布图；前端提供列表视图降级入口。

## 测试策略

- 图模型：拓扑排序、环检测、孤立节点、不可达节点、条件出口和汇聚规则。
- 兼容性：旧线性场景读写、发布、运行和版本恢复。
- API：图保存、图校验、AI 计划响应契约、非法接口 ID 和跨项目引用拒绝。
- 前端：节点增删改、连线约束、自动布局、撤销重做、列表/画布视图同步、AI 预览应用。
- 运行：条件分支、上游输出绑定、失败传播、跳过结果和运行快照。
- 性能：100 节点/200 边画布加载、拖拽和布局在可接受时间内完成。
