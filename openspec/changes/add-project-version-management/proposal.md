## Why

当前项目和需求之间只有项目归属，无法表达需求计划交付到哪个项目版本，也无法按版本组织需求、统计范围或建立清晰的发布追溯。系统需要提供轻量的项目版本能力，同时与现有需求文档修订版本保持独立，避免两类版本语义混淆。

## What Changes

- 在每个项目内部增加版本管理能力，支持创建、查看、编辑版本说明、设置当前版本和删除空版本。
- 项目版本不包含状态，不提供全局版本管理入口，也不引入发布流程。
- 每个真实项目维护一个显式的当前版本；新建项目自动创建并选中 `1.0.0`。
- 新建版本默认成为当前版本，用户可以在创建时取消该行为，也可以后续手动切换当前版本。
- 新建需求默认关联项目当前版本，并允许用户从当前项目版本下拉列表中改选。
- 需求列表仅展示所属项目版本号，需求详情展示所属项目版本。
- 需求允许迁移到同项目的其他版本，迁移行为写入操作日志。
- 存量项目首次迁移时幂等创建 `1.0.0`，将项目内历史需求统一关联到该版本。
- 已关联需求的版本不得删除；当前版本必须先切换后才能删除。
- 保留现有 `source_document_versions` 作为需求内容修订历史，不改变其语义和行为。

## Capabilities

### New Capabilities

- `project-version-management`: 定义项目内版本维护、当前版本、需求版本关联、迁移和存量数据初始化规则。

### Modified Capabilities

无。当前仓库尚未建立可复用的项目或需求基础 capability spec，本变更以新增能力形式描述完整行为。

## Impact

- 数据库：新增 `project_versions`，为 `projects` 增加当前版本引用，为 `source_documents` 增加项目版本引用，并增加迁移与索引。
- 后端：新增项目版本 repository、service、schema 和项目内 REST API；扩展项目与需求序列化、需求创建和需求更新校验。
- 前端：新增项目内版本管理页面；扩展新建需求表单、需求列表和需求详情。
- 审计：版本创建、编辑、设为当前版本、删除和需求迁移写入操作日志。
- 测试：增加迁移幂等性、版本约束、权限、API、需求默认关联和前端交互验证。
