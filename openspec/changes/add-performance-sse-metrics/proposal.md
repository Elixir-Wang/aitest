# 新增通用 SSE 性能指标

## 背景

当前性能测试将单接口请求作为完整 HTTP 响应执行和统计，能够度量请求完成耗时、吞吐与失败率，但不能消费 `text/event-stream` 流，也不能回答首内容、首次工具调用、首个业务事件或流完成的时间。不同供应商和内部服务的 SSE 事件名、JSON 结构和结束标记各不相同，若在脚本中写死某家协议，将无法复用且会使配置不可维护。

本变更为性能测试增加受控的 SSE 传输配置、通用事件匹配器、运行期指标采集和目标判定。用户可以手工声明“哪类 SSE 事件的哪个字段满足什么条件”，也可以对项目内单接口或接口场景中的目标步骤执行一次真实 SSE 探测，再由 AI 基于脱敏事件结构生成候选规则。AI 候选必须经现有匹配器确定性回放和用户确认后才能进入性能测试配置。

## 目标

- 支持 HTTP 与 SSE 两种传输方式，既有 HTTP 性能测试行为和配置保持不变。
- 按 SSE 标准解析 `event:`、多行 `data:`、注释与空行边界，并将事件标准化后交给匹配器。
- 允许为一个 SSE 测试配置多个首次命中时间指标，例如首内容、首次工具调用、首次检索结果和流完成。
- 提供受限、可验证的字段选择与比较语义，不允许配置执行任意代码。
- 将 SSE 指标与 HTTP/Locust 原始响应时间分开聚合、展示、设定目标和生成报告，避免污染现有 HTTP 延迟与 RPS。
- 提供 SSE 样例预览校验，帮助用户确认事件名、字段路径和首次命中位置。
- 支持基于当前未保存请求参数执行一次受控 SSE 探测，AI 只生成声明式指标候选，并返回真实样本上的首次命中证据。
- AI 不可用或候选未通过回放时使用确定性识别结果；候选配置仍须由用户确认后保存。
- 记录缺失、解析错误、超时和提前关闭等数据质量信息，使无工具调用的正常流不会被误判为失败。

## 非目标

- 第一阶段不支持 WebSocket、gRPC、双向流、SSE 重连或 `Last-Event-ID` 恢复。
- 不在没有真实 SSE 样本时猜测事件格式，不让 AI 生成 Python、脚本或受限 Schema 之外的规则。
- 一个场景性能测试只选择一个 SSE 目标步骤；同一场景内多个 SSE 步骤的独立指标命名空间不在本阶段范围。
- 不开放 Python、JavaScript、模板表达式或任意查询执行；字段路径仅支持受限 JSONPath 子集。
- 不保存完整 SSE 内容、模型输出或工具参数；运行产物只保存必要的脱敏诊断摘要和聚合指标。
- 不把 SSE 自定义指标写入 Locust HTTP 聚合行，也不改变已有 HTTP 性能目标的含义。

## 预期收益

- 同一套性能测试可覆盖主流 LLM 流式接口与内部事件流，而不依赖供应商专用脚本。
- 用户可以明确指定业务可感知的响应时刻，并为它们建立 P95/P99 目标。
- SSE 的缺失事件、协议问题与后端慢响应可以被区分，提升诊断可信度。
