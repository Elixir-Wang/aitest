# 测试用例格式规范

## 字段要求

每条测试用例必须包含：

- `id`：`tc-001`、`tc-002`、`tc-003`，连续递增。
- `module`：所属模块，和外层 `module_name` 保持一致或更具体。
- `title`：动宾结构，简洁描述验证目标。
- `priority`：只能是 `P0`、`P1`、`P2`、`P3`。
- `type`：只能是 `功能测试`、`异常测试`、`边界测试`、`性能测试`、`安全测试`、`兼容测试`。
- `precondition`：执行前置条件，没有则为空字符串。
- `steps`：执行步骤列表，每个步骤必须包含 `action` 和 `expected_result`。
- `steps[].action`：单个可执行动作。
- `steps[].expected_result`：该动作完成后的明确、可验证预期结果。
- `expected_result`：整条用例的最终或汇总预期结果。
- `test_data`：必要测试数据，没有则为空字符串。
- `notes`：补充说明或待确认点，没有则为空字符串。

## 标题规范

标题使用动宾结构：

- 好：`使用正确账号密码登录`
- 好：`提交空密码登录`
- 好：`无权限用户访问项目测试用例集`
- 差：`登录测试`
- 差：`异常情况`

## 步骤规范

- 每一步只描述一个动作。
- 使用明确动词开头：打开、输入、选择、点击、提交、查看、验证。
- 不要把多个操作合并成一步。
- 不要写“按正常流程操作”这类无法执行的描述。
- 每一步必须有自己的预期结果，不要只在用例末尾写一个总预期。

## 预期结果规范

- 必须能被人工或自动化验证。
- 包含界面提示、状态变化、数据变化或权限结果。
- 需求未明确时，不编造具体文案、时间、次数、阈值。
- 步骤级预期只描述该步骤完成后的可观察结果；用例级预期概括整条用例最终结果。

## 计数规范

- `total_count` 必须等于所有 `modules[].test_cases` 的总数。
- 测试用例 ID 必须按最终输出顺序连续递增。
- 每个模块至少包含 1 条测试用例。
