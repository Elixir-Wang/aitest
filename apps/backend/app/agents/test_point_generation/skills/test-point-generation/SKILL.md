# 测试点生成专家

## 快速开始

1. **解构需求** - 识别模块、角色、业务流程、业务规则
2. **三层扫描** - 功能覆盖 → 风险覆盖 → 边界覆盖
3. **结构化输出** - 按模板生成测试点清单

## 三层扫描法

### 第一层：功能覆盖

按意图类型生成测试点：

| 意图类型 | 适用场景 |
|----------|----------|
| **task** | 完成明确定义的目标，如表单提交、流程完成 |
| **boundary** | 系统在边界条件下的行为，如最大值、空值、临界值 |
| **comparative** | 验证用户在多个选项中做决策，如选择器、排序 |
| **exploratory** | 验证用户在信息空间中自主探索的能力 |

### 第二层：风险覆盖

| 风险类型 | 示例 |
|----------|------|
| 权限穿透 | 未授权角色执行操作 |
| 数据泄露 | 跨角色数据可见性 |
| 状态混淆 | 并发状态变更一致性 |
| 幂等破坏 | 重复提交的副作用 |

### 第三层：边界覆盖

- 数值边界：最小值、最大值、临界值
- 格式边界：空值、特殊字符、超长输入
- 时间边界：最早/最晚时间、时区边界
- 数量边界：零条、单条、最大数量

## 核心输出字段

| 字段 | 说明 |
|------|------|
| **point_key** | 唯一标识，格式 `模块.功能.类型.区分符`，如 `login.task.success` |
| **title** | 简洁标题 |
| **module** | 所属模块 |
| **category** | 类型：功能 / 异常 / 边界 / 权限 / 数据 / 状态 / 性能 / 安全 / 兼容性 |
| **priority** | 优先级：P0（核心路径）/ P1（重要功能）/ P2（优化项）|
| **description** | 测试点描述，说明要验证什么 |
| **preconditions** | 前置条件列表 |
| **verification_points** | 验证点列表，每条格式 `操作 → 预期结果` |
| **source_refs** | 需求文档引用 |
| **notes** | 备注，如有待确认事项写"待确认：..." |

## 输出模板

```markdown
# 测试点清单

## 统计摘要

| 指标 | 数量 |
|------|------|
| 总数 | N |
| P0 | N |
| P1 | N |
| P2 | N |

## 测试点详情

### [point_key] 测试点标题

| 字段 | 内容 |
|------|------|
| 模块 | 所属模块 |
| 类型 | 功能 / 异常 / 边界 / 权限 / 数据 / 状态 / 性能 / 安全 / 兼容性 |
| 优先级 | P0 / P1 / P2 / P3 |
| 来源 | 需求文档引用 |

**描述**

测试点描述内容。

**前置条件**

- 前置条件1
- 前置条件2

**验证点**

- 操作1 → 预期结果1
- 操作2 → 预期结果2

**来源引用**

- 需求文档章节引用

**备注**

备注内容或"待确认：xxx"
```

## 硬约束

1. `point_key` 在同一份输出中必须唯一
2. `priority` 只能是 `P0`、`P1`、`P2`、`P3`
3. `category` 只能是定义的枚举值
4. 每个测试点必须有验证点，至少 1 条
5. 验证点格式为 `操作 → 预期结果`
