# 测试点生成参考文档

## 覆盖矩阵

生成测试点时检查覆盖矩阵：

| | 功能正确性 | 权限安全 | 状态一致性 | 并发可靠 | 性能达标 |
|---|:---------:|:-------:|:---------:|:-------:|:-------:|
| **task** | ☐ | ☐ | ☐ | ☐ | ☐ |
| **boundary** | ☐ | ☐ | ☐ | ☐ | ☐ |
| **comparative** | ☐ | ☐ | ☐ | ☐ | ☐ |
| **exploratory** | ☐ | ☐ | ☐ | ☐ | ☐ |

## 输出模板

```markdown
# 测试点清单

## 统计摘要

| 指标 | 数量 |
|------|------|
| 总数 | N |
| P0 | N |
| P1 | N |
| P2 | N |

## 测试点详情

### [point_key] 测试点标题

| 字段 | 内容 |
|------|------|
| 模块 | 所属模块 |
| 类型 | 功能 / 异常 / 边界 / 权限 / 数据 / 状态 / 性能 / 安全 / 兼容性 |
| 优先级 | P0 / P1 / P2 / P3 |
| 来源 | 需求文档引用 |

**描述**

测试点描述内容。

**前置条件**

- 前置条件1
- 前置条件2

**验证点**

- 操作1 → 预期结果1
- 操作2 → 预期结果2

**来源引用**

- 需求文档章节引用

**备注**

备注内容或"待确认：xxx"
```

## 硬约束

1. `point_key` 在同一份输出中必须唯一
2. `priority` 只能是 `P0`、`P1`、`P2`、`P3`
3. `category` 只能是：功能 / 异常 / 边界 / 权限 / 数据 / 状态 / 性能 / 安全 / 兼容性
4. 每个测试点必须有验证点，至少 1 条
5. 验证点格式为 `操作 → 预期结果`
6. `source_refs` 必须指向需求文档中的章节；无法定位时在 `notes` 标记「待确认」
