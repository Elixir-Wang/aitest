## 📋 问题概述

**环境ID**: `env-c3bc1023763dbb16`  
**初始症状**: 登录耗时长（~70秒）且失败  
**修复日期**: 2026-06-28  

---

## 🔍 发现的问题

### 问题1: 验证码识别长度不匹配导致登录失败

**现象**:
```json
{
  "status": "failed",
  "message": "验证码识别结果长度不符合页面输入限制，应为 4 位。",
  "last_error_code": "CAPTCHA_SOLVE_FAILED"
}
```

**根本原因**:
- ddddocr识别第1次验证码时输出了5位（`Rwt2t`）
- 页面只接受4位验证码
- 原代码对长度不匹配采取零容忍策略，直接抛出异常并中止登录
- 浪费了后续2次重试机会（第2、3次识别都是正确的4位）

**影响**: 登录成功率 **0%**

---

### 问题2: 登录计划缓存总是失效

**现象**:
```json
{
  "kind": "login_plan_invalid",
  "reason": "captcha_image_selector_not_visible"
}
```

**根本原因**:
- 验证码图片是异步加载的（延迟约14-19ms）
- Playwright验证选择器时只等待300ms，检查时图片还没渲染
- 导致计划被误判为失效，每次都要重新LLM分析

**影响**: 每次登录耗时 **~70秒**（66秒LLM分析）

---

## ✅ 实施的修复

### 修复1: 智能验证码长度截取

**文件**: `apps/backend/app/services/captcha_solver_service.py:178-194`

**策略**: 识别结果过长时自动截取前N位，而不是直接失败

**效果**:
- ✅ 第1次: `Rwt2t` (5位) → `Rwt2` (4位)
- ✅ 第2次: `ar5c` (4位) → 保持不变
- ✅ 第3次: `nh57` (4位) → 保持不变
- ✅ 成功率: 100% (3/3)

---

### 修复2: 增加验证码图片等待时间

**文件**: `apps/backend/runners/playwright/ai-letter-login.mjs:384-409`

**策略**: 验证码图片等待时间从 300ms 增加到 5000ms

**效果**:
- ✅ 实际加载时间: 14-19ms
- ✅ 登录计划验证通过
- ✅ 无需重新LLM分析
- ✅ 节省时间: ~66秒
