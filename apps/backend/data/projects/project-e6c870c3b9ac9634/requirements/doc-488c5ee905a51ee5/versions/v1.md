# 官网登录sso

## 需求概述

建设统一登录认证授权中心（br-auth-center），作为官网统一身份基础设施，实现统一注册、统一登录、统一认证、统一授权、统一身份标识、单点登录（SSO）、单点登出（SLO）、统一入口能力。首期聚焦官网导流、活动、邀请、深链等新增链路，不强制产品迁移全部原有登录入口。

## 用户模型

### C端用户

个人用户支持手机号/邮箱统一注册与登录。

### B端用户

企业管理员、企业成员。

### B+C混合身份用户

同一用户在统一身份下可承载多身份场景。产品根据unified_uid和biz_context决定走个人空间还是企业空间。

### INVITE_ONLY（邀请制/灰度产品）

产品可通过biz_context携带邀请码（invite_code），认证中心仅透传，不校验邀请码有效性；产品后端自行校验。

## 身份标识与映射

### Unified UID

所有用户在统一认证中心内拥有唯一身份标识（Unified UID）。user_type表示认证中心侧识别到的身份线索：UNKNOWN、PERSONAL、ENTERPRISE_MEMBER。user_type不代表用户拥有某产品的B端权限。

### 本地账号映射

统一认证中心不直接替代各产品本地账号体系。各产品通过Unified UID与本地用户ID（local_user_id）建立映射关系（Unified UID ↔ Local User ID）。认证中心不维护此映射表，由产品侧自行维护。

### 首次绑定机制

用户首次通过官网进入产品时：
- 已存在本地账号：绑定该本地账号。
- 不存在本地账号：创建本地账号。
- 存在冲突：进入冲突处理流程。

产品侧可按产品用户模式（C/B/B+C/INVITE_ONLY）制定具体绑定策略（如自动创建、手机号匹配、引导试用等）。

## 核心业务流

### 官网登录

用户在官网完成统一注册或登录后，建立统一身份状态。

### 官网进入产品（SSO票据链路）

1. 用户访问新版官网，完成登录（手机号/邮箱）。
2. [可选] 产品后端预注册biz_context（邀请码/推荐码/场景标记），调用context/register获取context_id。
3. 用户点击产品入口，官网服务端调用ticket/create生成login_ticket（由官网侧发起，产品侧通常不直接调用）。
4. 官网跳转至产品sso_entry_url，携带login_ticket + state。
5. 产品后端调用认证中心 /api/sso/ticket/verify。
6. 认证中心返回UserInfo（unified_uid、user_type、脱敏手机号/邮箱、account_status、注册来源） + account_status + return_url + biz_context。
7. 产品侧查询本地映射，处理老用户绑定或新用户创建，并根据product_user_mode判断B端权限。
8. 产品侧建立本地Session（JWT/Cookie）。
9. 用户进入产品，或进入产品侧准入提示页。

预期：官网登录后进入产品免二次登录。

### 产品直接访问

产品 → 统一认证中心 → 登录 → 回跳产品。

## 安全规范

- 所有redirect_uri必须统一白名单管理。
- 所有授权请求必须校验state，防止CSRF。
- access_token / refresh_token 禁止暴露于前端或URL。
- client_secret / product_access_key 仅允许服务端保存，不入前端代码、不入URL、不入日志。
- 生产环境必须全链路HTTPS。
- 日志必须脱敏处理，不记录敏感信息。
- login_ticket为一次性、短时效（5分钟）的SSO票据，只用于换取UserInfo，不存储长期。
- 每次ticket/verify生成新的随机nonce，防止重放攻击。
- 5类接口按分钟桶限流（HTTP 429）。

## 登出机制

### 本地登出

仅退出当前产品，不影响官网及其他产品登录状态。

### 全局登出（首期不强制，后续增强）

退出统一认证中心，同时清理官网及接入产品登录状态。

## 认证中心标准输出能力

- 注册/登录（手机号、邮箱）
- 统一UID
- login_ticket（一次性、短时效SSO票据）
- ticket校验（产品后端用product_access_key换取UserInfo）
- UserInfo（unified_uid、user_type、脱敏手机号/邮箱、account_status、注册来源）
- biz_context透传（预注册业务上下文原样透传，不解析）
- account_status：ACTIVE / DISABLED / CANCELLED
- context/register（支持产品预注册业务上下文，返回context_id）
- 限流保护（5类接口按分钟桶限流）
- nonce防重放
- 审计日志（认证侧事件审计，敏感字段脱敏）

## 产品接入要求

### 产品侧必须做的事情

- 提供sso_entry_url（接收login_ticket + state的HTTP GET回调地址）
- 后端调用ticket/verify校验ticket，换取UserInfo
- 维护unified_uid ↔ local_user_id映射
- 建立产品本地Session（JWT/Cookie）
- 处理return_url跳转
- 保护product_access_key（只存后端）

### 产品侧可选做的事情

- 处理biz_context：从verify响应中读取并处理业务上下文
- 处理B端权限判断：查询本地账号是否有B端准入权限
- 处理老用户绑定：unified_uid与已有账号的关联策略
- 调用context/register预注册biz_context

### 认证中心不做的

- 创建产品本地账号（产品侧做）
- 维护UID ↔ 本地账号映射（产品侧做）
- 建立产品Session（产品侧做）
- 校验邀请码/推荐码有效性（产品侧做）
- 校验企业邮箱/企业代码（产品侧做）
- 维护租户/组织/角色/权限（产品侧做）
- 判断是否有产品使用权限（产品侧做）
- 实现OAuth2/OIDC（首期不实现，后续增强）
- 全局登出（首期不强制，后续增强）
- 第三方登录（首期不实现，后续增强）

## 产品接入模式

### C端产品

典型产品：百智个人场景。官网注册用户可尝试进入，产品侧按unified_uid查映射，无映射可自动创建本地账号。原登录入口首期可继续保留。推荐实现：ticket verify → 查映射 → 有映射建Session → 无映射查手机号匹配 → 命中自动绑定 → 无命中且允许自动创建 → 创建本地账号建Session。

### B端产品

典型产品：百才（HR后台）、百察、百灵。官网注册登录 ≠ 自动开通B端产品权限。ticket verify成功后，还需查询本地是否有账号和B端权限。无账号用户不应直接进入产品后台，应引导至留资/申请试用/联系管理员。推荐实现：ticket verify → 查本地账号 → 有账号有权限建Session → 有账号无权限提示"产品未开通"或"联系管理员" → 无账号引导留资或申请试用。

### B+C混合产品

典型产品：百智、百工（B+C场景）。同一产品同时支持个人用户和企业用户，产品根据UID和biz_context决定走个人空间还是企业空间。可通过biz_context传递进入场景标记。推荐实现：ticket verify → 查biz_context（scene / user_intent）→ 判断B/C分流 → B流程：查企业归属+权限 → 企业空间 → C流程：查个人映射 → 个人空间。

### INVITE_ONLY（邀请制/灰度产品）

典型场景：百工邀请制灰度开放。通过biz_context携带邀请码（invite_code），产品后端自行校验邀请码有效性。推荐实现：context/register预注册{invite_code: "BG_INV_XXX"} → 用户登录 → ticket verify → 从biz_context获取invite_code → 产品后端校验邀请码 → 有效建Session → 无效提示"邀请码无效"。

## 验收标准

### 功能验收

- 官网统一注册登录完成。
- 官网进入产品免二次登录。
- Unified UID生效。
- 首次绑定流程可用。
- SSO生效：正向链路（context/register → login → ticket/create → ticket/verify → 建立Session → return_url跳转）。
- SLO生效（首期不强制）。

### 异常链路验收

- 票据重用。
- state不符。
- nonce重放。
- product_access_key无效。

### 安全验收

- redirect_uri白名单。
- state校验。
- token安全。
- client_secret/product_access_key安全。
- HTTPS。
- 日志脱敏（审计日志无敏感明文）。

## 非建设范围

本项目不包含：统一产品业务权限、统一租户体系、统一角色体系、统一菜单体系、统一账号库合并、OAuth2/OIDC、第三方登录（首期不实现）。

## 接入路径

1. 产品完成登记表。
2. 认证中心侧配置product_code、sso_entry_url、allowed_redirect_domains。
3. 认证中心侧提供联调环境product_access_key（安全渠道交付）。
4. 产品后端实现sso_entry_url接收逻辑和ticket/verify调用。
5. 联调验证。
6. 通过验收清单。
7. 生产上线（生产密钥单独分发）。
