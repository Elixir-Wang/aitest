# 官网登录 SSO

## 需求概述

建设官网统一登录认证授权中心，作为百系产品的统一身份基础设施。用户在新版官网完成注册/登录后，可通过 SSO 票据免登跳转至任意已接入产品。产品保留本地账号体系及权限体系，认证中心负责统一身份识别、票据签发与校验、业务上下文透传及安全防护。首期不强制迁移原有产品登录入口，仅作为新增链路能力接入。

## 产品接入模式

### C 端产品

- 官网注册用户可通过 unified_uid 查询映射：有映射则建立会话；无映射可尝试手机号匹配自动绑定，或允许自动创建本地账号后建立会话。
- 原登录入口首期可继续保留。

### B 端产品

- 官网注册登录不等于自动开通 B 端权限。ticket/verify 成功后，产品须查询本地账号及 B 端准入权限；无账号用户应引导至留资、申请试用或联系管理员。
- 典型产品：百才（HR 后台）、百察、百灵。

### B+C 混合产品

- 同一产品同时支持个人与企业用户，产品根据 unified_uid 和 biz_context（如 scene/user_intent）分流至个人空间或企业空间。
- 典型产品：百智、百工（B+C 场景）。

### 邀请制/灰度产品

- 采用 INVITE_ONLY 模式，通过 biz_context 传递邀请码（invite_code）。认证中心仅透传，不校验邀请码有效性；产品后端收到后自行校验。
- 邀请码有效则建立会话，无效则提示“邀请码无效”。

## SSO 核心流程

### 官网登录进入产品

1. 用户在官网完成登录（手机号/邮箱）。
2. [可选] 产品后端预注册 biz_context（通过 context/register），如邀请码、推荐码、活动场景标记。
3. 用户点击产品入口，官网服务端调用 ticket/create 生成一次性 login_ticket。
4. 官网跳转至产品 sso_entry_url，附带 login_ticket 和 state。
5. 产品后端调用认证中心 /api/sso/ticket/verify 校验票据。
6. 认证中心返回 UserInfo（含 unified_uid、user_type、脱敏手机号/邮箱、account_status）、biz_context 等。
7. 产品侧：查询本地 unified_uid ↔ local_user_id 映射，进行老用户绑定/新用户创建/B 端权限判断。
8. 产品侧建立本地 Session（JWT/Cookie），跳转至 return_url。

### 产品侧必做任务

- 提供 sso_entry_url 接收 login_ticket + state
- 调用 ticket/verify 换取 UserInfo
- 维护 unified_uid ↔ local_user_id 映射
- 建立产品本地 Session
- 处理 return_url 跳转
- 保护 product_access_key（仅后端保存，不出现于前端、URL、日志）

### 产品侧可选任务

- 处理 biz_context（从 verify 响应中读取）
- B 端产品判断本地账号权限
- 处理老用户绑定（unified_uid 与已有账号关联策略）
- 调用 context/register 预注册业务上下文（有邀请码/推荐码/活动场景时）

## 身份与映射

### Unified UID

- 每个官网用户拥有全局唯一 unified_uid，作为跨产品身份锚点。
- user_type 说明统一认证中心识别的身份线索：UNKNOWN（未知）、PERSONAL（个人）、ENTERPRISE_MEMBER（企业成员）；注意：user_type 不等于 B 端产品权限。

### 本地账号映射

- 各产品通过 unified_uid 与本地账号建立映射关系（Unified UID ↔ Local User ID）。
- 首次绑定：用户首次通过官网进入产品时，已存在本地账号则绑定，不存在则创建，冲突则进入冲突处理流程。

### 产品用户模式

- 产品配置字段 product_user_mode，取值：C（面向个人用户）、B（面向企业用户）、B_PLUS_C（同时支持个人和企业）、INVITE_ONLY（邀请制/灰度准入）。代码判断使用枚举值。

## 安全规范

- redirect_uri 必须统一白名单管理。
- 所有授权请求必须校验 state，防止 CSRF。
- access_token / refresh_token 禁止暴露于前端或 URL。
- client_secret / product_access_key 仅允许服务端保存，不入前端代码、不入日志。
- 生产环境必须全链路 HTTPS。
- 日志必须脱敏处理，不记录明文敏感信息。
- login_ticket 为一次性、短时效（5 分钟）票据，仅用于换取 UserInfo，不作为登录态保存。
- ticket/verify 接口须使用 nonce 防重放攻击。

## 登出机制

### 本地登出

- 仅退出当前产品，不影响官网及其他产品登录状态。

### 全局登出（SLO）

- 退出统一认证中心，同时清理官网及接入产品登录状态。

## 认证中心能力

### 提供能力

- 手机号/邮箱注册与登录
- 统一 UID 管理
- login_ticket 颁发与校验
- UserInfo 服务（unified_uid、user_type、脱敏手机号/邮箱、account_status、注册来源）
- biz_context 透传（预注册的业务上下文原样透传，不解析）
- product_access_key 认证
- 限流保护（5 类接口按分钟桶限流，返回 HTTP 429）
- nonce 防重放
- 审计日志（认证侧事件审计，敏感字段脱敏）
- context/register 接口
- Actuator 最小暴露

### 不提供能力

- 认证中心不创建产品本地账号、不维护 UID ↔ 本地账号映射、不建立产品 Session。
- 不校验邀请码/推荐码有效性（仅透传）。
- 不校验企业邮箱/企业代码。
- 不维护租户/组织/角色/权限。
- 不判断用户是否有某产品的使用权限。
- 首期不实现 OAuth2/OIDC、全局登出、第三方登录。

## 接入路径与流程

### 产品接入步骤

1. 产品完成接入登记表。
2. 认证中心侧配置 product_code、sso_entry_url、allowed_redirect_domains。
3. 认证中心侧提供联调环境 product_access_key（通过安全渠道交付）。
4. 产品后端实现 sso_entry_url 接收逻辑和 ticket/verify 调用。
5. 联调验证。
6. 通过验收清单。
7. 生产上线（生产密钥单独分发）。

### 联调流程要点

- 双方确认联调环境地址和 product_access_key。
- 先验证 context/register → ticket/create → ticket/verify 正向链路。
- 验证 B 端/邀请制等特殊场景。
- 验证异常场景：票据已用、state 不符、nonce 重放、product_access_key 无效。
- 验证审计日志不含明文敏感信息。

## 验收标准

### 正向链路

- context/register → login → ticket/create → ticket/verify → 建立 Session → return_url 跳转。

### 异常链路

- 票据重用、state 不符、nonce 重放、product_access_key 无效。
- 审计日志无敏感明文。

### 安全验收

- redirect_uri 白名单、state 校验、token 安全、client_secret 安全、HTTPS、日志脱敏。
