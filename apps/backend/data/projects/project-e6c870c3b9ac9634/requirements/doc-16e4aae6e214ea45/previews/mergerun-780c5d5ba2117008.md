# 亦庄登录sso

## 需求概述

建设统一登录认证授权中心，作为百系产品的统一身份基础设施。用户通过官网完成一次注册/登录后，可免二次登录进入已接入的百系产品。统一认证中心负责统一身份识别（Unified UID 签发）、SSO 票据颁发与校验、业务上下文透传、首次接入状态管理以及安全审计能力。产品侧保留本地账号、权限、租户、角色等业务体系。

## 登录认证

### 官网统一注册与登录
- 支持手机号和邮箱注册与登录。
- 用户在官网完成注册/登录后，建立统一身份状态（统一登录会话）。

### SSO 票据链路
- 用户从官网进入产品时，官网服务端调用 `ticket/create` 生成一次性的 login_ticket，时效 5 分钟。
- 官网携带 login_ticket + state 跳转至产品的 sso_entry_url。
- 产品后端调用认证中心 `/api/sso/ticket/verify` 校验 ticket，换取 UserInfo（unified_uid、user_type、脱敏手机号/邮箱、account_status、注册来源）以及透传的 biz_context。
- ticket 仅用于换取 UserInfo，不存储为长期登录态。
- 每次验证必须校验 state 以防止 CSRF，并使用唯一 nonce 防重放攻击。

### 业务上下文预注册（biz_context 透传）
- 支持产品后端在用户登录前通过 context/register 预注册业务上下文（如邀请码、推荐码、场景标记），获得 context_id。
- 登录和 ticket 生成时携带 context_id，认证中心在 ticket/verify 中原样透传 biz_context，不解析其业务含义。

### session_token 鉴权查询产品进入状态
- 提供 GET `/api/sso/product-entry/status` 接口，供前端判断是否弹邀请码。
- 使用官网 session_token 鉴权（Authorization: Bearer {session_token}），获取 unified_uid。
- 根据 product_code 查询产品配置：
  - 产品不存在 → 返回 PRODUCT_INVALID。
  - 产品已禁用 → 返回 PRODUCT_DISABLED。
  - 若产品 require_invite_code = false → action = CREATE_TICKET_DIRECTLY。
  - 若产品 require_invite_code = true，则查询 auth_product_user_access 表：
    - 存在 CONNECTED 记录 → action = CREATE_TICKET_DIRECTLY。
    - 不存在 → action = SHOW_INVITE_DIALOG。
- 响应包含 product_code、product_name、require_invite_code、invite_required_for_current_user、access_status、action、sso_entry_url。

### 产品首次接入确认
- 提供 POST `/api/sso/product-entry/confirm` 接口，供产品后端在用户完成首次接入后回写状态。
- 使用 product_access_key 鉴权（Authorization: Bearer {product_access_key}），且 key 必须属于请求体中的 product_code，产品必须 ENABLED。
- 请求体包含 product_code、unified_uid、access_status（仅支持 CONNECTED）、bind_source（可选，INVITE_CODE/ADMIN/IMPORT/UNKNOWN）。
- 校验 unified_uid 用户存在，然后 upsert auth_product_user_access 表：
  - 不存在 → 插入，first_connected_at = now，last_connected_at = now。
  - 已存在 → 更新 access_status = CONNECTED，last_connected_at = now（不覆盖 first_connected_at）。
- 成功返回 product_code、unified_uid、access_status。

## 账号与映射

### Unified UID
- 所有用户在统一认证中心内拥有唯一身份标识（Unified UID）。

### 本地账号映射
- 统一认证中心不直接替代各产品本地账号体系。
- 各产品通过 Unified UID 与本地账号建立映射关系（Unified UID ↔ Local User ID）。
- 产品侧必须维护自己的账号映射表。

### 首次绑定机制
- 用户首次通过官网进入产品时：
  - 产品已存在本地账号 → 绑定本地账号。
  - 不存在本地账号 → 创建本地账号。
  - 存在冲突 → 进入冲突处理流程（由产品侧定义）。

### 用户模型
- 支持 C 端个人用户、B 端企业用户（管理员/成员）、B+C 混合身份用户。
- user_type（UNKNOWN / PERSONAL / ENTERPRISE_MEMBER）仅为认证中心侧的身份线索，不代表产品端 B 端权限。
- 产品的用户模式（C / B / B+C / INVITE_ONLY）由 product_context.product_user_mode 表示，由产品侧根据场景判断分流。

## 统一登出

### 本地登出
- 用户在产品内执行登出时，仅退出当前产品，不影响官网及其他接入产品的登录状态。

### 全局登出
- 用户从统一认证中心执行全局登出时，同时清理官网及所有接入产品的登录状态。

## 安全规范

### redirect_uri 白名单
- 所有 redirect_uri 必须统一白名单管理。

### state 校验
- 所有授权请求必须校验 state，防止 CSRF。

### Token 安全
- access_token / refresh_token 禁止暴露于前端或 URL 中。
- login_ticket 仅用于后端交换 UserInfo，不存储为长期登录凭证。
- product_access_key 仅允许服务端保存，不入前端代码、不入 URL、不入日志。

### HTTPS
- 生产环境必须全链路 HTTPS 调用认证中心。

### nonce 防重放
- 每次 ticket/verify 请求必须携带唯一随机 nonce，防止重放攻击。

### 日志安全
- 认证侧审计日志必须脱敏处理，不记录 session_token、product_access_key、邀请码等敏感信息。

### 鉴权隔离
- 状态查询接口（status）仅使用 session_token 鉴权，只返回当前用户自身状态。
- 状态回写接口（confirm）仅使用 product_access_key 鉴权，仅合法产品后端可调用。

## 产品接入

### 接入范围（本期）
- 用户从新版官网入口点击进入百系产品。
- 用户在官网完成注册/登录后由官网引导跳转到产品。
- 可选：产品通过新增导流入口（落地页、推广链接、活动页）接入；预注册邀请/推荐链接；深链场景通过认证中心完成身份核验。

### 不接入范围（本期）
- 企业客户正在使用的产品后台登录入口。
- 小程序、App、PC 客户端既有登录入口。
- 企业管理员分发账号后员工使用的内部入口。
- 有复杂租户审批、邀请码校验、企业邮箱校验的现有入口。
- 存量客户已收藏的产品后台地址。
- 本期不要求迁移全量登录入口，认证中心主要提供新增链路。

### 产品侧职责
- 提供 sso_entry_url（接收 login_ticket + state 的 HTTP GET 回调地址）。
- 后端调用 ticket/verify 校验 ticket 换取 UserInfo。
- 维护 unified_uid ↔ local_user_id 映射。
- 建立产品本地 Session（JWT / Cookie）。
- 处理 return_url 跳转。
- 可选处理 biz_context。
- 端产品必须处理 B 端权限判断。
- 保护 product_access_key（仅后端保存）。

### 认证中心提供能力
- 注册/登录（手机号/邮箱）。
- 统一 UID 管理。
- login_ticket 签发与验证。
- UserInfo 与 account_status（ACTIVE / DISABLED / CANCELLED）。
- biz_context 透传。
- context/register 预注册。
- 限流保护（5 类接口按分钟桶限流，HTTP 429）。
- nonce 防重放。
- 审计日志，敏感字段脱敏。

### 认证中心不做什么
- 不创建产品本地账号。
- 不维护 UID ↔ 本地账号映射。
- 不建立产品 Session。
- 不校验邀请码/推荐码有效性。
- 不校验企业邮箱/企业代码。
- 不维护租户/组织/角色/权限。
- 不判断产品使用权限。
- 不实现 OAuth2/OIDC（本期）。
- 不实现第三方登录（本期）。
- 不强制全局登出（本期仅作为设计约束，产品侧需支持）。

## 产品接入模式策略

### C 端产品
- ticket/verify 完成后，产品侧查映射：有映射直接建立 Session；无映射可尝试根据手机号自动绑定，或自动创建本地账号并建立 Session。
- 原登录入口首期可保留。

### B 端产品
- ticket/verify 完成后，还需查询本地账号及 B 端权限。
- 有账号有权限 → 建立 Session。
- 有账号无权限 → 提示“产品未开通”或“联系管理员”。
- 无账号 → 引导留资或申请试用。

### B+C 混合产品
- ticket/verify 后，根据 biz_context（scene/user_intent）判断 B/C 分流：
  - B 流程：查企业归属 + 权限 → 企业空间。
  - C 流程：查个人映射 → 个人空间。

### INVITE_ONLY（邀请制/灰度产品）
- 通过 biz_context 预注册 invite_code，认证中心仅透传不校验。
- 产品后端收到 invite_code 后自行校验有效性。
- 有效 → 建立 Session；无效 → 提示“邀请码无效”。

## 验收标准

### 功能验收
- 官网统一注册/登录完成。
- 官网进入产品免二次登录（SSO）。
- Unified UID 生效并正确签发。
- 首次绑定流程可用（含 C 端自动绑定、B 端权限判断等）。
- 全局登出（SLO）生效。
- 产品首次接入状态查询与回写接口正常。
- 正向链路：context/register → login → ticket/create → ticket/verify → 建立 Session → return_url 跳转。
- 异常链路：票据重用（返回错误）、state 不符（拒绝）、nonce 重放（拒绝）、product_access_key 无效（拒绝）、session_token 无效/过期（拒绝）。

### 安全验收
- redirect_uri 白名单生效。
- state 校验严格。
- login_ticket 不暴露于前端或 URL。
- product_access_key 仅后端保存。
- HTTPS 全链路。
- 审计日志无敏感明文。
- 限流函数生效（5 类接口）。

## 数据库表

### auth_product_user_access
- 字段：id（自增主键）、product_code（产品编码）、unified_uid（统一用户 ID）、access_status（CONNECTED / REVOKED）、bind_source（接入来源）、first_connected_at、last_connected_at、created_at、updated_at、is_deleted。
- 唯一索引：uk_product_uid（product_code, unified_uid）。
- 不存储：邀请码、local_user_id、local_tenant_id、权限。
