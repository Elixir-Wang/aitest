# 初步需求补充（仅限主需求锚定且有证据）

> 注意：以下不是归并需求，仅补充主需求中已有锚点的缺失信息；每段均包含来源文件和证据摘录。

## 邀请制产品首次进入状态补充

对于主需求中 INVITE_ONLY（邀请制/灰度产品）以及“产品通过预注册邀请链接/推荐链接业务上下文”的场景，可补充：认证中心维护某个 `unified_uid` 对某个 `product_code` 的首次接入轻量状态，用于判断用户点击进入产品时是否需要展示邀请码弹窗；认证中心仅维护 CONNECTED / NOT_CONNECTED 等接入状态，邀请码有效性、本地账号、角色和权限仍由产品侧处理。

来源：`SSO 产品进入状态接口 v1.0.md`；证据摘录：“认证中心维护轻量状态：某个 unified_uid 是否已完成某个 product_code 的首次接入。”、“认证中心：维护首次接入状态（CONNECTED / NOT_CONNECTED）；产品侧：校验邀请码有效性、维护本地账号、角色、权限”。

## 邀请制首次接入确认补充

对于邀请制产品在产品后端完成 ticket verify、获取 unified_uid 和邀请码、校验邀请码有效并创建本地用户/Session 后，可由产品后端回写首次接入状态为 CONNECTED；该状态用于后续用户再次从官网进入产品时判断是否可直接创建票据进入产品。

来源：`SSO 产品进入状态接口 v1.0.md`；证据摘录：“确认产品首次接入”、“P0 仅支持 CONNECTED”、“Upsert auth_product_user_access：不存在：插入，first_connected_at = now，last_connected_at = now；已存在：更新 access_status = CONNECTED，last_connected_at = now（不覆盖 first_connected_at）”。
