# 亦庄登录 SSO 需求分析报告

## 分析结论

本需求当前可作为“官网统一认证中心接入总览/首读材料”，但还不能单独作为开发与测试的完整契约。主需求已明确接入目标、职责边界、核心链路、产品侧必做事项、安全要求和验收方向；辅助文件进一步补充了邀请制产品进入状态查询、首次接入确认接口、状态表、登出与安全规范。

综合评估为“有条件通过”：可进入接入方案设计和联调准备，但进入开发排期前应确认 SLO 是否属于首期范围、亦庄具体产品模式与准入规则、接口契约细节、异常处理页面、账号绑定冲突策略和运行指标。

## 第一阶段：需求评审发现

### 已明确内容

- 统一认证中心承接新版官网进入百系产品的注册、登录、统一 UID、SSO 票据、UserInfo、biz_context 透传、限流、防重放和审计脱敏能力。
- 产品侧必须提供 `sso_entry_url`，后端调用 `ticket/verify`，维护 `unified_uid` 与 `local_user_id` 映射，建立本地 Session，处理 `return_url`，保护 `product_access_key`。
- 认证中心不创建产品本地账号、不维护产品租户/角色/权限、不校验邀请码业务含义、不建立产品 Session。
- 首期原有产品登录入口可保留，官网统一认证中心主要承接新增链路。
- C、B、B+C、INVITE_ONLY 四类产品模式已有推荐策略。
- 联调验收需覆盖正向链路、票据重用、`state` 不符、`nonce` 重放、`product_access_key` 无效和审计日志脱敏。

### 主要缺口

- “亦庄登录 sso”的具体接入产品、`product_code`、产品模式、入口 URL、回跳域名和环境信息未在主需求中给出。
- 主需求引用的正式接口契约和产品接入配置表未随输入提供，接口字段、签名、错误码、限流阈值和返回结构仍需以契约为准。
- B 端、邀请制和 B+C 场景的产品侧准入、账号绑定、冲突处理、提示页与留资链路没有形成可执行验收标准。
- 全局登出/SLO 在主需求中写为“首期不强制/后续增强”，但辅助产品需求说明书写入标准输出能力和验收标准，存在范围冲突。
- 性能、可用性、监控告警、灰度发布、回滚和数据迁移规则仍不完整。

## 第二阶段：测试场景补充

### 核心正向场景

- 官网已登录用户从标准入口进入 C 端产品：创建 `login_ticket`，跳转产品 `sso_entry_url`，产品校验票据，按 `unified_uid` 找到或创建本地账号，建立本地 Session，并跳转 `return_url`。
- B 端用户从官网进入产品：票据校验成功后，产品侧查询本地账号、租户、角色和权限；有权限则进入后台，无权限或无账号则进入未开通/申请试用/联系管理员提示页。
- B+C 产品根据 `biz_context.scene` 或 `user_intent` 分流个人空间或企业空间，并分别执行对应账号映射与权限判断。
- 邀请制产品携带 `invite_code` 进入：产品侧从 `biz_context` 读取邀请码，自行校验有效性，有效后创建/绑定本地账号并建立 Session。
- 已完成首次接入的邀请制用户再次点击进入产品：进入状态接口返回 `CREATE_TICKET_DIRECTLY`，不再弹邀请码。

### 边界与异常场景

- `login_ticket` 过期、重复使用、无效或与产品不匹配时，产品不得建立 Session。
- `state` 缺失、不匹配或被篡改时，必须拒绝回调并记录安全事件。
- `nonce` 重放时，`ticket/verify` 应拒绝并返回可识别错误。
- `product_access_key` 错误、泄露到前端、出现在 URL 或日志中均不符合安全验收。
- `product_code` 为空、不存在、禁用时，进入状态接口应返回对应错误。
- 邀请码无效、过期、已使用、与产品不匹配时，认证中心只透传，产品侧负责拒绝进入并展示业务提示。
- `account_status` 为 `DISABLED` 或 `CANCELLED` 时，产品侧不得创建有效登录态。
- `return_url` 不在允许域名白名单、跨域跳转或包含危险参数时，应拒绝或降级到安全默认页。
- 审计日志不得记录手机号、邮箱、邀请码、`session_token`、`product_access_key`、`login_ticket` 等敏感明文。

## 辅助文件已消解的问题

- 邀请制产品首次进入前是否需要弹邀请码：由“SSO 产品进入状态接口 v1.0”补充，前端可调用 `GET /api/sso/product-entry/status` 判断 `action`。
- 邀请制产品如何记录用户已完成首次接入：由“SSO 产品进入状态接口 v1.0”补充，产品后端在有效接入后调用 `POST /api/sso/product-entry/confirm` 写入 `CONNECTED`。
- 首次接入状态由谁维护、是否存储邀请码和产品权限：由“SSO 产品进入状态接口 v1.0”补充，认证中心只维护 `CONNECTED / NOT_CONNECTED` 轻量状态，不存邀请码、本地用户、租户或权限。
- 本地登出与全局登出的定义：由“百融统一登录认证授权中心产品需求说明书”补充，本地登出仅退出当前产品，全局登出退出统一认证中心并清理官网及接入产品登录状态。
- 安全规范的基础验收项：由“百融统一登录认证授权中心产品需求说明书”补充，包括 `redirect_uri` 白名单、`state` 校验、Token/密钥服务端保存、HTTPS 和日志脱敏。

## 仍需人工确认

1. 亦庄本次要接入的具体产品、`product_code`、产品模式是 C、B、B+C 还是 INVITE_ONLY？
2. 本次范围是否包含全局登出/SLO？若包含，产品侧 `logout_uri`、会话清理方式和验收链路是什么？
3. 正式接口契约中 `context/register`、`ticket/create`、`ticket/verify` 的完整请求字段、响应字段、错误码、签名/鉴权方式、限流阈值和票据有效期是否以主需求引用的 v1.2 契约为准？
4. 产品侧老用户绑定规则是什么：按手机号/邮箱自动绑定、人工确认绑定，还是必须由用户登录原产品账号后绑定？
5. 当手机号或邮箱匹配多个本地账号、已绑定其他 `unified_uid`、账号状态异常时，产品侧应如何处理？
6. B 端或邀请制用户无权限、无账号、邀请码无效、企业身份不满足时，应跳转到哪个提示页或留资流程？
7. `return_url` 的允许域名、默认回跳页、深链保留规则和非法地址降级策略是什么？
8. 生产环境的性能、可用性、监控告警、灰度发布、回滚策略和审计日志留存周期要求是什么？

## 冲突项

- 主需求明确“全局登出首期不强制，后续增强”；辅助产品需求说明书将 SLO/全局登出列为标准输出能力、产品接入要求和功能验收项。需要确认本次“亦庄登录 sso”是否纳入 SLO。
- 主需求称首期不实现 OAuth2/OIDC，并使用 `product_access_key`、`login_ticket`、`sso_entry_url` 等术语；辅助产品需求说明书出现 `client_id`、`client_secret`、`redirect_uri`、`access_token`、`refresh_token` 等 OAuth 风格术语。需要确认正式开发以 SSO 票据契约为准，还是存在后续 OAuth 化接口。

## 覆盖审计

- 身份入口：已覆盖官网注册登录、官网登录后进入产品、产品直接访问回跳场景，但亦庄具体入口未明确。
- 账号映射：已覆盖 `unified_uid` 与本地账号映射职责，但冲突绑定和自动创建条件未明确。
- 权限边界：已覆盖认证中心不维护产品权限，B 端权限由产品侧判断，但产品侧规则未明确。
- 邀请制：辅助文件已覆盖状态查询、弹窗判断、首次接入确认和表结构，但邀请码业务规则未明确。
- 安全：已覆盖 `state`、`nonce`、HTTPS、密钥保护和日志脱敏，缺少密钥轮换、告警和留存周期。
- 测试：已覆盖核心正向链路和关键异常链路，缺少亦庄产品专属数据准备和环境配置。

## 质量门禁

- 当前质量评级：有条件通过。
- 进入开发前必须确认范围冲突、接口契约、亦庄产品模式、账号绑定策略和异常落页。
- 进入测试前必须补齐可执行测试数据、联调环境、密钥交付方式、白名单配置和验收责任人。
