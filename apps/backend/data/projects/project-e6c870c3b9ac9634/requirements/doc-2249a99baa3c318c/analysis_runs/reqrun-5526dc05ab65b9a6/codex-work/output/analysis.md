# 需求分析报告

## 分析范围

本次分析仅基于主需求《百系产品接入官网统一认证中心总说明v1.0》。文档中引用的产品接入配置表、SSO 接口文档、接口契约等辅助材料未在本阶段读取、引用或代替回答待确认问题。

## 总体结论

主需求已清晰说明统一认证中心首期目标、接入范围、非接入范围、核心 SSO 链路、产品侧职责、认证中心能力边界、产品接入模式、安全要求和核心验收项。整体达到“部分可测试”水平，可支持产品团队理解接入方向和拆解研发任务。

但本文档定位为总览材料，明确不替代接口契约和开发指南，因此用于直接开发和测试仍存在关键缺口：接口字段契约、错误码、状态码、回调参数校验规则、Session 策略、账号绑定策略、B 端准入处理、return_url 安全规则、限流阈值和审计字段标准均需人工确认或由后续专项文档增强。

质量门禁结论为 warning：核心链路和边界职责明确，但仍需要补齐可执行验收标准和异常处理细节后，才能进入稳定开发与完整 QA 验证。

## 模块识别

### 官网统一认证入口

用户在新版官网完成注册或登录后，通过官网入口跳转至百系产品。首期重点承接官网导流、新增入口、活动页、邀请链接和深链身份核验，不强制迁移原有产品登录入口。

主要规则：

- 官网统一认证中心提供注册、登录、统一 UID、SSO 票据颁发与校验能力。
- 原有企业后台、小程序、App、PC 客户端、内部入口和存量收藏地址首期可继续保留。
- ticket/create 通常由官网侧发起，产品侧通常不直接调用。

### SSO 票据链路

核心链路为 context/register、官网登录、ticket/create、官网携带 login_ticket 和 state 跳转产品、产品后端调用 ticket/verify、认证中心返回 UserInfo、产品侧建立本地 Session 并跳转 return_url。

主要规则：

- login_ticket 为一次性、短时效票据，有效期 5 分钟。
- 产品后端必须调用 ticket/verify 换取 UserInfo。
- login_ticket 不能作为产品登录态长期保存。
- ticket verify 需要 nonce 防重放。

### 产品侧账号与 Session

产品侧负责 unified_uid 与 local_user_id 映射、本地账号处理、本地 Session 颁发、return_url 跳转、老用户绑定和产品权限判断。

主要规则：

- 认证中心不创建产品本地账号，不维护本地账号映射，不建立产品 JWT/Cookie。
- 产品侧必须维护 unified_uid 与 local_user_id 的映射。
- C 端可按策略自动绑定或创建本地账号。
- B 端必须基于本地账号、租户、角色和权限判断是否准入。

### biz_context 与预注册

产品可在有邀请码、推荐码、活动、深链或场景标记时调用 context/register 预注册业务上下文，认证中心在 verify 响应中原样透传，不解析业务含义。

主要规则：

- 无产品侧业务上下文的官网标准入口可跳过预注册。
- 邀请码、推荐码、企业身份、租户权限均由产品侧自行校验。
- biz_context 可用于 B+C 产品判断进入个人空间或企业空间。

### 产品接入模式

文档定义 C、B、B_PLUS_C、INVITE_ONLY 四类 product_user_mode，并区分 product_user_mode 与 user_type。

主要规则：

- product_context.product_user_mode 使用接口枚举值，代码判断应使用 C、B、B_PLUS_C、INVITE_ONLY。
- user_type 仅表示认证中心识别到的身份线索，不代表产品权限。
- B+C 产品需结合 UID、biz_context、本地企业归属和权限做分流。
- INVITE_ONLY 产品需自行校验 invite_code 是否有效。

### 安全与审计

安全要求包括 product_access_key 仅后端保存、login_ticket 不作登录态、nonce 每次唯一、生产 HTTPS 调用认证中心、审计日志脱敏。

主要规则：

- product_access_key 不得进入前端、URL 或日志。
- 生产环境禁止 HTTP 调用认证中心。
- 异常场景至少覆盖票据重用、state 不符、nonce 重放、product_access_key 无效。
- 审计日志不得包含明文敏感信息。

## 关键缺口

1. 接口契约缺口：主需求未列出 context/register、ticket/create、ticket/verify 的请求字段、响应字段、必填规则、错误码、状态码和签名或鉴权细节。
2. 回调安全缺口：sso_entry_url 接收 login_ticket 和 state，但 state 的生成、保存、校验失败处理、过期策略和攻击防护规则未明确。
3. return_url 缺口：文档要求处理 return_url 跳转，但未定义允许域名、相对路径、非法地址、缺失地址和默认落点。
4. 账号绑定缺口：C 端老用户手机号匹配、自动绑定、自动创建账号的触发条件、冲突处理和用户确认机制未明确。
5. B 端准入缺口：B 端无账号、无权限、租户不存在、角色不足、账号禁用等分支仅给出方向，缺少可测试页面、状态和提示规则。
6. biz_context 缺口：上下文字段结构、大小限制、有效期、context_id 失效、重复注册、篡改和缺失处理未明确。
7. 安全指标缺口：限流仅说明 5 类接口按分钟桶限流，未给出阈值、维度、恢复策略和产品侧错误处理。
8. 验收标准缺口：验收项覆盖主干和部分异常，但缺少每类产品模式的验收场景、数据准备和通过/失败标准。

## 待人工确认问题

### CQ-001：接口契约

context/register、ticket/create、ticket/verify 在本项目接入时以哪个接口契约版本为准，并且产品侧开发测试必须覆盖哪些请求字段、响应字段、错误码和 HTTP 状态码？

影响：接口细节不确认会导致产品侧凭空猜测参数、错误处理和兼容逻辑，无法形成可执行测试用例。

### CQ-002：state 校验

产品侧 sso_entry_url 收到 state 后应按什么规则校验、过期和失败拦截？

影响：state 规则不确认会影响 CSRF 防护、跳转串联验证和异常链路验收。

### CQ-003：return_url 跳转

ticket/verify 返回的 return_url 允许哪些域名或路径，缺失、非法、跨域、被篡改时产品侧应跳转到哪里？

影响：return_url 规则不确认会影响开放跳转风险控制和登录后落点一致性。

### CQ-004：账号绑定与自动创建

C 端产品在 unified_uid 无本地映射但手机号或邮箱命中已有账号时，是否允许自动绑定；未命中时是否允许自动创建本地账号？

影响：绑定规则不确认会影响存量账号归属、误绑定风险和新用户进入流程。

### CQ-005：B 端准入失败处理

B 端产品在用户无本地账号、无租户、无角色权限、账号禁用或企业状态异常时，应展示哪些准入提示页或引导动作？

影响：准入失败规则不确认会导致测试无法判断应拦截、申请试用、联系管理员还是返回官网。

### CQ-006：biz_context 结构与有效期

biz_context 和 context_id 的字段结构、大小限制、有效期、重复提交、缺失、过期或篡改时的处理规则是什么？

影响：上下文规则不确认会影响邀请、推荐、活动和深链测试场景的边界覆盖。

### CQ-007：account_status 处理

ticket/verify 返回 account_status 为 DISABLED 或 CANCELLED 时，产品侧是否必须拒绝建立 Session，并展示什么处理结果？

影响：账号状态规则不确认会导致禁用或注销账号可能被错误放行。

### CQ-008：限流与重试

认证中心 5 类接口的限流阈值、限流维度、HTTP 429 响应体和产品侧重试或提示策略是什么？

影响：限流规则不确认会导致压测、异常测试和用户提示无法验收。

### CQ-009：审计脱敏范围

认证中心和产品侧分别需要记录哪些 SSO 审计事件，手机号、邮箱、ticket、access_key、biz_context 中敏感字段的脱敏规则是什么？

影响：审计标准不确认会影响安全验收和日志合规检查。

## 测试场景补充视角

建议至少补齐以下测试场景：

1. 官网标准入口无 biz_context 的登录成功链路。
2. 携带 biz_context 的活动、推荐或邀请链路。
3. login_ticket 过期、重复使用、缺失、格式非法。
4. state 缺失、不匹配、过期或被篡改。
5. nonce 重放、nonce 缺失、nonce 重复。
6. product_access_key 缺失、错误、泄露检查和日志检查。
7. C 端已有映射、手机号命中绑定、无命中自动创建、绑定冲突。
8. B 端有账号有权限、有账号无权限、无账号、账号禁用、租户或角色异常。
9. B+C 产品根据 scene 或 user_intent 分流个人空间和企业空间。
10. INVITE_ONLY 产品邀请码有效、无效、过期、已使用、缺失。
11. return_url 合法、缺失、非法域名、跨域、被篡改。
12. account_status 为 ACTIVE、DISABLED、CANCELLED。
13. HTTP 429 限流响应和产品侧用户提示。
14. 审计日志不输出明文手机号、邮箱、login_ticket、product_access_key。

## 成熟度评估

成熟度：RA2，部分可测试。

理由：文档明确了目标、范围、职责边界、核心链路和部分验收项；但作为总览文档，接口契约、字段级规则、异常响应、产品模式细节和验收数据仍需确认。
