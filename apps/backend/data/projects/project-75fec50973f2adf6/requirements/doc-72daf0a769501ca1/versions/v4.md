# 对话流超长文本性能优化

## 背景

场景：海外项目需要将超长文档进行解析并存入对话流节点供下游消费。

问题：对话流节点字段携带超长文本会导致对话流引擎崩溃。

## 改造范围

**Python 版本：**

改对话流，包括自主规划 agent 和写作 agent 中**所有涉及系统变量、对话流变量读取、使用、写入的节点**：

- **输入节点**：收集用户回复至变量、收集用户上传文件
- **信息加工**：大模型变量赋值、普通变量赋值、知识检索变量赋值、文件检索变量赋值、文件解析
- **触发动作 & 分支**：代码执行、语义判断、条件判断
- **输出**：大模型回复、文本回复

## 改造方案

### 改造一：超长文本外置存储 + 变量引用透传 + 消费节点自动还原

当节点输出字段文本长度超过 10000 字符时：

1. 将完整文本内容存入数据库；
2. 对话流运行态中不再携带完整文本，只携带轻量级 chunk 引用信息；
3. 下游节点在真正消费变量时，根据引用信息读取完整内容；
4. 如果下游节点只需要判断、展示、传递，则根据节点类型决定是否读取完整内容；
5. 对于超长文本输出展示按 chunk 分区，前端切块展示（debug、预览、对话流测试、单节点调试、发布后页面、API 接口调试）。

**chunk 引用信息结构**：引用信息包含完整内容 ID、chunk 总数与每 chunk 长度，下游按需按 chunk 顺序读取并拼接。

## 兼容性设计

1. **对已有短文本变量无影响**  
   未超过 10000 字符的变量保持原结构，不影响现有流程。

2. **对下游节点尽量无感**  
   下游节点通过统一变量读取方法获取内容，不需要每个节点单独感知存储细节。

3. **对调试页面兼容**  
   调试页面输出分区展示完整超长文本。

4. **对历史会话兼容**  
   历史会话中已经存储的普通文本仍按原逻辑读取。

5. **对话流日志**  
   日志中展示变量的所有字段。
