# 需求理解

## 1. 需求背景
海外项目需要将超长文档解析后存入对话流节点供下游消费。现有对话流引擎在节点字段携带超长文本时会崩溃，需通过存储和消费机制改造避免引擎崩溃，并支持超长文本在调试、预览、发布后页面等场景下的正常展示。

## 2. 目标与价值
## 目标与价值

1. 避免对话流引擎因节点字段携带超长文本而崩溃
2. 在保持下游节点尽量无感知的前提下完成超长文本存储与消费改造
3. 使超长文本在 debug、预览、对话流测试、单节点调试、发布后页面、API 接口调试等场景下可分 chunk 展示
4. 已有短文本变量和历史会话的读取逻辑不受影响

## 4. 功能范围
## 功能范围

**包含的功能（Python 版本）**：

1. 改造点一：超长文本外置存储 + 变量引用透传 + 消费节点自动还原
   - 输入节点：收集用户回复至变量、收集用户上传文件
   - 信息加工节点：大模型变量赋值、普通变量赋值、知识检索变量赋值、文件检索变量赋值、文件解析
   - 触发动作 & 分支节点：代码执行、语义判断、条件判断
   - 输出节点：大模型回复、文本回复
   - 对上述节点中"系统变量、对话流变量"的读取、使用、写入逻辑进行改造
2. 改造点二：单个字段长度限制 20000 字
3. 兼容性：
   - 已有短文本变量（≤10000 字符）保持原结构
   - 下游节点通过统一变量读取方法获取内容，不需单独感知存储细节
   - 调试页面输出分区展示完整超长文本
   - 历史会话中已存储的普通文本按原逻辑读取
   - 对话流日志展示变量所有字段

**不包含的功能**：

1. Go 版本的具体改造范围与方案（原文标注待切流后补充完善）

## 5. 业务流程
## 业务流程

主流程（节点变量"写入 → 透传 → 消费"）：

1. **触发条件**：被改造范围内的任一节点（输入/信息加工/触发动作&分支/输出）产出文本型变量
2. **前置条件**：节点运行态上下文正常，变量读取/写入通道可用
3. **写入侧（变量产出节点）**：
   - 节点生成文本型变量内容
   - 系统判断文本长度
   - 长度 > 10000 字符：将完整文本存入数据库，运行态变量替换为轻量级 chunk 引用
   - 长度 ≤ 10000 字符：保持原结构直接放入运行态
4. **透传**：运行态仅携带引用（超长）或原文本（普通）继续向下游节点流转
5. **消费侧（下游节点）**：
   - 下游节点通过统一变量读取方法获取变量
   - 若下游节点为"真正消费"（需使用完整文本进行模型调用、写入、解析等）：根据 chunk 引用读出完整内容
   - 若下游节点仅"判断/展示/传递"：按节点类型决定是否读取完整内容
6. **展示侧（调试与发布后场景）**：超长文本按 chunk 分区展示，适用 debug、预览、对话流测试、单节点调试、发布后页面、API 接口调试

**分支**：

- 分支一：变量文本 ≤ 10000 字符 → 走"原结构透传"路径，下游无需特殊处理
- 分支二：变量文本 > 10000 字符 → 走"外置存储 + chunk 引用"路径，下游消费时按需还原

**图中未覆盖/原文未说明**：

- "真正消费"与"判断/展示/传递"的节点类型具体划分规则未明确
- 下游节点在 chunk 引用失效（如引用内容被清理）时的处理未明确
- API 接口调试场景下，下游调用方拿到的最终内容形态（完整文本/引用）未明确
