# 需求理解

## 1. 需求背景
海外项目需要将超长文档进行解析并存入对话流节点供下游消费。当前问题：对话流节点字段携带超长文本会导致对话流引擎崩溃。

## 2. 目标与价值
解决对话流引擎因节点字段携带超长文本而崩溃的问题，使超长文档能够正常解析、存储并在对话流中流转消费。

## 3. 用户角色与使用场景
| 用户角色 | 使用场景 | 用户目标 | 已知约束 |
|---------|---------|---------|---------|
| 海外项目用户 | 上传超长文档至对话流 | 将超长文档解析后存入对话流节点供下游消费 | 文档内容可能超过10000字符 |
| 对话流开发者/配置者 | 配置对话流节点（输入、信息加工、触发动作、输出） | 在对话流中正常使用超长文本变量，不触发引擎崩溃 | 超长文本需外置存储 |
| 对话流调试/测试人员 | 调试、预览、测试对话流 | 在调试页面查看超长文本完整内容 | 超长文本按chunk分区展示 |
| 最终用户 | 与对话流交互（发布后页面、API接口） | 正常消费对话流输出 | 超长文本按chunk分区展示 |

## 4. 功能范围
**包含的功能（Python版本）**：
1. 超长文本外置存储：节点输出字段文本长度超过10000字符时，将完整文本内容存入数据库
2. 变量引用透传：对话流运行态中只携带轻量级chunk引用信息，不携带完整文本
3. 消费节点自动还原：下游节点在真正消费变量时，根据引用信息读取完整内容
4. 按节点类型决定是否读取完整内容：下游节点只需要判断、展示、传递时，根据节点类型决定是否读取完整内容
5. 前端切块展示：超长文本输出展示按chunk分区（debug、预览、对话流测试、单节点调试、发布后页面、API接口调试）
6. 单个字段长度限制20000字
7. 兼容性设计：已有短文本变量无影响、下游节点尽量无感、调试页面兼容、历史会话兼容、对话流日志展示变量所有字段

**改造范围涉及的节点类型（Python版本）**：
- 输入节点：收集用户回复至变量、收集用户上传文件
- 信息加工：大模型变量赋值、普通变量赋值、知识检索变量赋值、文件检索变量赋值、文件解析
- 触发动作 & 分支：代码执行、语义判断、条件判断
- 输出：大模型回复、文本回复

**不包含的功能**：
