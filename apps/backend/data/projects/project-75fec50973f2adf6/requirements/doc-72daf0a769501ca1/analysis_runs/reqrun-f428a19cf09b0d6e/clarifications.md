# 待澄清问题

| 优先级 | 模块/对象 | 澄清问题 | 选项 A | 选项 B | 测试影响 |
|-------|----------|---------|--------|--------|------|
| P0 | 超长文本存储 | 节点输出字段文本长度超过10000字符时，触发外置存储的时机是什么？是在节点输出时立即存储，还是在整个对话流执行完成后统一存储？ | 节点输出时立即将完整文本存入数据库，运行态携带chunk引用信息 | 节点输出时先携带完整文本，待整个对话流执行完成后统一将超长文本存入数据库 | 影响超长文本存储的时序测试设计，无法判断存储失败时对话流是否继续执行，也无法验证运行态中是否真的不携带完整文本 |
| P0 | 长度限制 | 单个字段长度限制20000字，当文本长度超过20000字时如何处理？是截断、拒绝写入、还是分多个字段存储？ | 超过20000字时截断至20000字，并记录日志 | 超过20000字时拒绝写入并返回错误提示，要求用户缩短内容 | 影响超长文本边界场景的测试用例设计，无法断言超出20000字时的系统行为和用户反馈 |
| P0 | 消费节点还原 | 下游节点"真正消费变量"的判定标准是什么？哪些节点类型属于"需要读取完整内容"，哪些属于"只需要判断/展示/传递"？ | 大模型回复、代码执行、语义判断、条件判断节点需要读取完整内容；文本回复、展示类节点只需读取引用信息 | 所有节点类型统一在消费时读取完整内容，由框架层自动按需加载，节点本身不感知 | 影响所有下游节点消费超长文本的测试用例设计，无法判断哪些场景会触发完整内容读取、哪些不会，也无法验证不同节点类型的行为差异 |
| P1 | chunk分区 | 超长文本按chunk分区时，每个chunk的大小是多少？chunk的分区策略是什么（按字符数、按段落、还是按其他规则）？ | 每个chunk固定大小（如5000字符），按字符数切分 | 按自然段落或语义边界切分，每个chunk大小不固定 | 影响前端分块展示的测试用例设计，无法验证chunk边界是否正确、内容是否完整、分页/滚动逻辑是否正常 |
| P1 | chunk引用信息 | chunk引用信息的数据结构包含哪些字段？是否包含文本总长度、chunk数量、存储位置等元数据？ | 引用信息包含：文本ID、总长度、chunk数量、存储位置标识 | 引用信息仅包含：文本ID，下游节点通过ID查询完整内容 | 影响运行态数据结构的测试断言设计，无法验证引用信息是否足够下游节点还原完整内容 |
| P1 | 并发与一致性 | 多个对话流实例并发写入或读取同一超长文本时，如何保证数据一致性？是否存在并发写入覆盖的问题？ | 每个对话流实例独立存储超长文本，互不干扰，不存在并发覆盖问题 | 超长文本按唯一标识存储，后写入覆盖先写入，需考虑并发锁机制 | 影响并发场景的测试用例设计，无法验证高并发下数据是否一致、是否存在丢失或覆盖 |
| P1 | 超长文本清理 | 存入数据库的超长文本是否有生命周期？何时清理？是否随会话删除而删除？ | 超长文本随会话生命周期管理，会话删除时一并清理 | 超长文本独立存储，需要额外的定时清理策略（如保留7天后自动删除） | 影响数据清理和存储增长的测试覆盖，无法验证超长文本是否会无限累积导致存储膨胀 |
| P2 | 前端展示 | 前端按chunk分区展示超长文本时，具体的交互方式是什么？是分页、滚动加载、还是折叠展开？ | 分页展示，每页显示一个chunk，用户点击翻页查看 | 滚动加载，用户向下滚动时自动加载下一个chunk | 影响前端展示交互的测试用例设计，无法验证用户查看超长文本的完整交互流程 |
