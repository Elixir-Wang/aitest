# 待澄清问题

| 优先级 | 模块/对象 | 澄清问题 | 选项 A | 选项 B | 测试影响 |
|-------|----------|---------|--------|--------|------|
| P0 | 下游消费-节点类型划分 | 下游节点按什么规则划分为'真正消费完整内容'与'仅判断/展示/传递'？同一变量在不同下游节点可能同时承担两种用途时如何处理？ | 在每个被改造节点内显式声明该变量用途（消费/非消费），节点按声明决定是否按 chunk 引用还原完整内容 | 统一按'下游节点读取即还原'处理，全部下游节点在读取时拿到的都是完整文本，不做用途区分 | 无法设计大模型变量赋值、代码执行、语义判断、条件判断、文本回复等节点在消费超长文本时的还原断言，也无法验证同一变量在不同下游节点上的差异化处理 |
| P0 | 字段长度上限 | 当被改造节点的字段内容超过单字段 20000 字上限时，系统应如何处理？ | 在写入前拦截并报错，提示用户该字段超过 20000 字上限，阻止节点继续执行 | 超出 20000 字的部分截断丢弃，仅保留前 20000 字并在日志/页面标注已截断 | 无法设计超长输入（>20000 字）场景下的字段写入断言、用户提示文案验证以及节点执行阻断/截断行为的回归用例 |
| P0 | 外置存储一致性 | 当节点输出 > 10000 字符，完整文本落库成功但运行态变量替换为 chunk 引用失败时（如进程崩溃），如何保证运行态与外置存储一致？ | 落库与运行态引用写入作为同一事务，任一步失败则整笔回滚，运行态不出现孤立 chunk 引用 | 落库先成功即可推进，引用写入失败时节点按失败处理并保留落库内容供后续重试或补偿 | 无法设计超长文本场景下的崩溃/异常恢复用例，也无法断言运行态是否会出现引用悬空（落库有数据但运行态无引用或反之）的状态 |
| P1 | 下游消费-API 接口调试 | 在 API 接口调试场景下，下游调用方最终拿到的内容形态是完整文本还是 chunk 引用？ | API 接口调试场景统一在出口侧还原为完整文本返回，调用方无需感知 chunk 引用 | API 接口调试场景按 chunk 引用原样返回，由调用方决定是否拉取完整内容 | 无法设计 API 接口调试场景下超长文本的响应体断言（完整文本/引用结构），也无法验证下游调用方与新机制的兼容性 |
| P1 | chunk 引用失效 | 当下游节点按 chunk 引用读取完整内容时，若外置存储中的数据已被清理/失效，应如何处理？ | 视为数据缺失错误，节点按失败处理并向用户提示'引用内容已失效，无法读取完整文本' | 视为空内容处理，下游节点拿到空字符串继续执行，并在日志中标记'引用失效，已降级为空内容' | 无法设计外置存储数据失效/过期/被清理时的下游消费断言、错误提示验证以及节点失败/降级行为回归 |
| P1 | 调试页-分区展示 | 调试页面（debug/预览/对话流测试/单节点调试）'输出分区展示完整超长文本'中的'分区'具体按什么维度划分？ | 按 chunk 引用对应的存储分片逐片分区，每片一个独立可展开区域 | 按对话流节点维度分区，每个节点输出一个独立区域，区域内再按字段/原文顺序展示 | 无法设计调试页 UI 断言、分区交互（展开/收起/加载）的测试用例，也无法验证调试人员能否完整看到跨节点/跨分片的变量内容 |
| P1 | 日志规则-超长文本 | 对话流日志要求'展示变量的所有字段'，在变量为超长文本（chunk 引用）时，日志中展示的是引用信息还是完整文本？ | 日志展示完整文本内容，受日志长度限制时可截断并标注，便于排查 | 日志仅展示 chunk 引用信息（如引用 ID、长度），完整文本不在日志中出现 | 无法设计对话流日志在普通变量/超长变量场景下的字段断言，也无法验证日志量、排查效率与脱敏要求 |
| P1 | 历史会话-超长文本 | 历史会话兼容要求'已存储的普通文本按原逻辑读取'，如果历史会话中本就存在 > 10000 字符的旧数据（改造前已落库），读取时应如何处理？ | 历史会话中已存的 > 10000 字符旧数据读取时仍按完整文本返回，不做 chunk 引用化处理 | 历史会话中 > 10000 字符的旧数据在首次读取时统一迁移为 chunk 引用存储，迁移失败则按原文本返回 | 无法设计历史会话中既有超长文本的读取/展示/下游消费断言，也无法验证历史数据迁移或兼容路径是否需要回归 |
| P2 | 外置存储生命周期 | 外置存储中保存的完整超长文本（> 10000 字符）的保留时长与清理策略是什么？ | 随对话流运行实例生命周期保留，运行结束/会话归档后由系统统一清理外置存储中的完整文本 | 长期保留直至被人工/管理后台显式清理，不随运行实例生命周期自动过期 | 无法设计外置存储数据的留存/清理相关用例与回归范围，也无法判断下游引用失效是否构成高频风险 |
