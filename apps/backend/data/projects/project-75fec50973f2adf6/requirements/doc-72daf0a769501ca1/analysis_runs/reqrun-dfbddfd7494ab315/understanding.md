# 需求理解

## 1. 需求背景
海外项目需要将超长文档进行解析并存入对话流节点供下游消费。当前对话流节点字段携带超长文本会导致对话流引擎崩溃。

## 2. 目标与价值
解决对话流节点携带超长文本导致引擎崩溃的问题，通过超长文本外置存储+变量引用透传+消费节点自动还原的方案，使对话流能够稳定处理超长文本。

## 3. 用户角色与使用场景
| 用户角色 | 使用场景 | 用户目标 | 已知约束 |
|---------|---------|---------|---------|
| 海外项目用户 | 上传超长文档并解析，在对话流中消费 | 能够正常使用超长文档内容 | 对话流引擎无法承载超长文本 |
| 对话流开发者/配置者 | 配置对话流节点（输入、信息加工、触发动作、输出） | 配置的对话流能稳定运行，不受超长文本影响 | 需了解超长文本的引用机制 |
| 调试/测试人员 | 调试对话流、预览输出、单节点调试 | 能够查看超长文本的完整内容 | 超长文本需分区展示 |
| 最终用户（发布后） | 使用发布后的对话流功能 | 正常使用，无感知 | 无 |

## 4. 功能范围
**包含的功能（Python版本）**：
1. 超长文本外置存储：节点输出字段文本长度超过10000字符时，将完整文本存入数据库
2. 变量引用透传：对话流运行态中只携带轻量级chunk引用信息，不携带完整文本
3. 消费节点自动还原：下游节点消费变量时根据引用信息读取完整内容
4. 按节点类型决定是否读取完整内容：下游节点只需判断/展示/传递时，根据节点类型决定是否读取
5. 超长文本输出分区展示：debug、预览、对话流测试、单节点调试、发布后页面、API接口调试前端切块展示
6. 单个字段长度限制20000字
7. 改造范围覆盖Python版本的所有节点类型：输入节点（收集用户回复至变量、收集用户上传文件）、信息加工（大模型变量赋值、普通变量赋值、知识检索变量赋值、文件检索变量赋值、文件解析）、触发动作&分支（代码执行、语义判断、条件判断）、输出（大模型回复、文本回复）

## 5. 业务流程
1. 用户上传超长文档或对话流节点产生超长文本输出
2. 系统判断输出字段文本长度是否超过10000字符
   - 若未超过：保持原结构，按原有逻辑处理
   - 若超过：进入超长文本处理流程
3. 超长文本处理流程：
   a. 将完整文本内容存入数据库
   b. 对话流运行态中只携带轻量级chunk引用信息（不携带完整文本）
4. 下游节点消费变量时：
   a. 判断节点类型是否需要读取完整内容
   b. 若需要（如大模型回复、文本回复等消费节点）：根据引用信息从数据库读取完整内容
   c. 若不需要（如仅判断、展示、传递的节点）：使用引用信息即可
5. 前端展示时：超长文本按chunk分区展示
6. 历史会话中已存储的普通文本按原逻辑读取

## 7. 业务规则
| 规则类型 | 触发条件 | 判断逻辑 | 处理结果 |
|---------|---------|---------|---------|
| 存储规则 | 节点输出字段文本 | 文本长度 > 10000字符 | 完整文本存入数据库，运行态只携带chunk引用信息 |
| 存储规则 | 节点输出字段文本 | 文本长度 ≤ 10000字符 | 保持原结构，不触发外置存储 |
| 长度限制 | 所有节点输出字段 | 文本长度 > 20000字符 | 单个字段长度限制20000字（超出后的处理方式原文未说明） |
| 读取规则 | 下游节点消费变量 | 节点类型需要完整内容 | 根据引用信息从数据库读取完整内容 |
| 读取规则 | 下游节点消费变量 | 节点类型仅需判断/展示/传递 | 不读取完整内容，使用引用信息 |
| 兼容规则 | 历史会话 | 已存储的普通文本 | 按原逻辑读取 |
| 展示规则 | 前端展示超长文本 | 文本按chunk分区 | 前端切块展示 |
