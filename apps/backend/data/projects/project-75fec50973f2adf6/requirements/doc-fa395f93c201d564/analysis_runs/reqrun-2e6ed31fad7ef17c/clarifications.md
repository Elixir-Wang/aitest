# 待澄清问题

| 优先级 | 模块/对象 | 澄清问题 | 选项 A | 选项 B | 测试影响 |
|-------|----------|---------|--------|--------|------|
| P0 | 模型数据 | 模型是否支持思考模式的标识数据来源是什么？是后端接口返回的字段，还是前端静态配置的模型列表？ | 后端接口返回模型列表时，每个模型携带是否支持思考模式的字段（如 `supports_think_mode: true/false`） | 前端维护一份支持思考模式的模型白名单，前端根据模型名称或ID判断是否展示标签和开关 | 无法设计模型支持度数据的获取方式测试，无法断言标签展示/隐藏的准确性，也无法验证新增模型后标签是否正确展示 |
| P0 | 配置持久化 | 思考模式开关的状态如何持久化？是保存在Agent配置中，还是作为独立的用户偏好设置？ | 思考模式开关状态作为Agent配置的一部分，保存在Agent配置数据中，不同Agent独立记忆开关状态 | 思考模式开关状态作为全局用户偏好设置，切换后对所有Agent生效 | 无法设计开关状态的保存、读取和隔离性测试，无法断言切换Agent后开关状态是否正确 |
| P0 | 对话请求 | 思考模式开启后，对话请求中如何将思考模式参数传递给LLM？是通过请求参数传递，还是由后端根据Agent配置自动处理？ | 前端在对话请求中携带思考模式参数（如 `think_mode: true/false`），后端透传给LLM | 前端不传递参数，后端根据Agent配置中保存的思考模式状态，在调用LLM时自动处理 | 无法设计思考模式开启/关闭的端到端测试，无法断言参数传递的正确性 |
| P1 | 模型切换联动 | 在对话模型配置弹窗中，用户切换模型时，思考模式开关如何联动？ | 切换模型后，思考模式开关重置为默认关闭状态，用户需重新开启 | 切换模型后，如果新模型也支持思考模式，保留上一次的开关状态；如果不支持，隐藏开关并清除开启状态 | 无法设计模型切换场景下开关联动逻辑的测试用例，无法断言切换后开关状态和展示的正确性 |
| P1 | 默认状态 | 当用户首次选择一个支持思考模式的模型时，思考模式开关的默认状态是什么？ | 默认关闭，用户需要手动开启 | 默认开启，用户需要手动关闭 | 无法设计首次配置场景的默认状态断言，影响用户体验和回归测试 |
| P1 | 历史兼容 | 对于已存在的Agent配置（在本次功能上线前已配置好模型的Agent），思考模式开关的默认状态是什么？ | 历史Agent默认关闭思考模式，用户可手动开启 | 历史Agent根据模型是否支持思考模式自动决定，支持的模型默认开启 | 无法设计历史数据兼容性测试用例，无法断言存量Agent升级后的行为是否符合预期 |
| P1 | 思考过程展示 | 思考模式开启后，在Agent对话框中展示的思考过程具体包含哪些内容？是展示完整的推理链，还是仅展示摘要或关键步骤？ | 展示LLM返回的完整思考过程/推理链内容 | 展示经过后端处理或截断后的摘要信息 | 无法设计思考过程展示内容的断言，无法区分正常展示和异常截断场景 |
