# 多图合并解析PRD（原大模型变量赋值节点变更需求）

## 背景

百工平台可通过大模型变量赋值节点给会话变量动态赋值，用于构造大模型 Prompt。现有大模型赋值节点对于多图场景仅支持单个图片处理后串联结果，客户希望将多个图拼接后在一个 message 中统一作为大模型的输入，将图片作为大模型输入的一部分，而不是分多次调用模型。

OpenRouter 兼容 OpenAI 多模态消息格式，在同一条 messages 中通过数组形式发送图片。当请求中包含多张图片时，需要将每张图片单独放在 content 数组项中。因此，需要在前端收集并存储用户上传的多张图片至文件系统并生成 url，并按顺序拼接生成多个 image_url 消息，后台依据 OpenRouter 规范组装请求。

## 改造范围与清单

两个方案都实施。

Plan A 修改节点：

- 自主规划 agent 的 chatflow：收集用户上传文件 & 文件解析节点
- 任务流 agent 的 workflow：开始节点 & 文件解析节点
- 写作 agent 中的对话流：收集用户上传文件 & 文件解析节点

Plan B 修改节点：

- 自主规划 agent 的 chatflow：大模型回复 & 大模型变量赋值节点
- 任务流 agent 的 workflow：大模型变量赋值节点，需适配 go 版本工作流
- 写作 agent 中的对话流：大模型回复 & 大模型变量赋值节点
