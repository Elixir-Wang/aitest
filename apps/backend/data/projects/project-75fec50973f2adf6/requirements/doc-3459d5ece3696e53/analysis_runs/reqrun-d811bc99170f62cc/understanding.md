# 需求理解

## 1. 需求背景
百工平台通过大模型变量赋值节点给会话变量动态赋值，用于构造大模型 Prompt。现有大模型赋值节点对于多图场景仅支持单个图片处理后串联结果，客户希望将多个图拼接后在一个 message 中统一作为大模型的输入，将图片作为大模型输入的一部分，而不是分多次调用模型。OpenRouter 兼容 OpenAI 多模态消息格式，在同一条 messages 中通过数组形式发送图片。当请求中包含多张图片时，需要将每张图片单独放在 content 数组项中。因此，需要在前端收集并存储用户上传的多张图片至文件系统并生成 url，并按顺序拼接生成多个 image_url 消息，后台依据 OpenRouter 规范组装请求。

## 2. 目标与价值
支持多图合并解析，将多张图片拼接后在一个 message 中统一作为大模型的输入，而不是分多次调用模型。提升用户体验，满足客户对多图场景的统一处理需求。

## 3. 用户角色与使用场景
| 用户角色 | 使用场景 | 用户目标 | 已知约束 |
|---------|---------|---------|---------|
| 平台用户（对话流/工作流使用者） | 在对话流或工作流中上传多张图片进行解析 | 一次性上传多张图片并统一解析，将图片作为大模型输入的一部分 | 最多上传 10 张图片 |
| 平台管理员（赛博坦后台） | 在赛博坦后台配置模型的多图合并解析能力 | 配置模型是否支持多图合并解析 | 已录入的模型默认关闭状态 |
| 工作流/对话流配置者 | 在节点配置中选择模型、开启多图解析模式 | 配置多图解析的模型和解析方式 | 需选择支持多图解析的模型 |

## 4. 功能范围
**包含的功能**：
1. 赛博坦后台：模型能力配置，新增多图合并解析开关（支持/不支持），已录入模型默认关闭
2. 对话流/工作流节点：
   - Plan A：修改收集用户上传文件节点 & 文件解析节点，增加多图合并解析
   - Plan B：修改大模型回复 & 大模型变量赋值节点，新增图像输入模块
3. 模型列表展示多模态 icon 标识
4. 文件上传对话窗口支持多图上传（本地上传和 URL 上传），最多 10 张
5. URL 上传功能：支持一次上传多个 url 地址，校验文件大小、数量、格式
6. 后台按 OpenRouter 规范组装请求 messages 数组
7. 三种类型 agent & chat flow 的复制导入导出兼容
8. trace 日志

**不包含的功能**：
1. 文生图模型管理模块（下期评审）
2. 文生图节点（下期评审）

## 5. 业务流程
**Plan A 流程（对话流/工作流）**：
1. 用户在赛博坦后台配置模型的多图合并解析能力（支持/不支持）
2. 用户在对话流/工作流中配置文件解析节点
3. 文件类型选择包含图片后，点击自定义解析方式加号
4. 开启多图解析开关
5. 选择支持多图解析的模型（如 Qwen3.6-plus）
6. 运行对话流/工作流时，用户上传多张图片（本地上传或 URL 上传）
7. 上传完成后点击解析按钮，系统一次性进行解析
8. 解析完成后所有文件右侧展示 ✅
9. 后台按顺序拼接生成大模型请求的 messages 数组
10. 发送请求到 OpenRouter/大模型

**Plan B 流程**：
1. 在赛博坦后台新增/编辑模型时开启图像理解能力
2. 在大模型变量赋值节点选择支持图像理解的模型
3. 展示图像赋值区与多图拼接按钮
4. 用户在视觉理解赋值输入框中多选赋值变量
5. 收集用户上传文件组件支持多文件选择
6. 系统将图片存储到平台文件服务并生成可访问 URL
7. 后台按顺序拼接生成大模型请求的 messages 数组

**URL 上传流程**：
1. 用户打开文件上传对话窗口（对话流调试、agent 调试、agent-web 页、工作流 agent 开始节点）
2. 用户选择本地上传或 URL 上传
3. 本地上传：选择图片文件（最多 10 张）
4. URL 上传：输入多个 url 地址（最多 10 张）
5. 系统校验文件大小、数量、格式
6. 文件状态流转：传输中 → 传输完成 → 解析中 → 解析完成
7. 如果配置了文件解析变量赋值，文件自动解析

## 6. 状态流转
**文件状态流转**：
| 状态 | 触发条件 | 可执行操作 | 下一状态 |
|-----|---------|-----------|---------|
| 传输中 | 用户上传文件 | 等待 | 传输完成/传输失败 |
| 传输完成 | 上传成功 | 解析 | 解析中 |
| 传输失败 | 上传失败（校验不通过/网络错误） | 重新上传 | 传输中 |
| 解析中 | 用户点击解析按钮 | 等待 | 解析完成/解析失败 |
| 解析完成 | 解析成功 | 提交 | 提交后进入下一流程 |
| 解析失败 | 解析出错 | 重新解析 | 解析中 |

**多图解析状态（Plan A 对话流）**：
- 多图在未解析状态下显示未解析状态
- 解析完成后所有文件右侧展示 ✅
- 解析完成后再次上传文件或 url 后需要重新点击解析按钮才能点击提交按钮

## 7. 业务规则
| 规则类型 | 触发条件 | 判断逻辑 | 处理结果 |
|---------|---------|---------|---------|
| 校验规则 | 上传图片 | 文件大小、数量（最多 10 张）、格式校验 | 不符合校验规则报错 |
| 校验规则 | 选择模型 | 模型是否支持多图解析 | 不支持则清除模型选择或隐藏功能区 |
| 校验规则 | 开启多图解析 | 当前选择的模型是否支持多图解析 | 不支持则清除模型配置 |
| 校验规则 | 选择支持多图解析的模型后开启多图解析 | 模型支持 | 保留模型配置 |
| 校验规则 | 工作流运行时 | 超上下文报错 | 给出报错原因 |
| 校验规则 | 工作流多图解析失败 | 解析失败 | 退出工作流并报错，保持现有逻辑 |
| 默认规则 | 未定义特定多图解析模型 | 无特定模型配置 | 使用兜底多图解析模型进行解析 |
| 配置规则 | 赛博坦后台新增/编辑模型 | 多图合并解析开关 | 已录入的模型默认关闭状态 |
| 交互规则 | 解析完成后再次上传文件或 url | 已有解析结果 | 需要重新点击解析按钮才能点击提交按钮 |

## 8. 页面与交互
**赛博坦后台 - 模型配置页**：
- 新增/编辑模型页面新增多图合并解析开关（支持/不支持）
- 已录入的模型默认关闭状态

**对话流 - 文件解析节点**：
- 文件类型选择包含图片后，点击自定义解析方式加号
- 出现多图解析开关，位置在自定义解析方式点击加号后下方第一行
- 开启后，选择图片，列表展示后台支持多图解析的模型列表

**对话流/工作流 - 运行界面**：
- 用户输入新增多图合并子集上传模块
- 支持本地上传和 URL 上传
- 多图在未解析状态下显示未解析状态
- 解析完成后所有文件右侧展示 ✅
- 解析按钮

**模型选择列表**：
- 大模型回复、大模型变量赋值下选择模型列表给出 icon 区分具有多模态的模型
- 函数调用能力展示项隐藏，模型能力默认以 icon 形式展示在列表

**Plan B - 大模型变量赋值节点**：
- 选择支持图像理解的模型后展示图像赋值区与多图拼接按钮
- 选择不支持图片理解的模型时隐藏该功能区
- 视觉理解赋值输入框中可多选赋值变量

**文件上传对话窗口**：
- 范围：对话流调试、agent 调试、agent-web 页、工作流 agent 开始节点
- 本地上传多图解析限制上传最多 10 张图片
- 添加 URL 支持一次上传多个 url 地址
- url 文件状态展示：传输中、传输完成（不展示）、传输失败、解析中、解析失败、解析完成（不展示）

## 9. 数据与系统交互
**文件存储**：
- 用户上传的图片存储至平台文件系统并生成可访问的 URL

**后台请求组装**：
- 后台按顺序拼接生成大模型请求的 messages 数组
- 格式遵循 OpenRouter/OpenAI 多模态消息格式
- 每张图片单独放在 content 数组项中，类型为 image_url
- 示例 messages 结构：
```json
{
  "model": "google/gemini-2.5-flash",
  "messages": [
    {
      "role": "user",
      "content": [
        {"type": "text", "text": "请对比这几张图，指出主要差异。"},
        {"type": "image_url", "image_url": {"url": "https://example.com/image1.jpg"}},
        {"type": "image_url", "image_url": {"url": "https://example.com/image2.jpg"}}
      ]
    }
  ]
}
```

**系统交互**：
- 对接 OpenRouter 兼容 OpenAI 多模态消息格式
- 对接平台文件服务：存储图片并生成 URL

**变更影响**：
- 三种类型 agent & chat flow 的复制导入导出需兼容
- trace 日志
