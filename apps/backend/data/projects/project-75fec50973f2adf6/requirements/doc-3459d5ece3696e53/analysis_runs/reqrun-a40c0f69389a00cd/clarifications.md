# 待澄清问题

| 优先级 | 模块/对象 | 澄清问题 | 选项 A | 选项 B | 影响 |
|-------|----------|---------|--------|--------|------|
| P0 | 多图解析-模型选择 | Plan A 中提到的'兜底多图解析模型'具体是哪个模型？如何配置？ | 系统预设一个默认模型（如 Qwen3.6-plus），用户不可修改 | 在赛博坦后台增加一个'兜底多图解析模型'配置项，由管理员指定 | 影响多图解析的核心逻辑实现，若兜底模型不明确，开发无法确定默认行为 |
| P0 | 多图解析-解析触发 | Plan A 中对话流运行时的'解析按钮'和'提交按钮'的关系是什么？用户点击解析后是否自动提交？ | 点击解析按钮后自动提交并运行工作流/对话流 | 点击解析按钮仅完成图片解析，用户需再点击提交/运行按钮才能触发后续流程 | 影响用户操作流程和交互设计，决定解析和提交流程是分离还是合并 |
| P0 | 多图解析-工作流失败处理 | 工作流多图解析失败时，具体报错信息是什么？是否支持重试？ | 失败时退出工作流并报错'多图解析失败：{具体原因}'，用户需手动重新运行 | 失败时退出工作流并报错，但提供'重试'按钮，点击后重新执行解析步骤 | 影响工作流的异常处理机制和用户体验 |
| P1 | URL上传-校验规则 | URL上传时，文件大小校验的具体上限是多少？支持的图片格式有哪些？ | 单张图片不超过10MB，支持 jpg/png/gif/webp 格式 | 单张图片不超过20MB，支持 jpg/png/gif/bmp/webp 格式 | 影响前端校验逻辑和后端处理能力 |
| P1 | 多图解析-模型切换 | Plan A 中，开启多图解析后如果用户切换到一个不支持多图解析的模型，已上传的图片和解析状态如何处理？ | 清除已上传的图片和解析状态，提示用户当前模型不支持多图解析 | 保留已上传的图片，但禁用解析按钮，提示用户切换模型 | 影响用户在配置节点时的交互体验和数据一致性 |
| P1 | Plan B-变量赋值 | Plan B 中'视觉理解赋值输入框中可多选赋值变量'，这些变量是什么类型？是图片URL字符串还是文件对象？ | 变量类型为图片URL字符串，用户从已有的字符串变量中选择 | 变量类型为文件对象，用户从已有的文件类型变量中选择 | 影响变量选择的数据类型和后端拼接逻辑 |
| P1 | 多图解析-并发限制 | 多图解析是否有并发限制？同一用户是否可以同时发起多个多图解析请求？ | 无并发限制，用户可以同时发起多个解析请求 | 同一用户同时只能有一个解析任务进行中，新的请求需等待当前任务完成 | 影响系统在高并发场景下的稳定性和资源消耗 |
| P2 | 多图解析-图片顺序 | 多图拼接时，图片的顺序是否严格按照用户上传/选择的顺序？用户是否可以调整顺序？ | 严格按照用户上传的顺序拼接，用户不可调整 | 用户上传后可以拖拽调整图片顺序，按调整后的顺序拼接 | 影响用户体验和最终大模型接收到的图片顺序 |
| P2 | trace日志 | trace日志需要记录多图解析的哪些信息？ | 记录上传的图片URL列表、解析结果、耗时、使用的模型 | 记录上传的图片数量、解析成功/失败状态、耗时 | 影响日志系统的设计和后续问题排查能力 |
