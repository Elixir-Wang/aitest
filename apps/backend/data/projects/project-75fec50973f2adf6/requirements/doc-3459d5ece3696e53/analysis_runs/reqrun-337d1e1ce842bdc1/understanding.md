# 需求理解

## 1. 需求背景

百工平台通过大模型变量赋值节点给会话变量动态赋值，用于构造大模型 Prompt。现有大模型赋值节点对于多图场景仅支持单个图片处理后串联结果，客户希望将多个图拼接后在一个 message 中统一作为大模型的输入，将图片作为大模型输入的一部分，而不是分多次调用模型。

OpenRouter 兼容 OpenAI 多模态消息格式，在同一条 messages 中通过数组形式发送图片。当请求中包含多张图片时，需要将每张图片单独放在 content 数组项中。因此，需要在前端收集并存储用户上传的多张图片至文件系统并生成 url，并按顺序拼接生成多个 image_url 消息，后台依据 OpenRouter 规范组装请求。

## 2. 目标与价值

**业务目标**：支持多图合并解析，将多张图片拼接后在一个 message 中统一作为大模型的输入，而不是分多次调用模型。

**用户价值**：客户可以将多张图片作为大模型输入的一部分，实现多图对比、多图综合分析等场景。

**系统价值**：适配 OpenRouter 兼容 OpenAI 多模态消息格式，在同一条 messages 中通过数组形式发送图片。

## 3. 用户角色与使用场景

| 用户角色 | 使用场景 | 用户目标 | 已知约束 |
|---------|---------|---------|---------|
| 平台管理员 | 赛博坦后台配置模型 | 在新增/编辑模型时配置模型是否支持多图合并解析/图像理解能力 | 已录入的模型默认关闭状态 |
| 对话流/工作流设计者 | 设计对话流/工作流时配置节点 | 在文件解析节点/大模型变量赋值节点中配置多图解析 | 需要选择支持多图解析的模型 |
| 终端用户 | 运行对话流/工作流时上传图片 | 上传多张图片并触发多图合并解析 | 最多上传10张图片 |

## 4. 功能范围

**包含的功能**：

1. **赛博坦后台 - 模型能力配置**
   - Plan A：新增必填模型配置项"多图合并解析：支持/不支持"，已录入的模型默认关闭状态
   - Plan B：在新增模型页面与模型编辑页面新增"图像理解能力"开关按钮，已录入的模型默认关闭状态

2. **工作流/对话流节点改造（Plan A）**
   - 修改对话流、任务流中**文件解析节点**和**收集用户上传文件节点**，增加多图合并解析
   - 文件解析模块，文件类型选择包含图片后，点击自定义解析方式加号后出现多图解析开关
   - 开启后，选择图片，列表展示后台支持多图解析的模型列表
   - 如果没有定义图片特定模型进行多图解析，默认使用兜底多图解析模型进行解析
   - 如果未开启多图解析模式，选择了一个不支持多图解析的模型后，开启多图解析将模型清除
   - 如果选择的支持多图解析模型后保留模型配置
   - 解析模型优先支持 Qwen3.6-plus
   - 运行对话流和工作流时，当用户选择多图解析时，用户输入新增多图合并子集上传模块，支持本地上传和 URL 上传
   - 上传完成后点击解析一次性进行解析
   - 多图在未解析状态下显示未解析状态，解析完成后所有文件右侧展示 ✅
   - 在解析完成后再次上传文件或 url 后需要重新点击解析按钮才能点击提交按钮
   - 工作流开始节点 & 文件解析节点：如果勾选多图解析，新增解析按钮，上传完成后除图片外先进行解析。点击运行后将所有图片拼接进行统一解析，如果失败退出工作流并报错，保持现有逻辑

3. **工作流/对话流节点改造（Plan B）**
   - 模型开启图像理解能力后，在大模型模型选择列表展示图片理解标识（icon）
   - 节点在渲染时读取当前选择的大模型配置，判断其是否支持图像解析
   - 函数调用能力展示项隐藏，模型能力默认以 icon 形式展示在列表
   - 展示图像赋值区与多图拼接按钮
   - 选择不支持图片理解的模型时隐藏该功能区
   - 前端：用户在视觉理解赋值输入框中可多选赋值变量
   - 后端：收集用户上传文件组件支持多文件选择，系统将在用户上传后立即将图片存储到平台文件服务并生成可访问的 URL，后台按顺序拼接生成大模型请求的 message

4. **URL 上传功能**
   - 范围：对话流调试、agent 调试、agent-web 页、工作流 agent 开始节点
   - 本地上传多图解析限制上传最多 10 张图片
   - 添加 URL 支持一次上传多个 url 地址
   - 上传需校验文件大小、数量最多 10 张、格式，不符合校验规则报错
   - url 文件状态：传输中、传输完成（不展示）、传输失败、解析中、解析失败、解析完成（不展示）
   - 如果配置了文件解析变量赋值，文件自动解析

5. **变更影响兼容**
   - 三种类型 agent & chat flow 的复制导入导出需兼容
   - trace 日志需适配

**不包含的功能**：
- 文生图模型管理模块（下期评审）
- 文生图节点（下期评审）

## 5. 业务流程

### Plan A - 对话流/工作流多图合并解析流程

**角色**：对话流/工作流设计者（配置阶段）、终端用户（运行阶段）

**前置条件**：
- 赛博坦后台已配置模型支持"多图合并解析"
- 文件解析节点已开启多图解析开关并选择了支持多图解析的模型

**正常流程**：

1. 用户在对话流/工作流运行界面中，在多图合并子集上传模块上传图片（本地上传或 URL 上传）
2. 系统校验文件数量（最多10张）、大小、格式，不符合则报错
3. 用户点击"解析"按钮
4. 系统一次性解析所有图片
5. 解析完成后，所有文件右侧展示 ✅ 状态
6. 用户点击"提交"按钮
7. 后台将所有图片按顺序拼接，生成包含多个 image_url 的 messages 数组
8. 后台依据 OpenRouter 规范组装请求并发送给大模型

**异常分支**：
- 上传文件不符合校验规则（数量、大小、格式）→ 系统报错提示
- 解析失败 → 工作流退出并报错（保持现有逻辑）
- 解析完成后再次上传文件或 URL → 需要重新点击解析按钮才能点击提交按钮

### Plan B - 大模型变量赋值节点多图拼接流程

**角色**：对话流/工作流设计者（配置阶段）、终端用户（运行阶段）

**前置条件**：
- 赛博坦后台已配置模型开启"图像理解能力"
- 大模型变量赋值节点选择了支持图像理解的模型

**正常流程**：

1. 用户在大模型变量赋值节点的视觉理解赋值输入框中多选赋值变量
2. 用户在收集用户上传文件组件中选择多个文件
3. 系统将图片存储到平台文件服务并生成可访问的 URL
4. 后台按顺序拼接生成大模型请求的 message（包含 text 和多个 image_url）
5. 后台发送请求给大模型

**异常分支**：
- 选择不支持图片理解的模型 → 隐藏图像赋值区与多图拼接按钮
- 工作流运行时超上下文报错 → 给出报错原因

## 6. 状态流转

### URL 文件状态流转

| 当前状态 | 触发条件/动作 | 执行角色 | 下一状态 | 可观察结果 |
|---------|-------------|---------|---------|-----------|
| 传输中 | 用户上传 URL 文件 | 系统 | 传输完成（不展示）或传输失败 | 页面展示传输中状态 |
| 传输完成（不展示） | 文件传输成功 | 系统 | 解析中（如果配置了文件解析变量赋值则自动解析） | 不展示该状态 |
| 传输失败 | 文件传输失败 | 系统 | 传输失败 | 页面展示传输失败状态 |
| 解析中 | 触发解析（手动点击解析按钮或自动解析） | 系统 | 解析完成（不展示）或解析失败 | 页面展示解析中状态 |
| 解析完成（不展示） | 解析成功 | 系统 | - | 不展示该状态，文件右侧展示 ✅ |
| 解析失败 | 解析失败 | 系统 | 解析失败 | 页面展示解析失败状态 |

### 多图解析状态（Plan A 对话流）

| 当前状态 | 触发条件/动作 | 执行角色 | 下一状态 | 可观察结果 |
|---------|-------------|---------|---------|-----------|
| 未解析 | 用户上传图片完成 | 用户 | 解析中 | 文件显示未解析状态 |
| 解析中 | 用户点击解析按钮 | 系统 | 解析完成或解析失败 | 页面展示解析中 |
| 解析完成 | 解析成功 | 系统 | - | 所有文件右侧展示 ✅ |
| 解析失败 | 解析失败 | 系统 | - | 页面展示解析失败 |

## 9. 数据与系统交互

### 已知数据

**模型配置数据**：
- Plan A：模型是否支持"多图合并解析"（支持/不支持）
- Plan B：模型是否开启"图像理解能力"（开关）

**文件数据**：
- 上传的图片文件
- 文件大小、数量（最多10张）、格式
- 文件状态：传输中、传输完成、传输失败、解析中、解析失败、解析完成

**URL 数据**：
- 用户输入的 URL 地址
- URL 文件状态：传输中、传输完成（不展示）、传输失败、解析中、解析失败、解析完成（不展示）

### 系统交互

**前端 → 平台文件服务**：
- 用户上传图片后，系统将图片存储到平台文件服务并生成可访问的 URL

**后台 → 大模型（OpenRouter）**：
- 后台按顺序拼接生成大模型请求的 messages 数组
- 格式：OpenAI 多模态消息格式（兼容 OpenRouter）
- 每张图片单独放在 content 数组项中，类型为 image_url
- 请求示例见附录

### 后台生成请求的 messages 数组格式

```json
{
  "model": "google/gemini-2.5-flash",
  "messages": [
    {
      "role": "user",
      "content": [
        {
          "type": "text",
          "text": "请对比这几张图，指出主要差异。"
        },
        {
          "type": "image_url",
          "image_url": {
            "url": "https://example.com/image1.jpg"
          }
        },
        {
          "type": "image_url",
          "image_url": {
            "url": "https://example.com/image2.jpg"
          }
        }
      ]
    }
  ]
}
```
