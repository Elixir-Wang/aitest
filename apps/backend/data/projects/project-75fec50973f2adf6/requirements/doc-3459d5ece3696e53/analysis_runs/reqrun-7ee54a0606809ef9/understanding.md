# 需求理解

## 1. 需求背景
百工平台可通过大模型变量赋值节点给会话变量动态赋值，用于构造大模型 Prompt。现有大模型赋值节点对于多图场景仅支持单个图片处理后串联结果，客户希望将多个图拼接后在一个 message 中统一作为大模型的输入，将图片作为大模型输入的一部分，而不是分多次调用模型。OpenRouter 兼容 OpenAI 多模态消息格式，在同一条 messages 中通过数组形式发送图片。当请求中包含多张图片时，需要将每张图片单独放在 content 数组项中。因此，需要在前端收集并存储用户上传的多张图片至文件系统并生成 url，并按顺序拼接生成多个 image_url 消息，后台依据 OpenRouter 规范组装请求。

## 2. 目标与价值
实现多图合并解析功能，支持用户上传多张图片后在一个 message 中统一作为大模型的输入，将图片作为大模型输入的一部分，而不是分多次调用模型。支持本地上传和 URL 上传两种方式，支持最多 10 张图片的合并解析。

## 3. 用户角色与使用场景
| 用户角色 | 使用场景 | 用户目标 | 已知约束 |
|---------|---------|---------|---------|
| 百工平台用户（对话流/工作流使用者） | 使用对话流或工作流时上传多张图片进行合并解析 | 将多张图片一次性提交给大模型进行统一分析 | 最多上传 10 张图片 |
| 平台管理员（赛博坦后台） | 在赛博坦后台配置模型的多图合并解析能力 | 配置模型是否支持多图合并解析 | 已录入的模型默认关闭状态 |
| 工作流/对话流设计者 | 在设计工作流/对话流时配置文件解析节点和大模型变量赋值节点 | 配置多图合并解析开关、选择解析模型 | 需选择支持多图解析的模型 |

## 4. 功能范围
**包含的功能**：
1. 赛博坦后台新增模型配置项：多图合并解析（支持/不支持），已录入模型默认关闭
2. 大模型变量赋值节点新增图像输入模块（Plan B）
3. 大模型回复、大模型变量赋值下选择模型列表给出 icon 区分具有多模态的模型
4. 文件解析节点新增多图合并解析开关（Plan A）
5. 收集用户上传文件节点支持多图合并解析（Plan A）
6. 对话流调试、agent 调试、agent-web 页、工作流 agent 开始节点的文件上传对话窗口支持 URL 上传
7. 本地上传和 URL 上传多图解析限制最多 10 张图片
8. URL 上传支持一次上传多个 url 地址，需校验文件大小、数量、格式
9. URL 文件状态管理：传输中、传输完成、传输失败、解析中、解析失败、解析完成
10. 后台按顺序拼接生成大模型请求的 messages 数组（符合 OpenRouter/OpenAI 多模态消息格式）
11. 三种类型 agent & chat flow 的复制导入导出需兼容
12. trace 日志适配

**不包含的功能**（原文明确说明下期评审）：
1. 文生图模型管理模块（下期评审）
2. 文生图节点（下期评审）

## 5. 业务流程
**Plan A 流程（修改文件解析节点 & 收集用户上传文件节点）：**

1. 管理员在赛博坦后台配置模型是否支持多图合并解析（默认关闭）
2. 设计者在对话流/工作流中配置文件解析节点：
   - 文件类型选择包含图片
   - 点击自定义解析方式加号后出现多图解析开关
   - 开启后选择图片，列表展示后台支持多图解析的模型
   - 如果未定义特定模型，默认使用兜底多图解析模型
3. 用户运行对话流/工作流时：
   - 在开启多图解析的类别下，用户输入新增多图合并子集上传模块
   - 支持本地上传和 URL 上传
   - 上传完成后点击解析按钮一次性进行解析
   - 多图在未解析状态下显示未解析状态，解析完成后所有文件右侧展示 ✅
   - 解析完成后再次上传文件或 url 后需要重新点击解析按钮才能点击提交按钮
4. 后台按顺序拼接生成大模型请求的 messages 数组
5. 大模型返回结果

**Plan B 流程（修改大模型回复 & 大模型变量赋值节点）：**

1. 管理员在赛博坦后台新增/编辑模型时开启图像理解能力按钮
2. 设计者在节点中选择支持图像理解的模型（列表中有 icon 标识）
3. 前端展示图像赋值区与多图拼接按钮
4. 用户在视觉理解赋值输入框中可多选赋值变量
5. 收集用户上传文件组件支持多文件选择
6. 系统在用户上传后立即将图片存储到平台文件服务并生成可访问的 URL
7. 后台按顺序拼接生成大模型请求的 messages 数组

**URL 上传流程：**
1. 用户在文件上传对话窗口（对话流调试、agent 调试、agent-web 页、工作流 agent 开始节点）选择 URL 上传
2. 输入多个 url 地址
3. 系统校验文件大小、数量（最多 10 张）、格式
4. 不符合校验规则报错
5. 文件状态流转：传输中 → 传输完成（不展示）→ 解析中 → 解析完成（不展示），或失败状态
6. 如果配置了文件解析变量赋值，文件自动解析

## 6. 状态流转
**URL 文件状态流转：**

| 状态 | 说明 | 展示方式 |
|-----|------|---------|
| 传输中 | 文件正在上传 | 展示 |
| 传输完成 | 上传成功 | 不展示 |
| 传输失败 | 上传失败 | 展示 |
| 解析中 | 正在解析 | 展示 |
| 解析完成 | 解析成功 | 不展示 |
| 解析失败 | 解析失败 | 展示 |

**多图解析状态（Plan A 对话流/工作流）：**

| 状态 | 说明 | 展示方式 |
|-----|------|---------|
| 未解析 | 图片已上传但尚未解析 | 显示未解析状态 |
| 解析完成 | 所有文件解析成功 | 所有文件右侧展示 ✅ |

原文未说明解析失败时单个文件与整体的状态关系（如部分成功部分失败如何处理）。

## 7. 业务规则
| 规则类型 | 触发条件 | 判断逻辑 | 处理结果 |
|---------|---------|---------|---------|
| 校验规则 | URL 上传 | 校验文件大小、数量（最多 10 张）、格式 | 不符合校验规则报错 |
| 校验规则 | 本地上传 | 最多 10 张图片 | 超出限制报错 |
| 校验规则 | 选择模型 | 如果未开启多图解析模式，选择了一个不支持多图解析的模型后，开启多图解析将模型清除 | 清除已选模型 |
| 校验规则 | 选择模型 | 如果选择的支持多图解析模型后保留模型配置 | 保留模型配置 |
| 配置规则 | 赛博坦后台 | 新增模型配置项：多图合并解析（支持/不支持） | 已录入的模型默认关闭状态 |
| 配置规则 | 文件解析节点 | 开启多图解析后，选择图片，列表展示后台支持多图解析的模型 | 如果没有定义特定模型，默认使用兜底多图解析模型 |
| 交互规则 | 解析完成后再次上传 | 解析完成后再次上传文件或 url 后需要重新点击解析按钮才能点击提交按钮 | 重新解析后才能提交 |
| 交互规则 | 模型选择列表 | 大模型回复、大模型变量赋值下选择模型列表给出 icon 区分具有多模态的模型 | 展示 icon 标识 |
| 交互规则 | 模型选择（Plan B） | 选择不支持图片理解的模型时隐藏图像赋值区 | 隐藏功能区 |
| 交互规则 | 工作流（Plan A） | 如果勾选多图解析，新增解析按钮，上传完成后除图片外先进行解析 | 点击运行后将所有图片拼接进行统一解析 |
| 异常规则 | 工作流（Plan A） | 如果失败退出工作流并报错 | 保持现有逻辑 |

## 9. 数据与系统交互
**存储数据：**
- 用户上传的图片文件：存储至平台文件服务，生成可访问的 URL
- 模型配置：多图合并解析开关状态（支持/不支持），已录入模型默认关闭
- 文件解析节点配置：多图解析开关、选择的解析模型
- URL 文件状态：传输中、传输完成、传输失败、解析中、解析失败、解析完成

**系统交互：**
- 前端 → 文件服务：上传图片文件，获取可访问的 URL
- 后端 → OpenRouter/大模型 API：按 OpenRouter 规范组装请求，发送包含多张图片的 messages 数组

**API 请求格式（后台生成）：**
- 符合 OpenAI 多模态消息格式
- messages 数组中 content 为数组，包含 text 和多个 image_url 项
- 每张图片单独放在 content 数组项中
- 按顺序拼接生成多个 image_url 消息

**对接系统：**
- 平台文件服务：存储上传的图片文件
- OpenRouter/大模型 API：发送多模态请求
