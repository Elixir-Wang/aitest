# 需求理解

## 1. 需求背景
百工平台通过大模型变量赋值节点给会话变量动态赋值，用于构造大模型 Prompt。现有大模型赋值节点对于多图场景仅支持单个图片处理后串联结果，客户希望将多个图拼接后在一个 message 中统一作为大模型的输入，将图片作为大模型输入的一部分，而不是分多次调用模型。OpenRouter 兼容 OpenAI 多模态消息格式，在同一条 messages 中通过数组形式发送图片。当请求中包含多张图片时，需要将每张图片单独放在 content 数组项中。因此，需要在前端收集并存储用户上传的多张图片至文件系统并生成 url，并按顺序拼接生成多个 image_url 消息，后台依据 OpenRouter 规范组装请求。

## 2. 目标与价值
实现多图合并解析功能，支持将多张图片拼接后在一个 message 中统一作为大模型的输入，而不是分多次调用模型。支持用户在对话流/工作流中上传多张图片（本地上传和 URL 上传），系统按 OpenRouter/OpenAI 多模态消息格式组装请求，将图片作为大模型输入的一部分。

## 3. 用户角色与使用场景
| 用户角色 | 使用场景 | 用户目标 | 已知约束 |
|---------|---------|---------|---------|
| 百工平台普通用户 | 在对话流/工作流中使用大模型变量赋值节点 | 上传多张图片并一次性解析，将多图作为大模型输入 | 需要选择支持多模态的模型 |
| 百工平台管理员 | 在赛博坦后台配置模型能力 | 配置模型是否支持多图合并解析/图像理解能力 | 已录入的模型默认关闭状态 |
| 百工平台开发人员 | 根据 PRD 选择 Plan A 或 Plan B 进行开发 | 实现多图合并解析功能 | 需根据版本迁移、工作量等实际情况选择方案 |

## 4. 功能范围
**包含的功能**：
1. 赛博坦后台模型能力配置：新增模型配置项（多图合并解析：支持/不支持，或图像理解能力开关）
2. 大模型变量赋值节点新增图像输入模块（Plan B）
3. 文件解析节点和收集用户上传文件节点增加多图合并解析（Plan A）
4. 大模型回复、大模型变量赋值下选择模型列表给出 icon 区分具有多模态的模型
5. URL 上传功能：支持一次上传多个 url 地址，校验文件大小、数量（最多 10 张）、格式
6. 多图上传限制最多 10 张图片
7. 后台按顺序拼接生成大模型请求的 messages 数组（OpenAI 多模态格式）
8. 三种类型 agent & chat flow 的复制导入导出兼容
9. trace 日志

**不包含的功能**：
1. 文生图模型管理模块（下期评审）
2. 文生图节点（下期评审）

## 5. 业务流程
**Plan A 流程（修改文件解析节点和收集用户上传文件节点）**：

1. 用户在赛博坦后台配置模型是否支持多图合并解析
2. 用户在对话流/工作流中配置文件解析节点
3. 文件类型选择包含图片后，点击自定义解析方式加号后出现多图解析开关
4. 开启多图解析开关后，选择支持多图解析的模型
5. 运行对话流/工作流时，用户上传多张图片（本地上传或 URL 上传）
6. 上传完成后点击解析按钮一次性进行解析
7. 解析完成后所有文件右侧展示 ✅
8. 后台按顺序拼接生成大模型请求的 messages 数组
9. 将拼接后的请求发送给大模型

**Plan B 流程（修改大模型回复和大模型变量赋值节点）**：

1. 在赛博坦后台新增/编辑模型时开启图像理解能力开关
2. 模型开启图像理解能力后，在大模型模型选择列表展示图片理解标识
3. 用户在大模型变量赋值节点中选择支持图像理解的模型
4. 展示图像赋值区与多图拼接按钮
5. 用户在视觉理解赋值输入框中多选赋值变量
6. 后端收集用户上传文件，存储到平台文件服务并生成可访问的 URL
7. 后台按顺序拼接生成大模型请求的 messages 数组

**URL 上传流程**：
1. 用户在文件上传对话窗口选择 URL 上传
2. 输入多个 url 地址
3. 系统校验文件大小、数量（最多 10 张）、格式
4. 不符合校验规则报错
5. url 文件状态流转：传输中 → 传输完成 → 解析中 → 解析完成（或传输失败/解析失败）
6. 如果配置了文件解析变量赋值，文件自动解析

## 6. 状态流转
**URL 文件状态流转**：

| 状态 | 触发条件 | 下一状态 |
|-----|---------|---------|
| 传输中 | 用户提交 URL | 传输完成 / 传输失败 |
| 传输完成 | 文件传输成功 | 解析中（自动） |
| 传输失败 | 文件传输失败 | 传输失败（展示失败状态） |
| 解析中 | 传输完成后自动触发或用户点击解析 | 解析完成 / 解析失败 |
| 解析完成 | 解析成功 | 不展示状态（完成态） |
| 解析失败 | 解析失败 | 解析失败（展示失败状态） |

**多图解析状态（Plan A）**：
- 未解析状态：多图在未解析状态下显示未解析状态
- 解析完成：解析完成后所有文件右侧展示 ✅
- 解析完成后再次上传文件或 url 后需要重新点击解析按钮才能点击提交按钮

## 7. 业务规则
| 规则类型 | 触发条件 | 判断逻辑 | 处理结果 |
|---------|---------|---------|---------|
| 校验规则 | URL 上传 | 校验文件大小、数量、格式 | 不符合校验规则报错 |
| 限制规则 | 多图上传 | 最多上传 10 张图片 | 超出限制提示 |
| 校验规则 | 选择模型（Plan A） | 未开启多图解析模式，选择了一个不支持多图解析的模型后，开启多图解析将模型清除 | 清除已选模型 |
| 校验规则 | 选择模型（Plan A） | 如果选择的支持多图解析模型后保留模型配置 | 保留模型配置 |
| 校验规则 | 模型选择列表 | 判断模型是否支持图像解析 | 展示图片理解标识 icon |
| 校验规则 | 图像赋值区显示（Plan B） | 选择不支持图片理解的模型时隐藏该功能区 | 隐藏图像赋值区 |
| 校验规则 | 工作流运行（Plan B） | 工作流运行时超上下文报错 | 给出报错原因 |
| 校验规则 | 解析后再次上传（Plan A） | 解析完成后再次上传文件或 url | 需要重新点击解析按钮才能点击提交按钮 |
| 默认规则 | 模型配置 | 已录入的模型默认关闭多图合并解析/图像理解能力 | 默认关闭 |
| 兜底规则 | 模型选择（Plan A） | 如果没有定义图片特定模型进行多图解析 | 默认使用兜底多图解析模型进行解析 |
| 异常规则 | 工作流运行（Plan A） | 多图解析失败 | 退出工作流并报错，保持现有逻辑 |

## 8. 页面与交互
**赛博坦后台 - 模型配置**：
- Plan A：在赛博坦测试版新增必填模型配置项：多图合并解析：支持/不支持
- Plan B：在新增模型页面与模型编辑页面新增图像理解能力开关按钮

**对话流 - 文件解析节点（Plan A）**：
- 文件类型选择包含图片后，点击自定义解析方式加号后出现多图解析开关
- 多图合并解析按钮位置在自定义解析方式点击加号后下方第一行
- 开启后，选择图片，列表展示后台支持多图解析的列表
- 用户输入新增多图合并子集上传模块，支持本地上传和 url 上传
- 上传完成后点击解析一次性进行解析
- 多图在未解析状态下显示未解析状态，解析完成后所有文件右侧展示 ✅

**工作流 - 开始节点 & 文件解析节点（Plan A）**：
- 如果勾选多图解析，新增解析按钮
- 上传完成后除图片外先进行解析
- 点击运行后将所有图片拼接进行统一解析

**大模型变量赋值节点（Plan B）**：
- 模型选择列表展示图片理解标识 icon（函数调用能力展示项隐藏，模型能力默认以 icon 形式展示在列表）
- 选择支持图像理解的模型后，展示图像赋值区与多图拼接按钮
- 选择不支持图片理解的模型时隐藏该功能区
- 用户在视觉理解赋值输入框中可多选赋值变量

**文件上传对话窗口**：
- 范围：对话流调试、agent 调试、agent-web 页、工作流 agent 开始节点
- 本地上传多图解析限制上传最多 10 张图片
- 添加 URL 支持一次上传多个 url 地址
- url 文件状态展示：传输中、传输完成（不展示）、传输失败、解析中、解析失败、解析完成（不展示）

## 9. 数据与系统交互
**前端数据收集**：
- 收集用户上传的多张图片（本地上传和 URL 上传）
- 存储至文件系统并生成可访问的 URL

**后端数据处理**：
- 收集用户上传文件组件支持多文件选择
- 用户上传后立即将图片存储到平台文件服务并生成可访问的 URL
- 后台按顺序拼接生成大模型请求的 messages 数组

**API 请求格式（OpenAI 多模态格式）**：
```json
{
  "model": "google/gemini-2.5-flash",
  "messages": [
    {
      "role": "user",
      "content": [
        {
          "type": "text",
          "text": "请对比这几张图，指出主要差异。"
        },
        {
          "type": "image_url",
          "image_url": {
            "url": "https://example.com/image1.jpg"
          }
        },
        {
          "type": "image_url",
          "image_url": {
            "url": "https://example.com/image2.jpg"
          }
        }
      ]
    }
  ]
}
```

**系统交互**：
- 对接 OpenRouter（兼容 OpenAI 多模态消息格式）
- 对接平台文件服务（存储图片并生成 URL）

**数据兼容性**：
- 三种类型 agent & chat flow 的复制导入导出需兼容
- trace 日志
