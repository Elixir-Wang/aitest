# 待澄清问题

| 优先级 | 模块/对象 | 澄清问题 | 选项 A | 选项 B | 影响 |
|-------|----------|---------|--------|--------|------|
| P0 | 多图合并解析 - 方案选择 | Plan A 和 Plan B 最终选择哪个方案实施？还是两个方案都需要实现？ | 选择 Plan A，修改收集用户上传文件节点和文件解析节点 | 选择 Plan B，修改大模型回复和大模型变量赋值节点 | 方案选择决定了需要修改的节点范围和实现路径，是开发的基础前提，不明确则无法开始编码 |
| P0 | 多图合并解析 - 兜底模型 | 当未定义特定多图解析模型时，使用的'兜底多图解析模型'具体是哪个模型？如何配置？ | 系统内置固定兜底模型（如 Qwen3.6-plus），无需用户配置 | 在赛博坦后台新增一个'默认多图解析模型'配置项，由管理员指定 | 兜底模型是核心业务流程的关键环节，不明确则无法实现多图解析的默认行为 |
| P0 | 多图合并解析 - 文件解析节点 | Plan A 中文件解析节点开启多图解析后，解析按钮的触发逻辑是什么？是用户手动点击解析按钮，还是上传完成后自动触发解析？ | 用户手动点击解析按钮后才开始解析，解析完成后才能提交 | 上传完成后自动触发解析，解析完成后展示结果 | 影响用户交互流程和解析触发时机，不明确则无法实现正确的交互逻辑 |
| P1 | 多图合并解析 - 文件上传 | URL 上传时，支持哪些图片格式？本地上传和 URL 上传的格式校验规则是否一致？ | 支持常见图片格式（jpg、jpeg、png、gif、webp、bmp），本地上传和 URL 上传校验规则一致 | 仅支持 jpg、jpeg、png 格式，本地上传和 URL 上传校验规则一致 | 影响文件上传的校验逻辑和用户体验，不明确则无法实现格式校验 |
| P1 | 多图合并解析 - 文件上传 | 本地上传和 URL 上传的单个文件大小限制是多少？ | 单个文件不超过 20MB | 单个文件不超过 10MB | 影响文件上传的校验逻辑，不明确则无法实现大小校验 |
| P1 | 多图合并解析 - 工作流 | 工作流中多图解析失败时，'退出工作流并报错'的具体行为是什么？是否保留已解析成功的其他节点结果？ | 整个工作流终止，所有节点结果回滚，前端展示错误信息 | 工作流终止，但已完成的节点结果保留，仅标记多图解析节点为失败状态 | 影响工作流的错误处理机制和用户体验，不明确则无法实现正确的异常处理 |
| P1 | 多图合并解析 - 模型配置 | 赛博坦后台配置模型的多图合并解析能力时，'已录入的模型默认关闭状态'是否意味着存量模型全部默认不支持多图解析？新增模型时默认值是什么？ | 存量模型默认关闭（不支持），新增模型时默认也是关闭状态，需手动开启 | 存量模型默认关闭，新增模型时默认开启 | 影响模型配置的默认行为和存量模型的兼容性 |
| P2 | 多图合并解析 - 交互 | 解析完成后再次上传文件或 url 后需要重新点击解析按钮，此时之前已解析完成的图片状态如何处理？是保留解析结果还是清空？ | 清空所有图片的解析状态，全部变为未解析状态，需要重新解析所有图片 | 保留已有解析结果，仅新上传的图片显示未解析状态，用户可选择性解析 | 影响用户交互体验和状态管理逻辑 |
| P2 | 多图合并解析 - trace日志 | trace 日志需要记录哪些多图解析相关的信息？ | 记录上传的图片数量、图片 URL 列表、解析结果、解析耗时 | 记录上传的图片数量、解析结果（成功/失败），不记录具体图片 URL | 影响日志系统的实现范围和调试能力 |
