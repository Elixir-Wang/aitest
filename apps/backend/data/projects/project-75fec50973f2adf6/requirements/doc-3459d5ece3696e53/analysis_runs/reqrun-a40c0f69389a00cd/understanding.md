# 需求理解

## 1. 需求背景
百工平台通过大模型变量赋值节点给会话变量动态赋值，用于构造大模型 Prompt。现有大模型赋值节点对于多图场景仅支持单个图片处理后串联结果（分多次调用模型），客户希望将多个图拼接后在一个 message 中统一作为大模型的输入，将图片作为大模型输入的一部分，而不是分多次调用模型。OpenRouter 兼容 OpenAI 多模态消息格式，在同一条 messages 中通过数组形式发送图片。当请求中包含多张图片时，需要将每张图片单独放在 content 数组项中。因此，需要在前端收集并存储用户上传的多张图片至文件系统并生成 url，并按顺序拼接生成多个 image_url 消息，后台依据 OpenRouter 规范组装请求。

## 2. 目标与价值
支持多图合并解析功能，将多张图片拼接后在一个 message 中统一作为大模型的输入，而不是分多次调用模型。具体目标包括：1）在赛博坦后台新增模型配置项（多图合并解析/图像理解能力开关）；2）在对话流/工作流节点中支持多图上传、解析和拼接；3）支持 URL 上传图片；4）后台按 OpenRouter 规范组装多图请求。

## 3. 用户角色与使用场景
| 用户角色 | 使用场景 | 用户目标 | 已知约束 |
|---------|---------|---------|---------|
| 百工平台客户（最终用户） | 在对话流/工作流中上传多张图片进行统一解析 | 将多张图片一次性作为大模型输入，获得综合分析结果 | 最多上传10张图片 |
| 平台管理员/配置人员 | 在赛博坦后台配置模型的多图合并解析能力 | 开启/关闭模型的多图解析能力 | 已录入的模型默认关闭 |
| 工作流/对话流设计者 | 在节点配置中选择模型、开启多图解析、配置解析方式 | 设计支持多图解析的工作流/对话流 | 需选择支持多图解析的模型 |

## 4. 功能范围
**包含的功能**：
1. 赛博坦后台：模型能力配置，新增多图合并解析/图像理解能力开关（必填配置项，已录入模型默认关闭）
2. 对话流节点改造（Plan A）：收集用户上传文件节点 & 文件解析节点，增加多图合并解析
3. 工作流节点改造（Plan A）：开始节点 & 文件解析节点，增加多图合并解析
4. 对话流节点改造（Plan B）：大模型回复 & 大模型变量赋值节点，新增图像输入模块
5. 工作流节点改造（Plan B）：大模型变量赋值节点，新增图像输入模块
6. 模型列表展示：以 icon 形式区分具有多模态能力的模型
7. URL 上传功能：支持通过 URL 上传图片，校验文件大小、数量（最多10张）、格式
8. 后台按 OpenRouter 规范组装多图请求 messages 数组
9. 三种类型 agent & chat flow 的复制导入导出兼容
10. trace 日志

**不包含的功能**（原文明确说明下期评审）：
1. 文生图模型管理模块
2. 文生图节点

## 5. 业务流程
**Plan A 流程（对话流）**：
1. 用户在赛博坦后台配置模型的多图合并解析开关（支持/不支持）
2. 用户在对话流中配置文件解析节点，文件类型选择包含图片
3. 用户点击自定义解析方式加号，出现多图解析开关
4. 用户开启多图解析开关，选择支持多图解析的模型（默认使用兜底模型）
5. 运行对话流时，用户上传多张图片（本地上传或URL上传）
6. 上传完成后点击解析按钮，一次性进行解析
7. 解析完成后所有文件右侧展示 ✅
8. 解析完成后再次上传文件或URL后需要重新点击解析才能提交

**Plan A 流程（工作流）**：
1. 用户在开始节点勾选多图解析
2. 用户上传图片
3. 点击解析按钮，上传完成后除图片外先进行解析
4. 点击运行后将所有图片拼接进行统一解析
5. 如果失败退出工作流并报错

**Plan B 流程**：
1. 在赛博坦后台新增/编辑模型时开启图像理解能力开关
2. 节点渲染时读取当前选择的大模型配置，判断是否支持图像解析
3. 选择支持图像理解的模型后，展示图像赋值区与多图拼接按钮
4. 用户在视觉理解赋值输入框中多选赋值变量
5. 收集用户上传文件组件支持多文件选择
6. 用户上传后系统立即将图片存储到平台文件服务并生成可访问的 URL
7. 后台按顺序拼接生成大模型请求的 message

## 6. 状态流转
**文件上传状态（原文明确说明）**：
| 状态 | 说明 |
|-----|------|
| 传输中 | 文件正在上传 |
| 传输完成 | 上传成功（不展示） |
| 传输失败 | 上传失败 |
| 解析中 | 正在解析 |
| 解析失败 | 解析失败 |
| 解析完成 | 解析成功（不展示） |

**多图解析状态（原文明确说明）**：
| 状态 | 说明 |
|-----|------|
| 未解析 | 多图在未解析状态下显示未解析状态 |
| 已解析 | 解析完成后所有文件右侧展示 ✅ |

**工作流运行状态（原文明确说明）**：
- 如果多图解析失败，退出工作流并报错

## 7. 业务规则
| 规则类型 | 触发条件 | 判断逻辑 | 处理结果 |
|---------|---------|---------|---------|
| 校验规则 | 上传图片 | 文件大小校验 | 不符合校验规则报错 |
| 校验规则 | 上传图片 | 数量最多10张 | 超出报错 |
| 校验规则 | 上传图片 | 格式校验 | 不符合校验规则报错 |
| 校验规则 | URL上传 | 校验文件大小、数量最多10张、格式 | 不符合校验规则报错 |
| 配置规则 | 赛博坦后台配置模型 | 多图合并解析：支持/不支持（必填） | 已录入模型默认关闭 |
| 配置规则 | 选择模型 | 如果未开启多图解析模式，选择了一个不支持多图解析的模型后，开启多图解析将模型清除 | 清除模型选择 |
| 配置规则 | 选择模型 | 如果选择的支持多图解析模型后保留模型配置 | 保留模型配置 |
| 配置规则 | 选择不支持图片理解的模型 | 隐藏图像赋值区 | 不展示该功能区 |
| 解析规则 | 多图解析 | 如果没有定义图片特定模型进行多图解析，默认使用兜底多图解析模型 | 使用兜底模型 |
| 解析规则 | 解析完成后再次上传文件或URL | 需要重新点击解析按钮才能点击提交按钮 | 重新解析 |
| 运行规则 | 工作流多图解析 | 如果失败退出工作流并报错 | 保持现有逻辑 |
| 兼容规则 | 复制导入导出 | 三种类型 agent & chat flow 需兼容 | 兼容处理 |

## 8. 页面与交互
**赛博坦后台 - 新增/编辑模型页面**：
- 新增必填配置项：多图合并解析（支持/不支持），已录入模型默认关闭
- Plan B：新增图像理解能力开关按钮

**对话流 - 文件解析节点（Plan A）**：
- 文件类型选择包含图片后，点击自定义解析方式加号后出现多图解析开关
- 多图合并解析按钮位置在自定义解析方式点击加号后下方第一行
- 开启后，选择图片，列表展示后台支持多图解析的模型列表
- 运行对话流时，用户输入新增多图合并子集上传模块，支持本地上传和URL上传
- 多图在未解析状态下显示未解析状态，解析完成后所有文件右侧展示 ✅

**工作流 - 开始节点（Plan A）**：
- 新增勾选多图解析选项
- 新增解析按钮

**大模型变量赋值节点（Plan B）**：
- 模型列表以 icon 形式区分具有多模态能力的模型
- 选择支持图像理解的模型后，展示图像赋值区与多图拼接按钮
- 选择不支持图片理解的模型时隐藏该功能区
- 函数调用能力展示项隐藏，模型能力默认以 icon 形式展示在列表

**文件上传对话窗口**：
- 范围：对话流调试、agent 调试、agent-web 页、工作流 agent 开始节点
- 本地上传多图解析限制上传最多10张图片
- 添加URL支持一次上传多个url地址
- url文件状态展示：传输中、传输完成（不展示）、传输失败、解析中、解析失败、解析完成（不展示）

## 9. 数据与系统交互
**数据存储**：
- 前端收集并存储用户上传的多张图片至文件系统并生成url
- Plan B：用户上传后系统立即将图片存储到平台文件服务并生成可访问的URL

**系统交互**：
- 后台依据 OpenRouter 规范组装请求，生成 messages 数组
- 请求格式示例：
```json
{
  "model": "google/gemini-2.5-flash",
  "messages": [
    {
      "role": "user",
      "content": [
        {"type": "text", "text": "请对比这几张图，指出主要差异。"},
        {"type": "image_url", "image_url": {"url": "https://example.com/image1.jpg"}},
        {"type": "image_url", "image_url": {"url": "https://example.com/image2.jpg"}}
      ]
    }
  ]
}
```

**对接系统**：
- OpenRouter（兼容 OpenAI 多模态消息格式）
- 平台文件服务（存储图片并生成URL）

**API 能力**：
- 后台按顺序拼接生成大模型请求的 message
- 收集用户上传文件组件支持多文件选择

**变更影响**：
- 三种类型 agent & chat flow 的复制导入导出需兼容
- trace 日志
