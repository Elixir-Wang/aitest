# 待澄清问题

| 优先级 | 模块/对象 | 澄清问题 | 选项 A | 选项 B | 测试影响 |
|-------|----------|---------|--------|--------|------|
| P0 | 模型数据 | 模型是否支持思考模式的判断依据是什么？ | 后端接口返回模型列表时，每个模型携带一个字段（如 support_think_mode: true/false），前端根据该字段展示标签和开关 | 前端维护一个支持思考模式的模型白名单列表，根据模型名称或ID匹配判断 | 无法设计模型标签展示和开关显示的测试用例，无法断言哪些模型应展示标签、哪些不应展示，也无法验证新增模型时的行为 |
| P0 | 思考模式开关 | 思考模式开关的默认值是什么？新建Agent时默认开启还是关闭？ | 默认关闭，用户需要手动开启思考模式 | 默认开启，用户可以选择关闭 | 无法设计新建Agent场景下思考模式开关状态的测试断言，无法判断默认行为是否符合预期 |
| P0 | 思考模式开关 | 用户切换模型时，思考模式开关状态如何处理？ | 切换模型后，开关状态重置为默认值（默认开启或关闭） | 切换模型后，保留之前的开关状态，仅当新模型不支持思考模式时隐藏开关 | 无法设计模型切换场景下开关状态的测试用例，无法断言切换后开关的显示和状态是否正确 |
| P1 | 思考模式开关 | 思考模式开关状态的保存时机是什么？ | 开关切换后立即保存（自动保存），无需额外确认操作 | 开关切换后仅更新本地状态，随Agent整体配置一起保存（需点击保存/确认按钮） | 无法设计开关状态持久化的测试用例，无法断言开关状态在页面刷新、关闭重开后的表现 |
| P1 | 思考模式开关 | 同一个Agent下不同节点（如Multi-Agent的不同Agent节点）的思考模式开关是独立配置还是共享同一个开关？ | 每个节点的对话模型配置弹窗独立控制自己的思考模式开关，互不影响 | 同一个Agent下所有节点共享一个思考模式开关 | 无法设计多节点场景下开关状态的测试用例，无法断言各节点开关的独立性和相互影响 |
| P1 | 思考模式开关 | 思考模式开关是否支持在运行时（对话进行中）动态切换？ | 开关仅在Agent配置阶段生效，对话进行中不可切换 | 对话进行中也可以切换思考模式开关，切换后后续对话按新配置执行 | 无法设计运行时切换场景的测试用例，无法断言运行时切换后的对话表现 |
| P2 | 思考模式开关 | 思考模式开启时，对话框内思考过程的展示形式是什么？是否支持折叠/展开？ | 思考过程直接展示在对话框中，不可折叠，用户可看到完整思考链 | 思考过程以可折叠区域展示，默认展开或默认折叠，用户可手动折叠/展开 | 无法设计思考过程展示形式的UI测试用例，无法断言展示效果是否符合预期 |
