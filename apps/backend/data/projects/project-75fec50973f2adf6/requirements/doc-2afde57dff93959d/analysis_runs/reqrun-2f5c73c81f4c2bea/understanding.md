# 需求理解

## 1. 需求背景

当前在编辑Agent选用LLM模型时，无法直观查看目标模型是否支持开启思考模式；同时不支持Agent配置时自定义思考模式是否开启。

## 2. 目标与价值

1. 在模型选择处的模型名称后展示是否支持思考模式状态标签，做到状态可视化。
2. 在Agent对话模型配置弹窗内增加思考模式开关（仅支持思考模式的模型显示），支持用户手动开启/关闭思考模式。

## 3. 用户角色与使用场景

| 用户角色 | 使用场景 | 用户目标 | 已知约束 |
|---------|---------|---------|---------|
| Agent配置者/编辑者 | 在编辑Agent时选用LLM模型 | 直观查看目标模型是否支持思考模式 | 仅支持思考模式的模型才展示标签和开关 |
| Agent配置者/编辑者 | 在Agent对话模型配置弹窗中配置模型 | 自定义开启或关闭思考模式 | 仅支持思考模式的模型才显示开关 |

## 4. 功能范围

**包含的功能**：
1. 模型选择区域：在模型名称后面追加【Think】标签，仅当模型支持思考模式时展示。
2. 对话模型配置弹窗：为支持思考模式的LLM模型增加思考模式开启/关闭开关。
3. 思考模式开关影响Agent对话框内的展示效果（开启时展示思考过程，未开启时不展示）。

**涉及配置项位置**：
- 自主规划Agent - 对话模型配置弹窗
- Multi-Agent - Agent节点 - 对话模型配置弹窗
- 写作Agent - 新建Agent模板 - 正文生成模型配置弹窗
- 对话流 - 大模型回复节点 - 大模型配置
- 对话流 - 大模型变量赋值节点 - 大模型配置
- 任务流Agent - 大模型变量赋值节点 - 大模型配置

**不包含的功能**：
- 原文未说明不支持思考模式的模型是否展示任何标签或开关。
- 原文未说明思考模式开关的默认值（默认开启还是关闭）。
- 原文未说明模型支持思考模式的判断依据（是后端接口返回的字段还是前端硬编码列表）。

## 5. 业务流程

**场景一：模型选择时查看思考模式支持状态**

1. 前置条件：用户进入Agent编辑页面，打开模型选择区域。
2. 触发动作：系统加载模型列表。
3. 系统处理：系统判断每个模型是否支持思考模式。
4. 分支：
   - 模型支持思考模式 → 模型名称后展示【Think】标签。
   - 模型不支持思考模式 → 模型名称后不展示标签。
5. 可观察结果：用户看到模型名称后的【Think】标签。

**场景二：在对话模型配置弹窗中配置思考模式**

1. 前置条件：用户已选择一个支持思考模式的模型，打开对话模型配置弹窗。
2. 触发动作：弹窗加载。
3. 系统处理：系统判断当前选中的模型是否支持思考模式。
4. 分支：
   - 模型支持思考模式 → 弹窗中显示思考模式开关。
   - 模型不支持思考模式 → 弹窗中不显示思考模式开关。
5. 用户操作：用户手动开启或关闭思考模式开关。
6. 系统处理：保存用户的思考模式配置。
7. 可观察结果：开关状态被保存，后续对话按配置执行。

**场景三：Agent对话框内思考模式效果**

1. 前置条件：用户已配置思考模式开启。
2. 触发动作：用户发起对话。
3. 系统处理：模型按开启思考模式的方式响应。
4. 可观察结果：对话框内展示思考过程（如截图所示）。
5. 分支（未开启）：对话框内不展示思考过程。

## 8. 页面与交互

**模型选择区域**：
- 页面元素：模型名称、【Think】标签（仅支持思考模式的模型展示）

**对话模型配置弹窗**：

- 反馈：开关状态切换后视觉反馈（开启/关闭状态变化）

**Agent对话框**：
- 开启思考模式：展示思考过程（如截图所示）
- 未开启思考模式：不展示思考过程（如截图所示）
