# 待澄清问题

| 优先级 | 模块/对象 | 澄清问题 | 选项 A | 选项 B | 影响 |
|-------|----------|---------|--------|--------|------|
| P0 | 网关调用流程 | 当上游 LLM 接口调用超时或失败时，网关的默认重试策略是什么？ | 默认重试 3 次，使用指数退避策略，最终失败返回 5xx 错误给调用方 | 不自动重试，直接返回错误给调用方，由调用方决定重试 | 影响网关的可用性和上游 LLM 故障时的用户体验，超时和重试策略直接影响系统稳定性 |
| P0 | 模型配置管理 | 模型配置（llm_model_config）修改后是实时生效还是需要重启服务？ | 实时生效，网关通过定时轮询或事件监听机制感知配置变更（如每 30 秒刷新缓存） | 需要重启服务才能生效，配置变更后通过发布流程触发服务重启 | 影响运维流程和配置变更的响应速度，实时生效可能引入数据一致性问题 |
| P0 | API Key 安全 | api_keys 和 source_model_api_key 表中的 API Key 字段在数据库中如何存储？ | 明文存储，依靠数据库访问权限保护（与当前表设计一致） | 使用 AES 等加密算法加密存储，应用层解密使用 | 涉及敏感凭证存储安全，明文存储存在泄露风险 |
| P0 | API Key 校验 | 业务方调用网关时，如何校验 source_api_key 的合法性？校验失败如何处理？ | 网关接收请求后查询 source_model_api_key 表，校验通过则继续，否则返回 401 Unauthorized | 通过独立的鉴权服务校验，网关调用鉴权服务验证 source_api_key 有效性 | 影响网关的安全模型和性能，每次调用都需要鉴权时需考虑性能开销 |
| P0 | 接口协议 | interface_protocol 字段支持哪些协议类型？protocol_options JSON 字段存储什么内容？ | 支持 openai、anthropic、azure 等固定协议枚举值，protocol_options 存储请求/响应转换规则 | 使用插件化设计，支持自定义协议扩展，protocol_options 存储插件配置参数 | 影响网关对不同 LLM 厂商的适配能力和扩展性 |
| P0 | FunctionCall | FunctionCall 调用时，网关如何处理工具调用的透传和结果回传？ | 网关完全透传 FunctionCall 请求和响应，不做任何修改，由调用方和上游 LLM 直接交互 | 网关对 FunctionCall 进行协议转换，确保不同 LLM 厂商的 FunctionCall 格式统一 | 影响 FunctionCall 的兼容性和多厂商支持能力 |
| P1 | 代理配置 | proxy_config 中的代理是 HTTP 代理还是 SOCKS 代理？是否需要支持认证？ | 仅支持 HTTP 代理，无需认证（与当前表结构一致，proxy_url 包含完整 URL） | 支持 HTTP/HTTPS/SOCKS 代理，可选用户名密码认证 | 影响代理的灵活性，特别是访问内网或私有 LLM 服务的场景 |
| P1 | 流式响应 | 网关是否需要支持 LLM 的流式响应（SSE/Streaming）？ | 支持流式响应，通过 SSE 或 WebSocket 将上游 LLM 的流式输出转发给调用方 | 不支持流式响应，统一转换为非流式响应返回 | 影响对话场景的用户体验（首字延迟）和网关的实现复杂度 |
| P1 | 配置管理 | 模型配置管理是否提供 Web UI？还是仅提供 OpenAPI 接口供运维使用？ | 提供 Web UI 管理界面，管理员可通过页面进行增删改查 | 仅提供 OpenAPI 接口，通过命令行或运维脚本进行管理 | 影响交付范围和前端开发工作量 |
| P1 | 权限控制 | 模型配置管理的操作权限如何控制？是否需要区分查看、编辑、删除权限？ | 所有登录用户均可操作，通过操作日志记录变更（与当前表结构中无权限字段一致） | 仅管理员可操作，需要引入角色管理和权限控制模块 | 影响系统的安全性和误操作风险 |
| P1 | 异常处理 | 调用方传入的 llm_code 不存在或已删除时，网关返回什么错误？ | 返回 HTTP 400 Bad Request，提示"模型编码不存在或已下线" | 返回 HTTP 404 Not Found，提示"模型不存在" | 影响调用方的错误处理逻辑和用户体验 |
| P1 | 日志监控 | 网关是否记录调用日志？日志包含哪些字段？保留多久？ | 记录完整的请求/响应日志（脱敏后），保留 30 天用于问题排查 | 仅记录请求摘要（调用方、模型、耗时、状态码），保留 7 天 | 影响问题排查能力和存储成本，为后续 Token 计量提供数据基础 |
| P1 | SDK 切换 | UseLLMGatewaySDK 配置变更后，是否需要重启业务服务才能生效？ | 需要重启业务服务才能生效（与 params_config 的一般机制一致） | 支持热加载，业务服务定时拉取配置自动更新 | 影响切流效率和运维复杂度 |
| P2 | 数据库字符集 | source_model_api_key 表使用 utf8mb4_0900_ai_ci 字符集，其他表使用 utf8mb4_unicode_ci，是否有意为之？ | 保持现状，是历史遗留问题（暂不统一） | 统一为 utf8mb4_unicode_ci 字符集 | 影响数据排序、比较规则的统一性 |
| P2 | 字段约束 | llm_code 字段定义为 char(6)，编码规则是什么？是否支持扩展？ | 使用 6 位数字编码（如 000001-999999），按创建顺序递增 | 使用 6 位字母数字混合编码（如 AZ0001），支持自定义含义 | 影响编码的语义化和可扩展性 |
| P2 | 测试环境 | 测试数据库实例（10.100.123.143:3306）是否包含生产数据？测试账号密码硬编码是否安全？ | 测试环境独立，无生产数据，硬编码是测试环境惯例（与文档保持一致） | 测试账号密码应通过环境变量或配置中心注入，避免文档泄露 | 涉及测试环境安全和敏感信息保护 |
