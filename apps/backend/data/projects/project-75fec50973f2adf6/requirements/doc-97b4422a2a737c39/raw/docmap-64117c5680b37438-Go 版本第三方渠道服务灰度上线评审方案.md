# Go 版本第三方渠道服务灰度上线评审方案

## 1. 背景

第三方渠道服务当前已有 Python 版本，包括 gateway 和 worker。现已使用 Go 重构，需要将 Go 版本逐步上线，并保证上线过程中的流量迁移平稳、异常时可快速回退。

当前存在一个关键约束：

*   Go gateway 和 Python gateway 对第三方 webhook 的处理方式不同。
    
*   Go gateway 和 Python gateway 写入 RabbitMQ 的消息结构不同。
    
*   因此 Go worker 不能直接消费 Python gateway 写入的队列消息，Python worker 也不能直接消费 Go gateway 写入的队列消息。
    

基于该约束，本次上线不采用 worker 层混合消费，也不采用同一队列竞争消费，而采用 gateway 与 worker 成对灰度的方式。

---

## 2. 上线目标

本次上线目标：

1.  支持 Go gateway + Go worker 独立承接第三方渠道流量。
    
2.  保证 Python 链路和 Go 链路互相隔离，避免队列消息格式混用。
    
3.  根据第三方平台 webhook 配置能力选择不同灰度方式。
    
4.  支持异常时快速切回 Python 链路。
    
5.  保证迁移期间消息不丢失、不重复回复、可观测、可排查。
    

---

## 3. 核心原则

### 3.1 链路成对迁移

Python 链路：

```text
Python gateway -> Python queue -> Python worker

```

Go 链路：

```text
Go gateway -> Go queue -> Go worker

```

迁移时按完整链路切换，不做跨语言混用。

### 3.2 队列完全隔离

禁止以下操作：

```text
Python gateway -> Go worker
Go gateway -> Python worker
Python worker 和 Go worker 抢同一个队列
Go 队列消息直接搬到 Python 队列
Python 队列消息直接搬到 Go 队列

```

原因是两套 gateway 写入 MQ 的数据结构不一致，混用会导致字段缺失、解析失败、重复回复或回退失败。

### 3.3 回退优先切入口

异常回退时，优先将新流量切回 Python gateway，而不是搬运 Go 队列中的消息。

推荐回退动作：

```text
1. 第三方 webhook 切回 Python gateway
2. Go gateway 不再接收新流量
3. Go worker 继续处理 Go queue 存量消息
4. 如 Go worker 不可用，则暂停 Go worker，保留 Go queue / Go DLQ，人工评估重放方式

```
---

## 4. 平台分组策略

第三方平台根据 webhook 配置能力分为两类。

### 4.1 A 类平台：支持按机器人配置 webhook

A 类平台可以按机器人维度灰度。（钉钉、lark、facebook、instagram、telegram、email、zendesk、whatsapp个人）

示例链路：

```text
机器人 A -> Python gateway -> Python queue -> Python worker
机器人 B -> Go gateway     -> Go queue     -> Go worker

```

适合迁移顺序：

```text
测试机器人
  -> 内部机器人
  -> 低风险客户机器人
  -> 高流量客户机器人
  -> A 类平台全量

```

A 类平台的回退粒度是单机器人。

### 4.2 B 类平台：不支持按机器人配置 webhook

B 类平台不能按机器人灰度，采用渠道级整体切换。（企微、whatsapp企业）

切换前：

```text
渠道 X -> Python gateway -> Python queue -> Python worker

```

切换后：

```text
渠道 X -> Go gateway -> Go queue -> Go worker

```

B 类平台的回退粒度是整渠道。

由于 B 类平台不能小流量灰度，切换前必须加强测试。

---

## 5. 总体架构

```text
                 +--------------------+
第三方平台 webhook | 按平台能力配置入口 |
                 +--------------------+
                       |          |
                       v          v
                Python gateway   Go gateway
                       |          |
                       v          v
                Python queue     Go queue
                       |          |
                       v          v
                Python worker    Go worker

```

队列命名建议：

```text
cyber_telegram        # Python 老链路
cyber_telegram_go     # Go 新链路

cyber_lark            # Python 老链路
cyber_lark_go         # Go 新链路

cyber_zendesk         # Python 老链路
cyber_zendesk_go      # Go 新链路

```

原则：

*   原 Python 队列保持不变。
    
*   Go 链路使用独立 Go 队列。
    
*   Go 队列配置独立 retry queue 和 DLQ。
    
*   Go worker 只消费 Go 队列。
    
*   Python worker 只消费 Python 队列。
    

---

## 6. 上线前准备

### 6.1 配置准备

Go worker 需要按平台配置独立 Go 队列。

示例：

```bash
CHANNEL_GATEWAY_ENABLED_PLATFORMS=telegram
CHANNEL_GATEWAY_TELEGRAM_QUEUE=cyber_telegram_go

```

Python 链路继续使用原队列，例如：

```bash
MQ_QUEUE_NAME_TELEGRAM=cyber_telegram

```

如果 Go 链路同时迁移多个渠道，建议每个渠道单独配置队列，不共用 Go 队列。

### 6.2 路由确认

上线前必须确认：

```text


[ ] Go gateway 只写 Go 队列




[ ] Python gateway 只写 Python 队列




[ ] Go worker 只消费 Go 队列




[ ] Python worker 只消费 Python 队列




[ ] Go queue 和 Python queue 没有绑定到同一个 consumer group




[ ] Go DLQ 和 Python DLQ 分开



```
---

## 7. 回退方案

## 7.1 A 类平台回退

A 类平台支持机器人级回退。

操作：

```text
1. 将异常机器人的 webhook 改回 Python gateway URL
2. Go gateway 不再接收该机器人新流量
3. Go worker 继续处理 Go queue 中该机器人已入队消息
4. 观察 Go queue ready / unacked 清零

```

如果 Go worker 本身异常：

```text
1. webhook 立即切回 Python gateway
2. 暂停 Go worker
3. 保留 Go queue / Go DLQ
4. 评估修复后重放或人工补偿

```

## 7.2 B 类平台回退

B 类平台采用渠道级回退。

操作：

```text
1. 将该渠道 webhook 从 Go gateway URL 改回 Python gateway URL
2. Go gateway 不再接收该渠道新流量
3. Python gateway 恢复接收该渠道流量
4. Python worker 继续消费 Python 队列
5. Go worker 处理 Go 队列存量消息

```

如果 Go worker 可以继续处理：

```text
入口切回 Python 后，让 Go worker 处理完 Go queue 存量消息。

```

如果 Go worker 不可用：

```text
1. 入口立即切回 Python
2. 暂停 Go worker
3. 保留 Go queue / Go DLQ
4. 根据原始 webhook、业务日志或转换脚本评估补偿

```
