# 公司知识库 Obsidian 式目录浏览改造 Spec

## 背景

当前公司知识库已经具备列表、上传弹窗、详情预览和版本能力的基础实现。用户希望公司知识库的详情页更接近 Obsidian 的浏览体验：左侧是目录树，右侧展示选中文件内容，并通过目录树上的行内菜单完成上传、建目录和删除。

本次改造只调整公司知识库的信息架构和交互规格。项目知识库的 `llm-wiki` 生成、更新、发布和来源追踪逻辑不在本 spec 范围内。

## 目标

- 公司知识库列表继续保留，用于创建、查看和删除知识库条目。
- 创建公司知识库时只填写知识库名称和描述。
- 创建成功后，系统自动生成一个根文件夹，根文件夹名称等于知识库名称。
- 进入公司知识库条目后，展示两栏 Obsidian 式界面：左侧目录树，右侧 Markdown 内容。
- 目录树中的文件夹和文件都支持行 hover 或选中时显示三点菜单。
- 文件夹三点菜单支持新建文件夹、上传文件、删除本文件夹。
- 文件三点菜单支持删除文件。
- 删除文件和文件夹都需要二次确认；确认后后端直接删除物理文件及对应数据库记录。

## 非目标

- 不增加最右侧文档信息栏。
- 不在创建知识库时上传初始文件或初始文件夹。
- 不展示或维护知识类型字段。
- 不做项目关联字段。
- 不做知识库内容自动归类。
- 不做 Obsidian 插件、双链图谱、反向链接面板或本地文件同步。
- 不把删除设计成逻辑废弃；本次确认后直接删除。

## 页面结构

### 公司知识库列表页

列表页管理的是公司知识库条目，不是单个文件。

列表字段：

| 字段 | 说明 |
| --- | --- |
| 知识库名称 | 公司知识库条目名称 |
| 文件数量 | 该知识库下未删除文件数量 |
| 状态 | 可用、处理中、转换失败等中文状态 |
| 更新时间 | 最近一次目录、文件或元数据变更时间 |
| 操作 | 查看、编辑、删除 |

创建入口：

```text
创建知识库
```

创建表单字段：

| 字段 | 是否必填 | 说明 |
| --- | --- | --- |
| 知识库名称 | 是 | 同时作为创建后的默认根文件夹名称 |
| 描述 | 否 | 用于说明该知识库用途 |

创建成功后：

- 后端创建公司知识库条目。
- 后端创建默认根文件夹。
- 根文件夹名称等于知识库名称。
- 前端跳转到该知识库详情页。

### 公司知识库详情页

详情页采用两栏布局：

```text
左侧：目录树
右侧：Markdown 内容区
```

左侧目录树：

- 展示根文件夹、子文件夹和文件。
- 根文件夹默认展开。
- 文件夹可展开和收起。
- 点击文件夹只切换当前目录选择，不改变右侧文件内容。
- 点击文件后，右侧展示该文件 Markdown 内容。
- 当前选中的文件夹或文件需要高亮。

右侧内容区：

- 未选择文件时展示空状态，引导用户从左侧选择文件或上传文件。
- 选择文件后展示 Markdown 预览。
- 文件转换中时展示转换中状态。
- 文件转换失败时展示失败原因和重新上传入口。
- 右侧不展示独立文档信息栏。

## 目录树交互

### 行内三点菜单显示规则

文件夹行和文件行都支持三点菜单。

显示时机：

- 鼠标 hover 到该行时显示。
- 该行处于选中状态时显示。
- 该行获得键盘 focus 时显示。

默认状态下不显示三点菜单，避免目录树过载。

三点按钮要求：

- 使用 Lucide `MoreHorizontal` 图标。
- 点击后打开 shadcn DropdownMenu。
- 按钮需要有可访问名称，例如“打开申请操作库菜单”。
- 菜单打开期间，该行保持高亮。

### 文件夹菜单

文件夹三点菜单项：

```text
新建文件夹
上传文件
删除本文件夹
```

#### 新建文件夹

入口：文件夹三点菜单。

行为：

- 在当前文件夹下创建子文件夹。
- 弹出轻量输入框或对话框，填写文件夹名称。
- 同级目录下文件夹名称不可重复。
- 创建成功后刷新目录树，并选中新建文件夹。

校验：

- 文件夹名称必填。
- 去除首尾空格。
- 禁止路径分隔符。
- 禁止只由点号组成的名称。

#### 上传文件

入口：文件夹三点菜单。

行为：

- 上传文件到当前文件夹。
- 支持 Markdown、TXT、DOCX、PDF。
- Markdown/TXT 可直接形成 Markdown 内容。
- DOCX/PDF 经后端转换为 Markdown 后展示。
- 上传成功后刷新目录树。
- 如果上传的是第一个文件，自动选中该文件并在右侧展示。

约束：

- 上传不需要选择项目。
- 上传不需要选择知识类型。
- 上传不出现“新建需求 / 追加到已有需求”。
- 上传不触发项目知识库生成或更新。

#### 删除本文件夹

入口：文件夹三点菜单。

行为：

- 点击后弹出二次确认。
- 确认后后端直接删除该文件夹、全部子文件夹、全部文件、对应数据库记录和物理文件。
- 删除成功后刷新目录树。
- 如果当前右侧正在展示被删除文件，右侧回到空状态。
- 如果删除的是当前选中文件夹，选择切回父文件夹。

保护规则：

- 根文件夹不允许删除。
- 删除非空文件夹时，确认文案必须明确提示会删除所有子内容。
- 后端必须校验目标文件夹属于当前公司知识库。

### 文件菜单

文件三点菜单项：

```text
删除文件
```

#### 删除文件

入口：文件三点菜单。

行为：

- 点击后弹出二次确认。
- 确认后后端直接删除物理文件、转换后的 Markdown 文件和对应数据库记录。
- 删除成功后刷新目录树。
- 如果删除的是当前正在预览的文件，右侧回到空状态。

保护规则：

- 后端必须校验目标文件属于当前公司知识库。
- 删除失败时保留当前目录树状态，并展示错误提示。

## 后端数据模型调整

现有公司知识库文档模型需要从“文档列表 + 版本文件”扩展为“知识库条目 + 目录树节点 + 文件节点”。

建议新增或等价支持以下概念：

### CompanyKnowledgeBase

表示公司知识库条目。

核心字段：

| 字段 | 说明 |
| --- | --- |
| id | 知识库 ID |
| name | 知识库名称 |
| description | 描述 |
| status | 状态 |
| root_folder_id | 默认根文件夹 ID |
| file_count | 未删除文件数量 |
| created_at | 创建时间 |
| updated_at | 更新时间 |

### CompanyKnowledgeFolder

表示目录树文件夹。

核心字段：

| 字段 | 说明 |
| --- | --- |
| id | 文件夹 ID |
| knowledge_base_id | 所属知识库 |
| parent_id | 父文件夹 ID，根文件夹为空 |
| name | 文件夹名称 |
| sort_order | 同级排序 |
| created_at | 创建时间 |
| updated_at | 更新时间 |

约束：

- 同一 `knowledge_base_id + parent_id` 下文件夹名称不可重复。
- 根文件夹名称随创建时的知识库名称生成。
- 根文件夹不可删除。

### CompanyKnowledgeFile

表示目录树文件节点。

核心字段：

| 字段 | 说明 |
| --- | --- |
| id | 文件 ID |
| knowledge_base_id | 所属知识库 |
| folder_id | 所属文件夹 |
| original_filename | 原始文件名 |
| display_name | 目录树显示名称 |
| file_type | 文件类型 |
| file_size | 文件大小 |
| raw_path | 原始文件存储路径 |
| markdown_path | Markdown 文件存储路径 |
| markdown_content | Markdown 正文或缓存 |
| conversion_status | 转换状态 |
| conversion_summary | 转换摘要或失败原因 |
| created_at | 创建时间 |
| updated_at | 更新时间 |

约束：

- 同一文件夹下文件显示名称不可重复。
- 文件路径必须通过 Storage 层生成和解析。
- 前端不得直接拼接本地文件路径。

## API 设计

接口命名可继续沿用 `/api/v1/global-knowledge` 前缀，但前端展示为“公司知识库”。

### 创建知识库

```http
POST /api/v1/global-knowledge/bases
```

请求：

```json
{
  "name": "申请操作库",
  "description": "申请相关页面和规则说明"
}
```

响应：

```json
{
  "id": "gkb-001",
  "name": "申请操作库",
  "description": "申请相关页面和规则说明",
  "status": "available",
  "root_folder_id": "gkfld-001",
  "file_count": 0,
  "created_at": "2026-06-13T10:00:00+08:00",
  "updated_at": "2026-06-13T10:00:00+08:00"
}
```

### 查询知识库列表

```http
GET /api/v1/global-knowledge/bases
```

返回列表字段：

- id
- name
- description
- status
- status_label
- file_count
- updated_at
- available_actions

### 查询目录树

```http
GET /api/v1/global-knowledge/bases/{base_id}/tree
```

返回：

```json
{
  "root": {
    "id": "gkfld-001",
    "type": "folder",
    "name": "申请操作库",
    "children": []
  }
}
```

### 新建文件夹

```http
POST /api/v1/global-knowledge/bases/{base_id}/folders
```

请求：

```json
{
  "parent_id": "gkfld-001",
  "name": "01-基础配置"
}
```

### 上传文件到文件夹

```http
POST /api/v1/global-knowledge/bases/{base_id}/folders/{folder_id}/files
Content-Type: multipart/form-data
```

字段：

- `files`: 一个或多个文件

禁止字段：

- `project_id`
- `knowledge_type`
- `document_name`
- `mode`
- `existing_document_id`

### 查询文件内容

```http
GET /api/v1/global-knowledge/bases/{base_id}/files/{file_id}
```

返回：

- file metadata
- markdown_content
- conversion_status
- conversion_summary

### 删除文件

```http
DELETE /api/v1/global-knowledge/bases/{base_id}/files/{file_id}
```

删除语义：

- 删除数据库文件记录。
- 删除原始物理文件。
- 删除转换后的 Markdown 文件。
- 更新知识库 `file_count` 和 `updated_at`。

### 删除文件夹

```http
DELETE /api/v1/global-knowledge/bases/{base_id}/folders/{folder_id}
```

删除语义：

- 根文件夹返回错误。
- 删除文件夹记录。
- 递归删除子文件夹记录。
- 递归删除所有文件记录。
- 删除所有关联物理文件。
- 更新知识库 `file_count` 和 `updated_at`。

## 文件存储

公司知识库文件独立存储，不混入项目目录。

建议目录：

```text
data/
  global-knowledge/
    bases/
      {base_id}/
        folders/
          {folder_id}/
            raw/
            markdown/
```

说明：

- 数据库保存相对存储路径。
- Storage 层负责解析和安全校验。
- 删除文件或文件夹时，必须先确认目标路径位于公司知识库存储根目录内。

## 权限与风险确认

第一版以管理员可维护为准。

| 操作 | 权限 | 是否二次确认 |
| --- | --- | --- |
| 创建知识库 | 管理员 | 否 |
| 新建文件夹 | 管理员 | 否 |
| 上传文件 | 管理员 | 否 |
| 删除文件 | 管理员 | 是 |
| 删除文件夹 | 管理员 | 是 |
| 查看目录和文件 | 管理员、测试工程师、访客 | 否 |

删除确认文案需要包含对象名称。

删除文件确认文案：

```text
确认删除文件“申请操作库-SPEC”吗？删除后将从后端移除文件和对应记录。
```

删除文件夹确认文案：

```text
确认删除文件夹“01-基础配置”吗？该文件夹下的子文件夹和文件也会一并删除，并从后端移除对应记录。
```

## 前端实现建议

页面结构：

```text
CompanyKnowledgeListPage
CompanyKnowledgeVaultPage
  CompanyKnowledgeTree
    TreeFolderRow
    TreeFileRow
  CompanyKnowledgeMarkdownPane
  CreateFolderDialog
  UploadFileDialog
  DeleteFileConfirmDialog
  DeleteFolderConfirmDialog
```

组件规则：

- 继续使用 `PageShell`、`ShellSection`、`Button`、`Dialog`、`DropdownMenu`、`MarkdownPreview`。
- 三点菜单使用 `MoreHorizontal`。
- 文件夹图标使用 `Folder` 或 `FolderOpen`。
- 文件图标使用 `FileText`。
- 删除菜单项使用 `Trash2`，并使用 destructive 语义。
- 目录树宽度固定或可拖拽调整；第一版建议固定宽度，避免新增复杂交互。
- 右侧内容区必须 `min-width: 0`，避免长 Markdown 撑破布局。

## 状态处理

空知识库：

- 左侧只显示根文件夹。
- 右侧显示空状态：选择左侧文件夹上传文件。

无文件选中：

- 右侧显示空状态。

文件转换中：

- 右侧显示转换中提示。

文件转换失败：

- 右侧显示失败原因。
- 用户可在所在文件夹重新上传文件。

删除成功：

- 目录树刷新。
- 当前选中对象被删除时，右侧回到空状态。

删除失败：

- 目录树不乐观移除。
- 展示错误 toast。

## 验收标准

1. 公司知识库列表不展示知识类型。
2. 创建公司知识库时只出现知识库名称和描述字段。
3. 创建成功后自动生成同名根文件夹。
4. 进入公司知识库详情页后显示两栏布局。
5. 左侧目录树能展示根文件夹、子文件夹和文件。
6. 右侧能展示选中文件的 Markdown 内容。
7. 文件夹行 hover、选中或 focus 时显示三点菜单。
8. 文件行 hover、选中或 focus 时显示三点菜单。
9. 文件夹三点菜单包含新建文件夹、上传文件、删除本文件夹。
10. 文件三点菜单只包含删除文件。
11. 新建文件夹后目录树刷新并选中新文件夹。
12. 上传文件后文件出现在当前文件夹下。
13. 删除文件前有二次确认。
14. 删除文件确认后，后端删除物理文件和对应数据库记录。
15. 删除文件夹前有二次确认。
16. 删除文件夹确认后，后端递归删除文件夹、文件、物理文件和对应数据库记录。
17. 根文件夹不可删除。
18. 前端不提交 `project_id`、`knowledge_type`、需求上传模式字段。
19. 前端 lint 和 build 通过。
20. 后端测试覆盖创建知识库、默认根文件夹、目录树查询、新建文件夹、上传文件、删除文件、删除文件夹、根文件夹不可删除。
