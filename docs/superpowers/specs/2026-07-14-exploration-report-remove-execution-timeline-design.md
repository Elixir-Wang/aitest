# 探索报告移除执行时间线设计

## 背景

站点探索完成后生成的 `report.md` 当前包含“执行时间线”章节，以 Mermaid Gantt 展示每次工具调用的顺序、耗时和失败状态。该内容属于执行诊断信息，不是用户需要消费的最终探索产物，并且会显著拉长报告、暴露底层工具名称、降低业务信息密度。

## 目标

- 新生成的探索报告不再包含“执行时间线”。
- 新生成的探索报告不再包含“工具调用顺序与结果”说明或 Mermaid Gantt。
- 保留探索过程页的实时执行记录。
- 保留 `timeline_events.jsonl`、`raw_events.jsonl` 等底层事件数据，继续支持排障。

## 非目标

- 不修改历史探索任务已经生成的 `report.md`。
- 不改变事件采集、事件投影或实时进度展示。
- 不新增是否生成时间线的配置开关。
- 不调整报告中的执行概览、目标达成、页面图谱、失败诊断和产物质量提示。

## 方案

在 `apps/backend/app/services/page_exploration/report_writer.py` 的报告生成阶段移除“执行时间线”章节，并删除只服务于该章节的 Mermaid Gantt 渲染与工具耗时映射代码。报告仍使用现有 `timeline_events` 计算执行概览、目标进度和失败诊断，因此不改变 `write_exploration_report` 的输入接口。

## 测试

扩展探索报告测试，验证报告仍包含目标、路径、失败诊断和质量提示，同时明确验证以下内容不存在：

- `## 执行时间线`
- `工具调用顺序与结果`
- Mermaid `gantt` 图块

运行页面探索报告相关的后端测试，确保报告生成和产物登记行为保持正常。

## 兼容性

该调整只影响新生成的 `report.md` 文本内容，不改变 API 响应结构、数据库结构、产物类型或事件文件格式。历史报告保持不变。
