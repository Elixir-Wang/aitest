# 接口场景测试集、批量运行与报告设计

## 1. 目标

- “批量运行”Tab 展示可复用的接口场景测试集列表。
- 用户通过“新建测试集”配置名称、描述、一个接口环境和多个接口场景。
- 同一测试集内同一个场景只能出现一次，并保留用户选择顺序。
- 测试集允许重复执行；每次执行创建一个独立批次并生成一份新报告。
- 执行时读取测试集中各场景当前已保存内容，不展示版本、发布或历史版本选择。
- 每次批次固定串行执行，单场景失败后继续执行后续场景。
- 报告进入报告中心“接口”Tab，一次批次对应一份确定性报告。

## 2. 核心概念

### 2.1 场景测试集

场景测试集是可保存、可编辑、可重复执行的配置，包含：

- 名称；
- 描述；
- 一个接口环境；
- 多个不重复的接口场景；
- 场景执行顺序。

测试集不保存场景内容副本。编辑场景并保存后，测试集下一次执行自然使用新的当前内容。

### 2.2 执行批次

执行批次表示测试集的一次实际运行：

- 同一测试集可以产生多个批次；
- 每个批次立即创建全部单场景子运行，冻结本次执行输入；
- 测试集或场景后续修改不影响已经创建的批次；
- 每个完成批次生成一份独立报告。

## 3. 数据模型

### 3.1 `api_scenario_suites`

- `id`
- `project_id`
- `api_environment_id`
- `name`
- `description`
- `created_by`
- `created_at`
- `updated_at`

### 3.2 `api_scenario_suite_items`

- `suite_id`
- `scenario_id`
- `position`
- `created_at`

约束：

- `UNIQUE(suite_id, scenario_id)`：同一个场景不能重复加入测试集。
- `UNIQUE(suite_id, position)`：一个顺序位置只能对应一个场景。

### 3.3 `api_batch_runs`

在现有批次表增加：

- `suite_id`：来源测试集，可为空；删除测试集后历史批次保留。
- `name`：执行时保存测试集名称快照。
- `api_environment_id`：执行时保存所用环境关联。

### 3.4 `api_automation_runs`

继续使用：

- `batch_run_id`
- `batch_position`

作为批次内每个接口场景的实际执行记录。

## 4. 后端接口

### 4.1 测试集 CRUD

- `POST /projects/{project_id}/api-scenario-suites`
- `GET /projects/{project_id}/api-scenario-suites`
- `GET /projects/{project_id}/api-scenario-suites/{suite_id}`
- `PATCH /projects/{project_id}/api-scenario-suites/{suite_id}`
- `DELETE /projects/{project_id}/api-scenario-suites/{suite_id}`

创建和修改请求：

```json
{
  "name": "核心接口冒烟",
  "description": "每日检查核心链路",
  "api_environment_id": "apienv-1",
  "scenario_ids": ["apiscn-1", "apiscn-2"]
}
```

服务端必须校验：

- 名称非空；
- 环境属于当前项目；
- 至少选择一个场景；
- `scenario_ids` 不重复；
- 所有场景属于当前项目。

### 4.2 执行测试集

- `POST /projects/{project_id}/api-scenario-suites/{suite_id}/runs`

执行步骤：

1. 读取测试集及按 `position` 排序的场景。
2. 校验场景当前为 `ready` 且包含启用步骤。
3. 创建一条新的 `api_batch_runs`。
4. 按测试集顺序立即创建全部单场景子运行。
5. 后台按顺序串行执行。
6. 聚合批次结果并生成报告中心投影。

每次调用都会创建新的批次，即使来自同一个测试集。

### 4.3 批次查询

- `GET /projects/{project_id}/api-batch-runs`
- `GET /projects/{project_id}/api-batch-runs/{batch_run_id}`

批次返回 `suite_id`，用于前端展示测试集最近执行情况。

## 5. 前端交互

### 5.1 测试集列表

“批量运行”Tab 复用“场景编排”列表风格：

- 搜索框；
- 批量删除；
- “新建测试集”主按钮；
- 表格列：名称、描述、环境、场景数、最近运行结果、更新时间、操作；
- 行操作：编辑、运行、删除。

页面不再直接展示全部场景并立即运行。

### 5.2 新建与编辑

使用弹窗完成配置：

- 测试集名称；
- 描述；
- 接口环境；
- 可搜索的场景多选列表；
- 已选场景数量；
- 同一场景不可重复选择。

编辑时展示当前配置。保存只修改测试集，不自动运行。

### 5.3 运行

- 点击行内“运行”后创建新的批次。
- 正在提交时禁用重复点击。
- 创建成功后提示已开始运行。
- 列表轮询正在执行的批次，更新最近运行结果。
- 完成后可进入报告中心对应报告。

## 6. 删除语义

- 删除测试集会删除测试集配置和测试集场景关联。
- 不删除由该测试集产生的历史批次、子运行、报告和执行证据。
- 历史报告继续展示执行时保存的测试集名称和环境。

## 7. 报告与 AI

- 一个批次对应一份接口报告。
- 同一个测试集重复运行会生成多份报告。
- 报告指标完全由确定性执行数据计算。
- 本期不接入 AI；后续 AI 只能作为失败诊断增强，不参与结果判定。

## 8. 验收标准

1. 批量运行 Tab 展示测试集列表和“新建测试集”入口。
2. 测试集可创建、编辑、删除和重复执行。
3. 同一测试集不能重复加入同一场景。
4. 测试集只允许选择一个接口环境。
5. 每次执行读取场景当前已保存内容。
6. 同一测试集每次执行都创建新的批次和报告。
7. 子运行按测试集场景顺序串行执行，失败后继续。
8. 删除测试集不影响历史批次和报告。
9. 报告中心接口 Tab 保持一批一报告。
10. 页面不出现发布版本或历史版本运行概念。
