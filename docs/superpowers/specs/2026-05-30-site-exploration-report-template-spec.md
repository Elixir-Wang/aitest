# 站点探索报告模板规范

## 背景

站点探索已经从单一 Markdown 报告升级为结构化探索证据包。当前探索产物包括 `run.yaml`、`summary.yaml`、`graph.yaml`、`blockers.yaml`、`pages/*.yaml` 和 `logs/run.log`。这些文件是探索事实源，用于后续知识库补充、需求评审、测试用例生成和 UI 自动化生成。

探索报告不再承担事实源职责。它的定位是面向测试人员、产品人员和知识库维护人员的总结材料，用于快速理解本次探索覆盖情况、关键结论、风险缺口和后续处理建议。

## 目标

- 固化探索报告的标准模板。
- 明确探索报告只作为总结和追溯入口，不作为知识库或测试用例生成的主事实源。
- 让报告能清楚回答本次探索是否覆盖目标范围、哪些模块可用、哪些模块存在阻塞、哪些事实需要人工确认。
- 报告内容必须能够追溯到结构化探索产物。
- 保持报告轻量，避免堆叠全量 YAML、全量日志、全量 locator 或测试用例草稿。

## 非目标

- 不把探索报告作为知识库正文。
- 不把探索报告作为测试用例生成的主输入。
- 不在报告中生成正式测试用例。
- 不在报告中生成正式业务规则。
- 不在报告中展开全量页面 YAML。
- 不在报告中展开全量 `graph.yaml` edge。
- 不在报告中展开全量 `logs/run.log`。
- 不在报告中提供操作按钮或流程操作入口。
- 不让前端根据报告内容反向推断探索事实。

## 设计原则

1. 报告是总结，不是事实源。
2. 结构化 YAML 和运行日志是权威事实源。
3. 报告中的结论必须能够追溯到 `summary.yaml`、`pages/*.yaml`、`graph.yaml`、`blockers.yaml` 或 `logs/run.log`。
4. 报告只能记录观察到的页面事实和探索结论，不能把页面现象直接提升为正式业务规则。
5. 知识库落库和测试用例生成应优先使用 `pages/*.yaml`、`graph.yaml`、`blockers.yaml` 以及知识库模块文件。
6. 报告只展示必要摘要，细节通过证据索引指向原始产物。

## 数据来源

| 报告模块 | 主要来源 | 说明 |
| --- | --- | --- |
| 报告摘要 | `run.yaml`、`summary.yaml` | 项目、站点、环境、范围、目标、状态和一句话结论 |
| 探索结论 | `summary.yaml`、`blockers.yaml` | 总体结论、下游可用性、关键阻塞和关键收获 |
| 探索范围与边界 | `run.yaml` | 站点 URL、登录方式、验证码、默认角色、禁止路径和 limits |
| 覆盖概览 | `summary.yaml` | 模块、页面、关系、阻塞等聚合指标 |
| 模块覆盖矩阵 | `summary.yaml`、`blockers.yaml` | 模块状态、页面覆盖、主要事实、阻塞和知识库可用性 |
| 页面事实摘要 | `pages/*.yaml` | 页面标题、URL、类型、状态、核心字段、核心操作和证据文件 |
| 页面关系与路径 | `graph.yaml` | 页面跳转、提交、弹窗、Tab、筛选、分页和数据依赖 |
| 阻塞与跳过 | `blockers.yaml` | 无法探索、跳过、安全拦截和建议处理 |
| 风险与缺口 | `summary.yaml`、`blockers.yaml`、`pages/*.yaml` | 权限、登录、验证码、页面事实缺口、locator 稳定性和下游风险 |
| 待人工确认事项 | `pages/*.yaml`、`graph.yaml`、`blockers.yaml` | 低置信事实、业务含义不明确、需要人工补充的内容 |
| 证据索引 | 探索产物路径 | 报告结论对应的事实源入口 |

## 字段规则

### 报告状态

报告状态使用探索运行结果的用户可读状态：

| 状态 | 含义 |
| --- | --- |
| 已完成 | 探索范围内核心模块已完成，未发现关键阻塞 |
| 部分完成 | 已生成有效事实，但存在未覆盖页面、非关键阻塞或低置信事实 |
| 阻塞 | 登录、权限、验证码、环境或安全策略导致核心探索不可继续 |
| 失败 | runner、编排服务或产物生成异常导致探索不可用 |

### 知识库可用性

模块覆盖矩阵中的知识库可用性使用以下值：

| 值 | 说明 |
| --- | --- |
| 可用 | 页面事实完整，可作为知识库补充来源 |
| 部分可用 | 存在缺口，但非核心事实可进入知识库并标记 warning |
| 不可用 | 核心流程或关键页面无法确认，不应进入知识库 |
| 待确认 | 系统无法判断业务重要性，需要人工确认 |

### 证据字段

证据字段只填写相对产物路径或文件名，不粘贴原始内容。

示例：

```text
pages/page-001-login.yaml
graph.yaml#edge-001
blockers.yaml#blocker-002
logs/run.log#log-0008
```

如果当前产物不支持锚点，可以先只写文件路径。

## 页面事实摘要规则

页面事实摘要只展示核心事实，不展示完整页面结构。

必须展示：

- 模块
- 页面
- URL
- 页面类型
- 页面状态
- 证据文件

可按需展示：

- 主要字段
- 主要操作
- 主要状态
- 关键说明

禁止展示：

- 全量 accessibility tree
- 全量 locator
- 全量 DOM
- 全量 YAML 原文

## 页面关系与路径规则

页面关系与路径只展示对理解探索结果和下游测试生成有价值的关系。

优先展示：

- 关键跳转路径
- 表单提交路径
- 弹窗打开和关闭
- Tab 切换
- 筛选和分页
- 状态变化
- 数据依赖

不展示：

- 重复分页边界
- 无业务意义的静态链接
- 外链内容
- 已被安全策略跳过且无下游价值的动作明细

## 阻塞与风险规则

阻塞与跳过必须区分：

- 阻塞：导致页面或模块无法继续探索。
- 跳过：由于禁止路径、外链、安全策略或用户范围配置而主动不探索。

风险与缺口用于说明下游使用限制，不能和阻塞表重复堆叠。风险描述应关注影响：

- 是否影响知识库补充。
- 是否影响需求评审。
- 是否影响测试用例生成。
- 是否影响 UI 自动化生成。

## 待人工确认规则

以下内容必须进入待人工确认事项：

- 页面观察到但不能直接确认的业务规则。
- 低置信数据依赖。
- 无法判断是否核心模块的模块。
- 阻塞模块是否允许跳过。
- 状态流转含义不明确。
- 探索事实和需求文档冲突。

## 生成位置

报告建议继续保存为 Markdown 文件：

```text
apps/backend/data/projects/{project_id}/exploration/{run_id}/documents/exploration-v1.md
```

该文件是派生产物。重新生成报告时，应从结构化探索产物重新派生，不应把旧报告作为事实源继续推导。

## 前端展示边界

探索详情页的“探索报告”tab 展示该 Markdown 报告。

要求：

- 不提供报告操作按钮。
- 不在报告页展示全量日志。
- 不在报告页展示全量 YAML。
- 不在报告页生成测试用例。
- 不在报告页写入知识库。
- 报告中的证据路径可以作为后续跳转或查看入口，但第一版不强制实现跳转。

## 与知识库和测试用例生成的关系

知识库落库和测试用例生成链路应使用：

1. `pages/*.yaml`
2. `graph.yaml`
3. `blockers.yaml`
4. 知识库 `modules/*.md`
5. 知识库 `maps/page-requirement-map.md`
6. 知识库 `maps/module-source-map.md`

探索报告只作为人工理解本次探索结果的总结材料，不作为生成链路的主输入。

## 验收标准

1. 新探索报告包含 11 个标准章节：报告摘要、探索结论、探索范围与边界、覆盖概览、模块覆盖矩阵、页面事实摘要、页面关系与路径、阻塞与跳过、风险与缺口、待人工确认事项、证据索引。
2. 报告中的结论能追溯到结构化探索产物。
3. 报告不展示全量 YAML、全量日志或全量 locator。
4. 报告不包含操作按钮或流程操作入口。
5. 报告不生成正式测试用例。
6. 报告不把页面事实直接提升为正式业务规则。
7. 阻塞、跳过、风险和待确认事项分区清晰，不互相混淆。
8. 证据索引包含 `run.yaml`、`summary.yaml`、`pages/*.yaml`、`graph.yaml`、`blockers.yaml` 和 `logs/run.log`。
