# API 场景响应提取两行卡片设计

## 背景

接口编排的“响应处理”用于把当前接口响应中的字段提取为具名输出，供后续步骤引用。当前编辑器使用固定四列布局：输出变量名、来源、提取路径、删除按钮。在右侧窄面板中，前两列占据固定宽度，导致提取路径只剩很窄的空间，出现 `$.data.segment_code` 被截断的问题。

## 目标

- 在窄侧栏中完整、可编辑地展示响应提取路径。
- 让用户明确理解“保存为”“来源”“提取路径”三个字段的关系。
- 保留当前响应提取数据结构和运行时行为，不改变接口编排语义。
- 为不同响应来源提供适配的输入提示，避免状态码仍显示无意义的路径输入框。

## 非目标

- 不重构响应提取的后端执行器。
- 不新增自定义脚本提取能力。
- 不在本次工作中重新设计断言、前置处理或后置处理。

## 交互设计

每条响应提取以两行卡片展示：

```text
保存为：segment_code       来源：响应 Body
提取路径：$.data.segment_code                         删除
```

### 第一行

- 左侧为输出变量名输入框，标签为“保存为”。
- 右侧为来源选择器，标签为“来源”。
- 来源选项保持现有三项：响应 Body、响应 Header、状态码。

### 第二行

- 提取路径输入框占据剩余宽度。
- Body 使用 `$.data.id` 作为提示。
- Header 使用 Header 名称作为提示。
- 状态码不显示或禁用提取路径输入框，并以说明文字提示“自动取 HTTP 状态码”。
- 删除按钮固定在右侧，点击后删除当前提取项。

### 必填行为

当前新增提取项默认为 `required: true`，运行时找不到值会终止当前步骤。为避免隐式行为，卡片中增加“未提取到时终止步骤”开关，映射到已有 `required` 字段；默认保持开启，兼容现有行为。

## 布局规则

- 默认使用两行 CSS Grid/Flex 布局，不依赖固定的 `150px + 170px + 1fr` 四列宽度。
- 变量名和来源在第一行按可用空间分配宽度。
- 路径输入在第二行 `min-width: 0`，允许完整编辑长路径。
- 外层不通过裁剪隐藏输入内容；必要时使用输入框原生滚动和 Tooltip 展示完整值。
- 桌面宽屏也保持两行结构，保证不同窗口宽度下视觉和操作一致。

## 数据与兼容性

- 保持 `ApiAutomationScenarioExtractor` 的 `name`、`source`、`expression/path`、`required` 字段不变。
- 前端继续兼容历史数据中使用 `path` 的记录，并在编辑时优先显示 `expression ?? path`。
- 不改变后端提取结果的变量命名、后续步骤引用方式和必填字段校验。

## 验收标准

1. 在截图所示窄面板宽度下，`$.data.segment_code` 等长路径可以完整查看和编辑，不被容器裁切。
2. 每条记录能直接看懂“保存为哪个变量、从哪里取、取哪个路径”。
3. 切换 Body、Header、状态码时，路径输入的提示或可用状态正确变化。
4. 新增、编辑、删除提取项后，保存的数据结构与现有接口兼容。
5. `required` 默认行为不回归，并能在界面中显式调整。
6. 现有响应提取契约测试继续通过，并补充两行布局和状态码路径行为的静态契约测试。
