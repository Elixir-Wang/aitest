# 站点探索模板步骤-执行双栏展示 Spec

## 背景

探索概览页当前把模板步骤、实时动作和结果摘要混在一起，用户很难一眼分清“先做什么”和“正在做什么”。

这次调整的目标是把目标探索改成明确的两栏结构：

- 左侧：探索模板步骤，按 todolist 方式展示
- 右侧：执行结果，按步骤和动作结果展示

## 目标

1. 智能体先按目标生成模板步骤，左侧优先展示步骤清单。
2. 步骤清单只回答“要做什么”，不混入执行细节。
3. 右侧按计划执行，展示每一步的动作、输入、输出、结果、错误。
4. 步骤与执行分离，避免左侧被实时日志刷屏。
5. 复用现有 `write_todos` / `todo_update` 链路作为步骤更新来源，不额外引入新的计划接口。

## 非目标

- 不新增后端接口。
- 不强制引入 TodoListMiddleware。
- 不把执行日志反向当成计划。
- 不在左侧展示原始 SSE 明细。
- 不重做探索报告页。

## 推荐方案

采用 `探索模板步骤` + `执行结果` 双栏：

```text
探索概览
  左侧：模板步骤
    - 模板名称
    - 目标摘要
    - 步骤列表
    - 当前进行中步骤

  右侧：执行结果
    - 当前步骤
    - 动作卡片
    - 输入 / 输出 / 错误
    - 历史步骤折叠列表
```

布局建议：

```text
lg:grid-cols-[360px_minmax(0,1fr)]
```

左侧宽度固定，适合 todolist 扫描；右侧自适应，适合步骤明细。

## 左侧模板步骤

左侧只展示模板步骤，不展示执行明细。

建议字段：

- 探索目标
- 入口 URL
- 范围
- 禁止路径
- 当前状态
- 步骤列表
- 当前进行中步骤

计划项展示规则：

- `pending` 显示待执行
- `in_progress` 高亮
- `completed` 打勾
- `blocked` / `failed` 显示异常

计划项内容尽量短，只保留人能快速扫过的文本。

## 右侧执行结果

右侧按步骤展示执行过程，优先展示：

- 步骤标题
- 动作名称
- 输入参数
- 输出结果
- 错误原因
- 耗时

规则：

- 当前步骤默认展开
- 历史步骤默认折叠
- 失败步骤默认展开
- 原始事件只放在折叠调试区

## 步骤来源

第一版建议继续复用现有步骤更新链路：

- 后端通过 `write_todos` 产生步骤更新事件
- 前端将其渲染为左侧 todolist

只有当后续需要把“先规划、再执行”做成 agent 标准能力时，才再评估 `TodoListMiddleware`。

## 需要删除的旧内容

1. 左侧旧的模块树式概览。
2. 左侧的当前焦点卡和完成度模型。
3. 左侧重复展示的实时动作摘要。
4. 任何把执行日志和步骤混在一起的展示。

## 验收标准

- 左侧能清楚看到模板步骤。
- 右侧能清楚看到执行步骤和结果。
- 页面不会因为实时日志增长而打乱左侧布局。
- 步骤更新只通过步骤链路展示，不新增重复状态源。
