# 知识库项目/公司页签实施 Spec

## 背景

知识库页面当前只有一个列表入口，无法区分项目知识库和公司知识库。已有 PRD 将知识库拆成两类：

- `docs/00-产品文档/00-05-AI测试系统-知识库生成与更新PRD.md` 定义项目知识库，按项目隔离，基于需求文档、站点探索、澄清写回和人工补充生成模块化 `llm-wiki`。
- `docs/00-产品文档/00-22-AI测试系统-全局知识库PRD.md` 定义全局知识库。产品界面按用户说法展示为“公司知识库”，用于跨项目复用的测试规范、用例模板、评审规则、自动化规范、平台 PRD、通用术语和团队方法论。

本次先补齐知识库列表上方的一级业务页签，并形成后续后端与前端实现的规格边界。

## 目标

- 在知识库列表上方增加两个页签：`项目知识库`、`公司知识库`。
- `项目知识库` 保持现有项目知识库能力入口，后续接项目知识库生成、更新、来源追踪和版本记录。
- `公司知识库` 对应 PRD 中的全局知识库，不绑定项目，不受顶部项目切换器过滤。
- 页面文案要让用户明确当前列表上下文，避免把公司知识误认为项目来源材料。

## 非目标

- 本次不伪造项目知识库或公司知识库列表数据。
- 本次不新增后端接口、不新增数据库表、不接上传弹窗。
- 本次不改变顶部项目切换器和左侧导航结构。
- 本次不把项目知识库内容自动提炼到公司知识库。

## 信息架构

知识库模块保留原有模块内页签：

- 知识库首页
- 来源材料
- 模块文档
- 更新预览
- 历史版本

在列表区域上方新增知识库范围页签：

| 页签 | 产品含义 | PRD 对应 | 项目上下文 |
| --- | --- | --- | --- |
| 项目知识库 | 当前项目的正式知识库版本和模块文档 | 项目知识库 | 后续按当前项目过滤 |
| 公司知识库 | 跨项目复用知识 | 全局知识库 | 不按当前项目过滤 |

说明：

- 用户口径使用“公司知识库”。
- 后端接口和模型可继续使用 `global_knowledge` 命名，前端显示中文公司知识库。
- 当顶部为“全部项目”时，后续可默认进入公司知识库；当顶部为具体项目时，后续可默认进入项目知识库。本次只提供页面内切换状态。

## 前端行为

### 项目知识库页签

- 列表标题：`项目知识库列表`。
- 主按钮：`生成知识库`。
- 搜索提示：`搜索模块、来源或版本`。
- 表格第三列显示：`来源`。
- 仍使用现有空数据，不展示静态 mock 行。

### 公司知识库页签

- 列表标题：`公司知识库列表`。
- 主按钮：`上传公司知识`。
- 搜索提示：`搜索公司知识、类型或版本`。
- 表格第三列显示：`知识类型`。
- 仍使用现有空数据，不展示静态 mock 行。

## 后续接口边界

项目知识库后续接口应围绕项目维度：

- 查询项目知识库构建列表。
- 查询项目知识库模块文档。
- 生成知识库。
- 更新知识库。
- 查询来源引用矩阵、构建阻塞和历史版本。

公司知识库后续接口应围绕全局维度：

- `POST /api/v1/global-knowledge/documents`
- `GET /api/v1/global-knowledge/documents`
- `GET /api/v1/global-knowledge/documents/{document_id}`
- 更新元数据、废弃、查看历史版本。

公司知识库上传禁止字段：

- 不显示或提交 `project_id`。
- 不显示关联项目。
- 不显示需求名称。
- 不显示新建需求/追加到已有需求。

## 数据准入规则

项目知识库：

- 只沉淀已确认的需求事实、页面事实、融合事实和测试关注点。
- 待确认问题、阻塞项、未确认冲突和失败诊断结果不能作为正式知识条目。
- 已发布版本不可原地覆盖，更新必须生成新 KnowledgeBuild。

公司知识库：

- 只保存跨项目可复用内容。
- 不保存项目专属客户名称、环境地址、账号、接口私有细节和项目业务状态流转。
- 下游 Agent 使用知识优先级为：项目知识库 > 公司知识库 > 模型通用知识。

## 验收标准

- 知识库列表上方可见 `项目知识库`、`公司知识库` 两个页签。
- 默认进入 `项目知识库`。
- 点击 `公司知识库` 后，列表标题、主按钮、搜索提示和表头文案切换为公司知识库语义。
- 点击 `项目知识库` 后，列表标题、主按钮、搜索提示和表头文案恢复项目知识库语义。
- 页面不新增任何静态 mock 知识库数据。
- TypeScript/前端 lint 不因本次改动新增错误。
