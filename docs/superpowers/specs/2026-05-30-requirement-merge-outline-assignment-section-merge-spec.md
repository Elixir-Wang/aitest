# 需求文档合并：新大纲生成、标题归属与章节合并 Spec

> 更新说明：本规范中的“AI 生成二级、三级目标大纲”和“旧块归属二级或三级模块”已被 `2026-06-05-requirement-merge-secondary-block-outline-spec.md` 收敛为新版主路径。新版主路径只在大纲阶段生成二级模块和来源块归属，三级标题改为模块正文生成阶段基于真实内容自动生成。后续实现以 2026-06-05 规范为准。

## 背景

当前需求文档合并流程已经从“按旧 fragment 直接拼接”调整为“大纲驱动合并”。
本次需要进一步收紧为三段独立流水线：

1. 先基于多个旧文档的二三级标题，生成新的统一目标大纲。
2. 再按批次将旧块标题归属到新大纲模块，只判断标题，不看块正文。
3. 最后按照新大纲顺序填充内容：
   - 只有 1 个旧块时，直接使用原块内容。
   - 多个旧块时，交给 AI 只在当前模块内独立合并。

本次明确约束：

- 每个旧块只能归属一个新模块。
- 不生成空章节。
- 每个 AI 步骤互相隔离，不共享上下文。
- 任一阶段失败即停止，不兜底，不伪造成功结果。

## 目标

1. AI 仅生成新大纲的二级、三级章节，一级标题由后端固定为需求名称。
2. AI 仅根据旧块标题、层级、路径、类型提示判断归属，不读取块正文。
3. 每个旧块必须且只能归属一个新大纲二级或三级模块。
4. 新大纲中每个二级、三级模块都必须至少命中一个旧块。
5. 按新大纲顺序逐章生成内容：
   - 1 块直接填充。
   - 多块独立调用 AI 合并。
6. 每个 AI 调用都只处理当前阶段、当前批次、当前章节，不依赖上下文记忆。
7. 失败不生成正式版本，不做规则兜底。

## 非目标

本次不做：

- 不恢复旧的 fragment 级全局拼接逻辑。
- 不允许一个旧块归属多个新模块。
- 不允许生成空章节后再人工补齐。
- 不在归属阶段使用块正文。
- 不让 AI 同时处理大纲生成、归属和正文合并。
- 不做失败后的关键词规则兜底。

## 业务规则

### 规则 1：目标大纲结构

- 一级标题由后端固定为当前需求名称。
- 二级、三级标题由 AI 基于多个旧文档二三级标题综合生成。
- 一级标题不由 AI 生成。
- 目标大纲只允许 `level=1/2/3`。
- 不允许跳级，不允许 `level>3`。

### 规则 2：旧块归属

- 归属阶段只看旧块标题，不看正文内容。
- 每个旧块只能归属一个目标模块。
- 目标模块只能是新大纲的二级或三级章节。
- 不允许归属到一级根节点。
- 不允许同一个旧块同时归属多个章节。
- 无法判断时应失败，不应扩散成多个候选归属。

### 规则 3：章节填充

- 每个新大纲章节必须至少有一个旧块归属。
- 不存在空章节。
- 一个章节只有 1 个旧块时，直接写入该旧块正文。
- 一个章节有多个旧块时，只在该章节内调用 AI 合并。
- 合并输出只属于当前章节，不允许跨章节生成内容。

### 规则 4：AI 隔离

- 生成大纲的 AI 不知道后续归属和合并结果。
- 归属阶段的 AI 不看块正文。
- 章节合并阶段的 AI 只看当前章节的归属块，不看其他章节。
- 不共享对话上下文，不依赖上一轮 AI 的自然语言记忆。

## 流程设计

### Step 0：结构化解析

后端先将多个原文档解析为两类数据：

1. 旧大纲节点：
   - `source_node_id`
   - `source_file_id`
   - `level`
   - `title`
   - `heading_path`
   - `content_type_hints`
   - `preserve_original`
2. 原始块内容：
   - 用于第三步章节合并
   - 不参与第二步归属判断

### Step 1：生成新大纲

输入给 AI 的内容：

- 当前需求名称
- 所有旧文档的二三级标题树
- 可选的标题级摘要或类型提示

输出要求：

- 只输出新的二级、三级章节。
- 不输出一级根节点。
- 不输出正文。

后端负责：

- 固定生成一级根节点，标题为需求名称。
- 校验新大纲层级合法性。
- 为所有节点生成稳定 `section_id`。

### Step 2：标题归属，按批次执行

归属阶段按批次处理旧块标题，建议按：

- 源文档分组
- 或二级标题分组
- 或固定批次大小分组

每个批次独立调用 AI。

输入只包含：

- 新大纲可归属章节列表
- 当前批次旧块标题列表

输入不包含：

- 旧块正文
- 其他批次的对话内容
- 上一轮归属结果的自然语言上下文

输出格式：

```json
{
  "assignments": [
    {
      "source_node_id": "A-03-02",
      "target_section_id": "sec-05-04",
      "assignment_type": "primary",
      "reason": "旧标题与 login_ticket 校验接口语义一致。"
    }
  ]
}
```

说明：

- `target_section_id` 只能是单值。
- 不允许数组。
- 不允许一对多归属。

### Step 3：按大纲顺序填充章节

后端按目标大纲顺序逐章处理。

对每个章节：

1. 找出所有归属到该章节的旧块。
2. 校验该章节至少有 1 个旧块。
3. 若仅 1 个旧块：
   - 直接使用原块正文。
4. 若超过 1 个旧块：
   - 调用章节级 AI 合并。
5. 生成该章节的最终内容后，写入新的合并稿。

### Step 4：章节级 AI 合并

该步骤只处理单个目标章节。

输入：

- 当前章节元信息
- 当前章节对应的旧块正文列表

输出：

- 当前章节合并正文
- 去重结果
- 冲突说明
- 覆盖到的旧块 ID 列表

该步骤不得：

- 修改其他章节
- 引入其他章节上下文
- 返回整篇文档

## 校验规则

### 新大纲校验

1. 只允许一个根节点。
2. 根节点必须为 `level=1`。
3. 根节点标题必须等于当前需求名称。
4. 二级、三级标题必须合法。
5. 不允许空标题。
6. 不允许正文混入标题字段。

### 归属校验

1. 每个旧块必须出现一次。
2. 每个旧块只能出现一次。
3. 每个旧块只能归属一个目标章节。
4. 目标章节必须是二级或三级。
5. 不允许归属到根节点。
6. 不允许未知旧块。
7. 不允许未知目标章节。
8. `preserve_original=true` 的旧块不得被忽略。

### 章节填充校验

1. 每个新章节必须至少命中一个旧块。
2. 仅 1 块时不得调用章节合并 AI。
3. 多块时必须调用章节合并 AI。
4. 章节合并结果不得越界影响其他章节。

## 失败策略

任一阶段失败即停止：

- 新大纲生成失败
- 归属任一批次失败
- 归属覆盖不完整
- 章节合并失败
- 任一输出 JSON 解析失败

失败后：

- 不写正式版本
- 不伪造候选稿成功
- 不使用兜底规则生成替代结果

- `section-merge-<section_id>.json`
- `section-merge-results.json`
- `stage-errors.json`

## 实施原则

1. AI 输入尽量小。
2. AI 输出尽量窄。
3. 每个步骤只做一件事。
4. 每个步骤结果都要能独立复核。
5. 不把“推理”和“拼装”混到同一个 prompt 里。
6. 后端负责最终结构正确性，AI 只负责局部判断或局部合并。
