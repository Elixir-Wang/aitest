# 接口编排测试编辑器重设计

## 1. 设计结论

接口编排测试不是“把多个接口用例放到一个列表里执行”，而是：

> 从接口资产中选择多个接口，按业务顺序组成执行链路，通过变量传递连接上下游请求，并对每一步响应进行校验和故障定位。

本次采用“增强线性编排”方案：

- 主链路从上到下顺序执行。
- 支持接口请求、条件执行、固定等待、轮询等待、数据赋值和清理步骤。
- 支持步骤启停、失败策略和始终执行。
- 不在首版支持任意连线、并行分支和循环容器。
- 接口步骤从接口资产 `ApiAutomationEndpoint` 创建，不从接口用例 `ApiAutomationTestCase` 创建。

## 2. 当前问题诊断

### 2.1 业务模型错误

当前前端 `ApiScenarioEditor` 加载接口用例列表，并通过 `addScenarioStep(caseId)` 创建步骤。步骤名称、请求和断言都以接口用例为起点。

当前后端也强化了这一错误关系：

- `_validate_scenario_definition` 要求每个步骤必须存在当前项目的接口用例。
- `_build_scenario_snapshot` 从接口用例读取请求、测试数据和断言。
- 即使步骤已有 `endpoint_id`，发布执行仍以 `api_test_case_id` 为核心。

这导致“接口资产”退化为用例的附属信息，无法表达真正的接口编排。

### 2.2 页面信息层级错误

当前页面把场景名称、场景变量 JSON 和描述长期放在主工作区，挤占了步骤配置空间；真正高频的请求参数、变量传递、响应提取和断言却使用四块原始 JSON 文本框表达。

结果是：

- 用户看不到完整业务链路。
- 添加步骤入口与业务概念不符。
- 配置过程依赖用户理解内部数据结构。
- 变量从哪里来、被谁消费不可见。
- 运行失败后缺少沿链路定位问题的能力。

## 3. 目标与非目标

### 3.1 目标

1. 用户能从接口资产快速选择一个或多个接口组成链路。
2. 用户能通过表单配置请求，无需手写内部 JSON。
3. 用户能把上一步响应字段保存为输出，并在后续步骤引用。
4. 编辑器能在运行前发现缺失变量、非法引用和无断言步骤。
5. 用户能沿执行链路查看每一步请求、响应、断言和变量快照。
6. 草稿能感知接口资产变化，已发布版本和历史运行保持稳定。

### 3.2 非目标

- 不建设任意拖线的低代码流程平台。
- 不在首版支持并行、汇聚和循环容器。
- 不把接口用例作为步骤添加来源。
- 不要求普通用户编辑 `bindings`、`extractors`、`assertions` 等底层 JSON。
- 不在编辑页长期展示场景描述等低频字段。

## 4. 核心领域模型

### 4.1 接口资产

接口资产描述一个可调用接口的稳定定义：

- HTTP 方法与路径。
- Path、Query、Header、Cookie 参数定义。
- 请求体 Schema。
- 响应状态与响应 Schema。
- 鉴权要求。
- 所属接口文档、标签和资产版本。

接口资产不保存某次场景中的具体数据值。

### 4.2 编排场景

编排场景描述一个完整业务链路：

- 场景名称、描述和场景级变量。
- 有序步骤列表。
- 默认环境与运行策略。
- 草稿状态、发布版本和资产差异状态。

### 4.3 编排步骤

接口步骤引用一个接口资产，并保存当前场景特有的配置：

- 步骤名称和顺序。
- 参数值与变量引用。
- 响应提取规则。
- 断言规则。
- 条件、等待和失败策略。
- 是否启用。

同一个接口资产可以被重复添加为多个步骤，每个步骤拥有独立配置。

### 4.4 步骤输出

步骤输出是从响应中提取的具名变量，例如：

- `登录.token`
- `创建订单.orderId`
- `查询订单.status`

后续步骤通过变量选择器引用输出。界面显示可读名称，持久化层使用稳定步骤 ID 和输出名，避免步骤改名破坏引用。

### 4.5 运行实例

每次运行生成不可变运行实例，保存：

- 使用的场景发布版本或草稿快照。
- 使用的环境快照。
- 每一步的开始时间、结束时间和状态。
- 脱敏后的请求、响应和变量快照。
- 断言明细、错误和跳过原因。

## 5. 页面信息架构

```text
返回  场景名称  草稿/版本/资产差异        环境  检查  发布  运行
----------------------------------------------------------------------
编排 | 场景变量 | 版本记录 | 场景设置
----------------------------------------------------------------------
执行链路                              当前步骤配置
从接口资产添加                        接口摘要 / 查看资产
                                      请求配置
1 登录                                响应提取
2 创建订单                            断言
3 查询订单                            执行控制
4 条件执行
5 清理数据
----------------------------------------------------------------------
最近运行摘要                                      展开运行结果
```

### 5.1 顶部栏

- 场景名称直接展示并支持就地编辑。
- 展示草稿、已发布版本、未保存和资产差异状态。
- 环境选择、检查、发布和运行属于顶部主要操作。
- 默认自动保存草稿；显式发布生成稳定版本。

### 5.2 次级导航

- `编排`：默认工作区。
- `场景变量`：维护场景级固定值和默认值。
- `版本记录`：查看发布版本、差异和回滚入口。
- `场景设置`：描述、标签、超时、默认失败策略等低频配置。

场景描述不再长期占据编排工作区。

### 5.3 两栏主工作区

- 左侧固定展示有序执行链路。
- 右侧只展示当前步骤配置。
- 接口资产选择器和运行结果使用按需抽屉，不增加永久第三栏。

## 6. 从接口资产添加步骤

点击“从接口资产添加”打开大尺寸选择器。

### 6.1 选择器结构

- 左侧：接口文档、服务和标签筛选。
- 中间：接口资产列表，支持方法、名称和路径搜索。
- 右侧：接口定义预览，包括参数、请求体、响应和资产版本。
- 底部：已选数量与“添加到链路”。

### 6.2 选择规则

- 支持单选和多选。
- 多选按选择顺序加入链路。
- 同一接口允许重复加入。
- 已废弃或存在破坏性变化的资产显示风险状态。
- 接口用例不出现在资产选择器中。

### 6.3 添加后的默认行为

- 步骤名称默认使用接口摘要，可独立修改。
- 请求表单根据资产 Schema 自动生成。
- 必填参数为空时显示待配置状态。
- 如果环境已提供公共鉴权，自动显示其来源而不是复制固定值。

## 7. 步骤配置

右侧配置区包含四个主页签和一个高级入口。

### 7.1 请求配置

按参数位置分组展示：

- Path
- Query
- Header
- Cookie
- Body

每个参数支持以下来源：

- 固定值。
- 场景变量。
- 环境变量。
- 前序步骤输出。
- 内置动态值，例如当前时间或随机 ID。

请求体优先使用 Schema 表单；提供只读 JSON 预览。复杂或未定义 Schema 时允许进入高级 JSON 编辑。

### 7.2 响应提取

- 优先从响应 Schema 选择字段。
- 允许输入 JSONPath、Header 名称或状态码来源。
- 每条提取规则必须定义输出名。
- 输出名在当前步骤内唯一。
- 输出在后续步骤的变量选择器中立即可用。

### 7.3 断言

断言使用规则行，而不是 JSON 文本框：

- 来源：状态码、响应 Header、响应 Body、响应时间、提取输出。
- 运算符：等于、不等于、包含、存在、类型、范围、正则、Schema 校验。
- 期望值：固定值或变量引用。
- 严重级别：失败或警告。

接口资产的响应 Schema 可用于快速生成基础断言，但是否采用由用户确认。

### 7.4 执行控制

- 是否启用。
- 执行条件。
- 超时时间。
- 重试次数与间隔。
- 失败策略：停止、继续、始终执行。
- 运行前后的高级脚本入口。

### 7.5 高级模式

高级模式以抽屉形式提供底层配置，不作为默认入口。它用于：

- 查看标准化步骤 JSON。
- 编辑复杂请求体。
- 配置暂未被可视化表单覆盖的高级规则。

## 8. 增强线性节点

首版支持以下节点：

| 节点 | 用途 |
|------|------|
| 接口请求 | 调用接口资产并校验响应 |
| 条件执行 | 满足条件时执行紧邻的目标步骤或跳过当前步骤 |
| 固定等待 | 等待指定时长 |
| 轮询等待 | 重复调用目标接口，直到断言满足或超时 |
| 数据赋值 | 创建或转换场景变量 |
| 清理步骤 | 标记为 `always_run`，用于清理测试数据 |

脚本节点属于高级能力，默认不出现在添加菜单。首版不支持并行、汇聚、循环容器和任意连线。

## 9. 变量与数据血缘

### 9.1 变量层级

变量选择器分为：

1. 前序步骤输出。
2. 场景变量。
3. 环境变量。
4. 内置动态值。

普通用户通过选择器插入变量，不需要记忆表达式语法。

### 9.2 数据血缘

系统自动记录：

- 输出由哪个步骤、哪个响应字段产生。
- 输出被哪些后续步骤和参数引用。
- 删除、禁用或移动步骤会影响哪些引用。

### 9.3 运行前校验

检查至少包括：

- 无启用步骤。
- 接口资产不存在或不属于当前项目。
- 接口必填参数缺失。
- 引用不存在的变量。
- 引用后续步骤输出。
- 步骤输出重名。
- 明显的变量类型不匹配。
- 条件表达式无效。
- 没有断言的接口步骤。
- 资产发生破坏性变化但尚未确认。

错误信息必须包含步骤名称、字段位置和修复入口。

## 10. 草稿、发布与接口资产版本

### 10.1 草稿

- 草稿步骤引用最新接口资产。
- 接口资产变化时显示差异状态。
- 用户可逐步骤查看参数、Schema 和鉴权变化。
- 破坏性变化未确认时禁止发布，但可继续编辑。

### 10.2 发布

发布时生成不可变场景版本，并冻结：

- 场景配置。
- 步骤顺序与步骤配置。
- 每个接口步骤使用的接口资产快照。
- 环境变量只冻结结构和引用，不冻结密钥值。

### 10.3 运行

- 默认运行最新已发布版本。
- 编辑器可显式“运行当前草稿”。
- 运行当前草稿时生成一次性快照，避免运行中资产变化。

## 11. 运行结果与失败定位

运行后在编辑器底部展开结果抽屉。

### 11.1 总览

- 每一步状态、耗时和执行顺序。
- 总耗时、请求数和断言通过数。
- 未执行、条件跳过和失败终止使用不同状态。
- 清理步骤即使主链失败也独立展示执行结果。

### 11.2 步骤详情

- 失败原因摘要。
- 脱敏后的实际请求。
- HTTP 响应和响应时间。
- 每条断言的期望值、实际值和结果。
- 当前步骤可见的变量快照。
- 重试和轮询记录。
- “回到步骤配置”入口。

### 11.3 重新运行

- 重新运行完整场景。
- 从失败步骤运行；系统复用此前成功步骤的输出快照，并明确标识为调试运行。
- 单步试运行当前接口；仅用于配置调试，不计入正式场景运行。

## 12. 数据模型调整建议

当前 `api_scenario_steps` 同时保存 `endpoint_id` 和 `api_test_case_id`，但校验、快照和运行依赖接口用例。建议改为以步骤类型和接口资产为中心。

### 12.1 场景步骤

建议的逻辑字段：

```text
id
scenario_id
step_type                 api_request | condition | wait | poll | assign
endpoint_id               仅接口类步骤必填
step_order
name
request_config_json
extractors_json
assertions_json
control_config_json
on_failure
enabled
created_at
updated_at
```

`api_test_case_id` 不再作为接口步骤的创建和执行依赖。为兼容旧数据可暂时保留为可空迁移字段，但新编辑器不写入它。

### 12.2 发布快照

接口步骤快照应包含：

```text
endpoint_snapshot
request_config
extractors
assertions
control_config
```

`endpoint_snapshot` 至少保存方法、路径、参数、请求体、响应和鉴权定义，不再从接口用例读取请求和断言。

### 12.3 运行步骤结果

每个运行步骤保存：

```text
step_id
step_type
status
started_at
finished_at
duration_ms
request_snapshot
response_snapshot
input_variables_snapshot
output_variables_snapshot
assertion_results
error
skip_reason
attempts
```

敏感 Header、Cookie、Token 和密钥必须在持久化前脱敏。

## 13. 现有代码必须纠正的边界

### 13.1 前端

- `ApiScenarioEditor` 不再加载 `listApiAutomationTestCases` 作为步骤来源。
- `addScenarioStep` 接收 `endpointId`，并根据接口资产创建空配置步骤。
- 现有四个 JSON 文本框替换为请求、提取、断言和控制的结构化编辑器。
- 场景名称保留在顶部，描述和变量移入次级页面。

### 13.2 后端

- `_prepare_scenario_step` 直接校验 `endpoint_id`，不通过 `api_test_case_id` 推导接口。
- `_validate_scenario_definition` 要求接口步骤拥有有效接口资产，而不是接口用例。
- `_build_scenario_snapshot` 从接口资产和步骤配置构建发布快照。
- 执行器从步骤快照生成请求，不读取接口用例的 `request_json`、`test_data_json` 和 `assertions_json`。

## 14. 视觉设计规范

### 14.1 视觉定位

界面定位为“专业测试工作台”，而不是普通后台表单或低代码画布：

- 专业、克制、清晰，优先保证长时间使用的舒适度。
- 保持项目现有蓝灰主题，不引入与主系统割裂的视觉语言。
- 通过颜色表达 HTTP 方法、数据依赖和运行状态，不使用无意义装饰。
- 使用适度阴影和层级分隔工作区，不为每个字段增加独立卡片。

### 14.2 色彩语义

- 主操作与当前选择：项目主蓝色。
- `GET`：蓝色。
- `POST`：绿色。
- `PUT/PATCH`：紫色或琥珀色。
- `DELETE`：红色。
- 数据引用与步骤输出：蓝色弱底色变量胶囊。
- 通过：绿色。
- 警告、资产变更和条件节点：琥珀色。
- 失败：红色。
- 未执行和禁用：中性灰色。

HTTP 方法色仅用于短标签，不能给整块步骤卡片大面积铺色。

### 14.3 层级与空间

- 顶部栏高度约 64 至 72 像素，承载场景身份和全局操作。
- 次级导航高度约 40 至 44 像素。
- 左侧执行链路建议宽度 360 至 400 像素。
- 右侧配置区占据剩余空间，并保证表单内容宽度不超过舒适阅读范围。
- 步骤卡片采用 10 至 12 像素圆角和轻量阴影；当前步骤使用左侧强调线和更明显的边框。
- 字段行使用分隔线形成表格节奏，不把每个输入框包进独立卡片。

### 14.4 执行链路视觉

- 步骤序号、HTTP 方法、步骤名称和接口路径构成第一视觉层级。
- 变量引用、输出数量、断言数量和轮询策略以紧凑胶囊展示。
- 相邻步骤通过细线连接，表达执行顺序，但不模拟可任意连线的流程图。
- 条件、等待和清理节点使用不同图标、边框样式和弱背景色。
- 拖动时展示明确插入位置，不只改变鼠标样式。

### 14.5 配置区视觉

- 当前接口方法、名称、路径、所属服务和资产版本在配置区顶部固定展示。
- 请求、提取、断言和执行控制使用页签切换。
- 参数表单按 Header、Path、Query 和 Body 分组。
- 参数值、来源和操作保持列对齐，便于批量扫描。
- 动态变量输入使用带来源标识的变量胶囊，不仅展示模板字符串。
- JSON 只作为预览或高级模式，不使用大面积空白代码框占据默认页面。

### 14.6 动效与反馈

- 步骤切换、抽屉展开和页签切换使用 160 至 220 毫秒过渡。
- 拖动排序、运行进度和校验定位允许使用功能性动效。
- 禁止大幅缩放、持续闪烁和纯装饰性动画。
- 自动保存、资产变化和校验结果在标题区持续可见，但不频繁弹出 Toast。
- 运行时步骤状态沿链路逐个更新，失败后自动聚焦失败步骤，但不强制跳走当前页面。

### 14.7 响应式策略

- 桌面宽屏使用完整两栏布局。
- 中等宽度压缩左侧链路宽度，隐藏非关键胶囊信息。
- 小于适合双栏的宽度时，左侧链路变为可展开侧栏，右侧配置保持主工作区。
- 不在移动端提供完整编排能力，只提供查看运行结果和基础操作。

### 14.8 视觉验收标准

1. 首屏无需滚动即可看到场景身份、执行链路、当前步骤和运行入口。
2. 用户能在三秒内识别当前步骤、接口方法和上下游顺序。
3. HTTP 方法色、变量色和运行状态色不互相混用。
4. 默认页面不出现大面积无内容区域和四块并列 JSON 文本框。
5. 页面同时展示五至七个步骤时仍保持清晰，不显得拥挤。
6. 资产变化、未保存、校验失败和运行失败均有稳定、可追踪的页面内状态。
7. 所有交互状态满足键盘焦点、颜色对比度和禁用态可识别要求。

## 15. 推荐实施顺序

1. 先纠正后端步骤、校验、发布快照和执行语义。
2. 改造接口资产选择器和接口步骤创建流程。
3. 实现请求参数结构化表单。
4. 实现响应提取、变量选择器和数据血缘校验。
5. 实现结构化断言和执行控制。
6. 实现运行结果抽屉与步骤级定位。
7. 最后补充等待、条件、轮询和清理节点。

## 16. 验收标准

1. 新建接口步骤时只能从接口资产选择器选择接口。
2. 不创建接口用例也能完成一个多接口串联场景。
3. 相同接口资产可以被多次加入同一场景。
4. 用户无需编辑 JSON 即可配置请求、响应提取和断言。
5. 后续步骤可以通过选择器引用前序步骤输出。
6. 非法变量引用在运行前被定位到具体步骤和字段。
7. 草稿能提示接口资产变化，发布版本不受后续资产变化影响。
8. 运行结果能沿步骤链展示请求、响应、断言和变量快照。
9. 场景失败时可以一键回到对应步骤配置。
10. 旧场景能通过迁移或兼容读取继续展示，但新场景不再依赖 `api_test_case_id`。

## 17. 实现说明（2026-07-14）

- 接口步骤以 `endpoint_id` 为新数据源，`api_test_case_id` 仅保留旧数据读取和审计用途。
- 发布版本冻结在 `api_scenario_revisions.snapshot_json`；恢复历史版本只覆盖草稿，不修改当前发布 revision 和 hash。
- 首版辅助节点已实现 `assign`、`condition`、`wait`、`poll`，清理步骤使用 `on_failure = always_run`。
- 结构化断言已实现 `jsonpath_type`、`response_time_max` 和基础 `schema_basic`；基础结构仅校验类型、必填属性和嵌套 properties/items，不实现完整 JSON Schema。
- 场景运行写入 `scenario-result.json`，记录步骤请求、响应、输入、输出、断言、轮询尝试、错误和跳过原因，并对授权头、Cookie、token、password、secret 与 API key 字段递归脱敏。
- 前端版本记录与运行诊断均使用独立面板；底部状态栏可展开步骤瀑布，并可从失败步骤返回配置区。
- 旧场景初始化迁移会根据 `api_test_cases.endpoint_id` 幂等回填缺失的 `api_scenario_steps.endpoint_id`，不会删除旧用例 ID。
- 任意连线、并行、汇聚、循环容器和完整 JSON Schema 继续按批准范围延后。
