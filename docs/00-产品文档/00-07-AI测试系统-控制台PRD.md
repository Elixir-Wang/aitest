# 00-07 AI测试系统 - 控制台 PRD

## 1. 这份文档解决什么问题

本文只细化控制台。控制台是用户进入系统后的第一工作台，用于展示测试资产健康度、待处理事项、最近任务和质量风险。

权限管理见：

- `00-02-AI测试系统-权限管理PRD.md`

项目管理见：

- `00-06-AI测试系统-项目管理PRD.md`

---

## 2. 控制台定位

控制台不是统计数字堆叠，而是回答：

- 当前测试资产建设是否健康
- 哪些事项需要处理
- 最近哪些任务失败或等待人工
- 哪些项目需要优先关注

---

## 3. 可见范围

控制台必须受页面右上角项目切换器约束。项目切换器不是装饰性筛选项，而是控制台所有指标、待处理事项、质量风险、最近任务和跳转目标的数据范围。

项目切换器支持两类分区：

| 分区 | 含义 | 控制台展示 |
| --- | --- | --- |
| 全部项目 | 当前用户可见项目的汇总视图 | 展示跨项目总览、项目排行榜、跨项目待处理和最近任务 |
| 指定项目 | 某一个项目的健康视图 | 展示该项目的需求、探索、知识库、用例、自动化和缺陷状态 |

角色可见范围：

| 角色 | 可选项目范围 |
| --- | --- |
| 管理员 | 全部项目 + 任意指定项目 |
| 测试工程师 | 自己被分配项目的全部汇总 + 被分配的指定项目 |
| 访客 | 全部项目 + 任意指定项目，只读 |

所有指标必须同时受“角色可见范围”和“项目切换器当前分区”影响。

---

## 4. 核心指标

| 指标 | 计算口径 | 点击后跳转 |
| --- | --- | --- |
| 项目数 | 未归档项目数量 | 项目列表 |
| 用例资产数 | 草稿、待评审、已采纳测试用例总数 | 测试用例列表 |
| 测试用例采纳率 | 已采纳用例数 / AI 生成用例总数 | 用例评审列表 |
| UI 自动化测试用例数 | 已生成 pytest + Playwright UI 自动化代码且可执行的用例数 | UI 自动化用例列表 |
| UI 自动化覆盖率 | UI 自动化测试用例数 / 已采纳测试用例数 | UI 自动化覆盖详情 |
| 发现缺陷数量 | 失败诊断中分类为产品 Bug 的数量 | 缺陷诊断列表 |
| 待处理事项数 | 待澄清、待评审、待诊断、自愈待确认、知识库待更新总数 | 待处理列表 |

不把“站点探索次数”作为核心指标。站点探索只作为任务类型、项目详情和最近任务展示。

核心指标的数据范围规则：

- 选择“全部项目”时，项目数展示当前用户可见的未归档项目数量，其余指标汇总当前用户可见项目。
- 选择“指定项目”时，项目数不再作为核心指标展示，建议替换为“项目状态”或“项目健康评分”；其余指标只统计当前项目。
- 指标点击后的跳转必须继承当前项目范围，例如从单项目控制台点击“待评审测试用例”时，只进入该项目的用例评审列表。
- 测试工程师选择“全部项目”时，不代表系统全部项目，只代表自己被分配项目的汇总。

## 5. 待处理事项

| 类型 | 说明 | 操作 |
| --- | --- | --- |
| 待回答澄清问题 | 需求分析提出但未回答的问题 | 回答问题 |
| 待评审测试用例 | AI 生成后未采纳的用例 | 进入评审 |
| 失败待诊断 | 自动化失败但未分类 | 进入诊断 |
| 自愈补丁待确认 | 已生成修复建议 | 查看补丁 |
| 知识库待更新 | 来源材料变化但知识库未更新 | 查看更新计划 |

待处理事项要按项目分组展示，避免用户只看到数字但不知道从哪里处理。

展示规则：

- 全部项目分区：待处理事项按项目分组，并显示项目名称、待处理类型和数量。
- 指定项目分区：默认不再按项目分组，按处理优先级、类型和更新时间排序。
- 访客可以查看待处理事项，但处理按钮禁用。

## 6. 最近任务流

| 字段 | 说明 |
| --- | --- |
| 任务名称 | 任务显示名 |
| 所属项目 | 可跳转项目 |
| 任务类型 | 需求分析、站点探索、知识库生成、用例生成、UI 自动化执行等 |
| 状态 | 排队中、运行中、等待人工、成功、失败、已取消 |
| 当前阶段 | 例如“等待确认冲突项” |
| 触发人 | 发起任务的用户 |
| 开始时间 | 任务开始时间 |
| 耗时 | 当前或最终耗时 |
| 结果入口 | 分析报告、探索文档、知识库版本、Allure 报告 |
| 下一步动作 | 回答问题、评审用例、确认更新、查看失败 |

最近任务流范围规则：

- 全部项目分区：展示当前用户可见项目的最近任务，并保留“所属项目”列。
- 指定项目分区：只展示当前项目任务，“所属项目”列可以弱化或隐藏。
- 点击任务详情后，面包屑和返回路径必须保留当前项目分区。

## 7. 质量风险区

第一版建议展示以下风险：

| 风险 | 说明 |
| --- | --- |
| 知识库待更新 | 来源材料已更新但知识库未更新 |
| 用例采纳率低 | AI 生成用例大量未被采纳 |
| UI 自动化覆盖率低 | 已采纳用例未转 UI 自动化 |
| 最近执行失败 | 自动化运行失败且未诊断 |
| 缺陷未处理 | 产品 Bug 分类后未闭环 |

风险项点击后必须跳到对应项目和列表。

质量风险范围规则：

- 全部项目分区：风险优先展示项目级风险排行，例如“知识库待更新项目 Top 5”“UI 自动化覆盖率最低项目 Top 5”。
- 指定项目分区：风险展示模块级或资产级问题，例如哪些模块缺用例、哪些已采纳用例未自动化、哪些失败未诊断。

---

## 8. 页面布局

建议布局：

1. 顶部标题区：控制台标题 + 右上角项目切换器
2. 顶部核心指标卡片
3. 左侧待处理事项
4. 右侧质量风险
5. 下方最近任务流

控制台不再使用“可选项目筛选器”这种弱表达，而是统一使用右上角项目切换器控制全页数据范围。

---

## 9. SQLite 存储策略

控制台第一版不单独建复杂报表表。

数据来源：

- 项目表
- 任务表
- 文档/需求分析表
- 知识库版本表
- 测试用例表
- 自动化执行表

接口自动化第一期不纳入控制台核心指标。导航可展示 Soon 入口，但不统计接口自动化用例数、覆盖率和执行结果。
- 失败诊断表

如查询变慢，后续再增加统计缓存表。第一版优先保证口径正确。

---

## 10. 验收标准

- 控制台右上角必须展示项目切换器。
- 管理员和访客可以选择全部项目或任意指定项目查看控制台。
- 测试工程师可以选择自己分配项目的汇总视图或指定项目视图。
- 控制台所有指标、待处理事项、质量风险、最近任务和跳转都必须继承当前项目切换器范围。
- 指标点击后必须跳到可解释的数据列表，不能只有数字。
- 最近任务必须能进入任务详情。
- 失败任务必须展示失败原因摘要。
- 待处理事项必须能跳转到可处理页面。
- 访客看到按钮时必须为只读或不可用状态。
