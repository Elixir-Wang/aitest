**接口**: `POST https://saibotan-pre.100credit.cn/openapi/sse/agent-dialog/lightweight-beta/dialog`

**复测日期**: 2026-07-02

**测试工具**: Windows PowerShell + `curl 8.21.0`

**测试环境**: `pre`

**凭证**: 使用用户提供的新 `cybertron_robot_key` / `cybertron_robot_token`，报告中已脱敏

## 1. 复测目标

- 使用新凭证重新验证接口行为
- 对照原 23 个场景确认鉴权、SSE、异常处理是否稳定
- 观察新凭证对应机器人/模型返回是否与上一轮不同

## 2. 复测范围

本次复测覆盖 23 个场景：

- 正常请求
- 特殊字符/短问句
- `question` 为空、缺失、空格、长文本
- `username`、`robot_key`、`robot_token` 缺失、为空、null、错误
- `segment_code`、`message_source` 缺失或非法
- 非法 JSON
- GET / OPTIONS 方法
- `Accept` / `Content-Type` 异常

## 3. 总体结论

- 新凭证可正常鉴权并返回 SSE 流
- 正常业务流均返回 `HTTP 200`、`text/event-stream`、`code=000000`
- 成功业务流均包含结束标记 `finish: "y"`
- 新凭证对应模型回答为“豆包/字节跳动开发训练的人工智能”
- 鉴权错误、必填缺失、方法限制、非法 JSON 的表现与上一轮一致
- 本轮未再大面积出现 `系统繁忙(201)`，仅 `question` 为空格时返回 `系统繁忙(203)`

## 5. 关键观察

### 5.1 正常请求

`TC01` / `TC02` 均正常返回模型身份：

- `TC01`: `我是由字节跳动开发训练的人工智能，基于豆包大模型为大家提供服务。`
- `TC02`: `我是由字节跳动开发训练的人工智能，基于豆包大模型为你提供服务~`

说明新凭证对应的机器人/模型配置与上一组凭证不同。

### 5.2 SSE 完整性

所有成功业务流均满足：

- HTTP: `200`
- Content-Type: `text/event-stream`
- SSE 业务码: `000000`
- 最后一条事件: `finish: "y"`

curl 仍返回 `curl: (56) Connection closed abruptly`，但已收到 `finish=y`，不影响本次按流式完整度判断结果。

### 5.3 鉴权与必填

核心鉴权逻辑稳定：

- 缺少或置空 `username` / `robot_key` / `robot_token`: `400001`
- `robot_token` 错误: `400002`
- `robot_key` 错误: `400001`

这些错误仍通过 SSE `data.code` 返回，HTTP 状态仍为 `200`。

### 5.4 非强校验字段

以下字段缺失或非法仍可进入正常业务流：

- `segment_code`
- `message_source`

需确认这是否符合业务预期。

### 5.5 系统繁忙

本轮不再大面积出现上一轮的 `系统繁忙(201)`。

仅 `question` 为空格时返回：

```text
系统繁忙(203)，正在处理中，请稍后重试
```

该场景仍表现为：

- HTTP: `200`
- 业务码: `000000`
- `finish: "y"`

因此客户端仍需识别成功流里的系统繁忙文本。

## 6. 风险点

| 风险 | 说明 | 建议 |
|---|---|---|
| 业务错误仍可能包装在 HTTP 200 内 | 鉴权错误通过 SSE `code` 表达 | 客户端必须解析 SSE 事件体 |
| 系统繁忙仍可能包装在成功流内 | 空格问题返回 `系统繁忙(203)` 且 `code=000000` | 客户端需识别最终回答内容或服务端增加明确错误字段 |
| 非法 JSON 返回 500 | 请求体格式错误未转成 4xx | 调用方先做 JSON 格式校验 |
| `segment_code` / `message_source` 非强校验 | 缺失或非法仍通过 | 后端/产品确认是否符合预期 |
| 浏览器直连存在预检风险 | `OPTIONS` 返回 405 | 前端直调需补 CORS 方案 |

## 7. 接入建议

- 客户端成功判断建议同时检查：
  - HTTP 状态
  - SSE `data.code`
  - 最后一条事件 `finish`
  - 最终回答内容是否包含系统繁忙或下游错误提示
- SDK 层建议将 `400001`、`400002`、`系统繁忙(201/203)` 归一为明确异常
- 调用方应在发起请求前校验 JSON 格式和核心必填字段
- 若该接口用于浏览器前端直接调用，需要补 CORS/OPTIONS 支持验证

## 8. 最终结论

使用新凭证复测后，接口整体表现正常：

- 新凭证可用
- SSE 流完整
- 正常问题可得到豆包模型回答
- 鉴权与方法限制稳定

仍需关注：

- `question` 为空格时出现 `系统繁忙(203)`
- 成功流中仍可能包含业务降级文本
- `segment_code`、`message_source` 未表现出强校验
