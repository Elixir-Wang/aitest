# 探索概览重设计审计

## 使用的 skill

- `redesign-existing-projects`：审计现有探索概览界面的视觉弱点和可升级点。
- `imagegen-frontend-web`：将升级方向收束为一张横向、可落地的高级前端视觉参考图。

## 当前界面诊断

1. 信息结构正确，但视觉层级偏平。
   当前代码保留了「探索阶段」和「对话与执行」两栏，这个结构是对的；问题在于阶段卡、执行日志、状态 badge 之间权重接近，用户第一眼不容易判断当前运行焦点。

2. 执行流更像日志列表，不像可追踪的 Agent 过程。
   事件之间只靠边线分隔，缺少“时间轴、工具调用、模型分析、结果证据”的类型区分。

3. 页面状态表达过度依赖蓝色。
   现有 primary 是蓝色，运行中、按钮、选中态也集中在蓝色系，容易读成单一调性。新版需要保留系统感，但加入 jade、amber、ink、slate 等状态层次。

4. 右侧缺少决策辅助。
   当前截图右侧空间主要承载日志内容延展。对测试人员来说，探索概览更需要快速回答：当前到哪一步、证据是否足够、有什么风险、下一步是什么。

5. 密度适合工作台，但缺少“高级产品”的材料感。
   现有设计是标准 shadcn/light dashboard 质感。升级应避免营销化 hero，而是用精密网格、玻璃分层、状态轨道、证据抽屉来制造专业感。

## 设计方向

- 主题：AI 测试任务指挥台，而不是普通日志页。
- 视觉：浅色冷静底色 + 深墨标题 + jade 运行态 + amber 风险态 + 少量 violet 表示模型思考。
- 架构：三列 cockpit。
  - 左：目标阶段轨道，强调当前阶段。
  - 中：Agent 执行流，按模型分析、工具调用、结果证据分层。
  - 右：运行洞察，提供覆盖、证据、风险和下一步。
- 签名元素：贯穿中间栏的“Agent execution spine”，让日志变成可读的执行轨迹。
