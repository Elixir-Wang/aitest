# 05-02 AI测试系统 - 导航与页面映射清单

## 1. 设计目标

本文定义 AI 测试系统第一版前端导航结构。前端基于 `next-shadcn-admin-dashboard-main`，沿用模板的分组导航能力，但第一版不在左侧侧边栏常驻展示二级菜单。

目标：

- 左侧导航只展示组名称和高频一级入口。
- 二级功能进入模块页面后，通过页面内 Tabs、子导航、卡片入口或面包屑承载。
- 左侧一级入口控制在 12 个左右，避免后台系统第一屏信息过载。
- 项目内能力必须在项目上下文中工作；项目上下文通过页面右上角项目切换器承载，不在左侧展开项目树。
- 项目切换器提供“全部项目”和“指定项目”两类工作分区；全局页面可选择全部项目，项目强绑定页面默认使用指定项目。
- 接口自动化第一期显示 `Soon`，不可选择，不允许创建、生成或执行。

---

## 2. 导航数据结构

第一版左侧导航只需要 `NavGroup -> NavMainItem`。模板虽然支持 `subItems`，但本系统第一版不把二级功能放入左侧常驻导航。

```ts
interface NavMainItem {
  title: string
  url: string
  icon?: LucideIcon
  comingSoon?: boolean
  disabled?: boolean
  projectScoped?: boolean
  requiredRole?: "admin" | "tester" | "guest"
}

interface NavGroup {
  id: number
  label: string
  items: NavMainItem[]
}
```

说明：

- `label` 是左侧导航组名称。
- `items` 是左侧一级模块。
- `projectScoped = true` 表示必须有当前项目。
- `comingSoon = true` 表示展示 `Soon` Badge。
- `disabled = true` 表示不可点击或只进入占位说明页。
- 二级页面不配置为左侧 `subItems`，统一由页面内部管理。
- `projectScoped = true` 的页面必须展示项目切换器，并且需要指定一个当前项目才能执行新增、生成、编辑、执行等写操作。

| 一级模块 | 路由 | 说明 |

| 一级模块 | 路由 | 说明 |

| 系统设置 | `/settings/system` | 文件存储、本地 Runner、Playwright、Allure、Agent 安全策略 |

## 5. 页面内二级导航映射

二级功能不放左侧侧边栏。用户进入一级模块后，在页面顶部或内容区使用 Tabs、Segmented Control、卡片入口或局部子导航切换。

| 一级模块 | 页面内二级功能 |
| --- | --- |
| 控制台 | 全局概览、待处理事项、最近任务、质量风险 |
| 任务中心 | 全部任务、等待人工、失败任务、任务详情 |
| 项目 | 项目列表、项目概览、项目设置 |
| 需求 | 文档管理、需求评审、分析结果、澄清问题、版本记录 |
| 探索 | 站点配置、探索任务、探索文档、候选需求文档、冲突项 |
| 知识库 | 知识库首页、来源材料、模块文档、更新预览、历史版本 |
| 测试用例 | 用例列表、用例评审、覆盖矩阵、版本历史 |
| UI 自动化 | 套件列表、代码查看、本地执行、Allure 报告、失败诊断 |
| 接口自动化 | Soon 占位说明 |
| 报告中心 | 运行记录、Allure 报告、失败诊断、内部 Bug 记录 |
| 模型配置 | Provider、模型用途、Agent 模型策略 |
| 用户与权限 | 用户管理、项目分配、个人配置 |
| 系统设置 | 文件存储、本地 Runner、Playwright、Allure、Agent 安全策略 |

页面内二级导航规则：

- 页面内二级入口只在进入对应一级模块后展示。
- 详情页、编辑页、新建页、版本 Diff 页、任务日志页、失败诊断详情页不进入左侧导航。
- 当前二级功能通过页面内 Tab 高亮，而不是展开左侧菜单。
- 面包屑展示当前位置，例如 `项目 / 知了平台 / 需求 / 澄清问题`。
- 项目上下文通过页面右上角项目切换器、页面标题和面包屑展示，左侧不重复展示项目层级。

## 6. 项目切换器与工作分区

项目是系统的第一业务隔离边界，但不作为左侧导航层级展开。第一版采用“左侧能力导航 + 右上角项目切换器”的结构，避免左侧同时承载项目树和功能树导致空间占用过大。

### 6.1 项目切换器位置

项目切换器固定出现在项目相关列表页、详情页和任务型页面的右上角，靠近页面标题区或工具栏。

推荐形态：

```text
项目：全部项目 ▼
项目：知了平台 ▼
```

项目切换器不是普通列表筛选条件，而是当前工作分区入口。用户切换项目后，当前页面、后续进入的项目相关模块和任务创建默认使用同一个项目上下文。

### 6.2 工作分区

| 分区 | 含义 | 适用页面 | 写操作规则 |
| --- | --- | --- | --- |
| 全部项目 | 跨项目查看汇总信息 | 控制台、任务中心、报告中心、项目列表 | 页面所有数据受全部项目分区约束；仅允许查看、筛选、汇总，不允许直接发起项目强绑定写操作 |
| 指定项目 | 在某一个项目内工作 | 需求、探索、知识库、测试用例、UI 自动化、项目详情 | 允许在权限范围内执行上传、生成、编辑、评审、执行等操作 |

### 6.3 页面默认规则

| 页面 | 默认项目范围 | 是否允许全部项目 | 说明 |
| --- | --- | --- | --- |
| 控制台 | 全部项目 | 是 | 所有指标、待处理、风险和任务都受项目切换器约束；可查看全局健康度，也可切到单项目健康度 |
| 任务中心 | 全部项目 | 是 | 查看全部任务，也可筛选单项目任务 |
| 项目 | 全部项目 | 是 | 项目管理入口，不依赖当前项目 |
| 需求 | 最近使用项目或用户默认项目 | 否 | 必须指定项目后才能上传、评审和编辑需求 |
| 探索 | 最近使用项目或用户默认项目 | 否 | 必须指定项目后才能配置站点和发起探索 |
| 知识库 | 最近使用项目或用户默认项目 | 否 | 知识库生成、更新、浏览都必须归属单项目 |
| 测试用例 | 最近使用项目或用户默认项目 | 否 | 用例生成和评审必须归属单项目 |
| UI 自动化 | 最近使用项目或用户默认项目 | 否 | 自动化代码生成和执行必须归属单项目 |
| 接口自动化 | 最近使用项目或用户默认项目 | 否 | 第一版 Soon，仅展示占位 |
| 报告中心 | 全部项目 | 是 | 支持跨项目查看报告，也可切单项目 |
| 系统管理 | 不使用项目切换器 | 否 | 模型、用户、系统设置是全局配置 |

### 6.4 交互规则

- 项目切换器显示用户可见项目；管理员和访客可见全部项目，测试工程师只可见分配项目。
- 进入项目强绑定页面时，如果没有默认项目，系统展示项目选择空状态，引导用户选择项目。
- 在项目强绑定页面选择“全部项目”时，系统不进入可编辑列表，而是提示“请选择具体项目后继续操作”。
- 高风险动作必须在确认弹窗中展示当前项目名称，例如生成知识库、批量生成用例、批量生成 UI 自动化、执行自动化。
- 切换项目后，页面列表、统计卡片、二级 Tabs、面包屑和新建按钮状态必须同步刷新。
- 用户最近使用项目和默认项目可以保存到个人偏好；测试工程师默认进入最近操作的已分配项目。

## 7. 权限与状态

| 角色 | 导航可见性 | 交互规则 |
| --- | --- | --- |
| 管理员 | 全部导航可见 | 全部可写，接口自动化 Soon 除外 |
| 测试工程师 | 工作台、分配项目相关入口、测试资产入口可见 | 可操作分配项目，系统管理不可写 |
| 访客 | 管理员可见内容基本可见 | 全部只读，写操作禁用，接口自动化 Soon 只展示 |

项目内导航如果没有当前项目：

- 管理员和访客进入项目列表选择项目。
- 测试工程师进入自己的项目列表。
- 如果没有可见项目，展示空状态。

## 8. 验收标准

- 左侧导航必须展示组名称。
- 左侧导航只展示高频一级模块，不常驻展示二级模块。
- 左侧一级入口包含：控制台、任务中心、项目、需求、探索、知识库、测试用例、UI 自动化、接口自动化、报告中心、模型配置、用户与权限、系统设置。
- 二级功能必须在页面内通过 Tabs、子导航、卡片入口或面包屑承载。
- 项目内模块必须展示右上角项目切换器。
- 控制台、任务中心、报告中心支持“全部项目”和“指定项目”两类分区。
- 需求、探索、知识库、测试用例、UI 自动化默认只允许指定项目工作，不允许在全部项目分区直接执行写操作。
- 项目内模块在没有项目上下文时不能进入无效页面。
- 接口自动化显示 `Soon`，不可选择，不允许创建、生成、执行。
- 访客可以看到只读入口，但写操作禁用。
- 移动端导航使用抽屉，点击一级模块后收起或进入对应模块页。
