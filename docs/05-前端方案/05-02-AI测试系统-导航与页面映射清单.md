## 5. 项目切换器说明

- 项目切换器通过 Zustand Store（`useProjectContextStore`）管理当前项目上下文，存储于 localStorage 的 `ai-testing.project.scope` 和 `ai-testing.project.current`。
- `project-context-store.ts` 中的 `getProjectScopedUrl` 函数负责将 `:projectId` 占位符替换为当前项目 ID。
- 侧栏中 `projectScoped: true` 的入口（性能测试、模型评测）在无项目上下文时显示为 disabled。
- 项目切换器显示在页面右上角 Header 区域（`workspace-shell.tsx` 第 61 行 `<ProjectSwitcher scope="project" />`），影响该页面及后续进入的项目相关路由。
- 当 scope 为 `all` 时，`projectScoped: true` 的路由 URL 中的 `/projects/:projectId` 前缀会被自动移除（如性能测试在全局视图下访问 `/performance-tests`）。

## 6. 权限与角色

### 6.1 角色定义

| 角色 | ROLE_RANK | 说明 |
| --- | --- | --- |
| admin | 3（最高） | 系统管理员，全部可写 |
| tester | 2 | 测试工程师，分配项目内可写 |
| guest | 1（最低） | 访客，全部只读 |

### 6.2 权限判定逻辑

权限判定逻辑位于 `nav-main.tsx` 第 33-46 行：

```ts
const ROLE_RANK: Record<"admin" | "tester" | "guest", number> = {
  admin: 3,
  tester: 2,
  guest: 1,
};

function hasRequiredRole(
  userRole: "admin" | "tester" | "guest" | undefined,
  requiredRole: "admin" | "tester" | "guest" | undefined,
): boolean {
  if (!requiredRole) return true;
  if (!userRole) return false;
  return ROLE_RANK[userRole] >= ROLE_RANK[requiredRole];
}
```

判定规则：`userRole` 的 ROLE_RANK 大于等于 `requiredRole` 时通过。即 admin 可以访问所有页面，tester 可以访问无 `requiredRole` 或 `requiredRole` 为 `tester` 的页面，guest 仅可访问无 `requiredRole` 的页面。

### 6.3 角色可见导航

| 角色 | 可见导航 | 交互规则 |
| --- | --- | --- |
| admin | 所有导航（含系统管理） | 全部可写 |
| tester | 工作台、分配项目相关入口、测试资产入口 | 分配项目内可写，系统管理不可写 |
| guest | 工作台、测试资产入口 | 全部只读 |

## 7. 根路径冲突

### 7.1 冲突说明

存在两个映射到 `/` 的 `page.tsx` 文件：

| 文件 | 用途 |
| --- | --- |
| `apps/frontend/src/app/page.tsx` | 主入口路由，根据登录状态 redirect |
| `apps/frontend/src/app/(external)/page.tsx` | 外部访问兜底路由，直接 redirect |

### 7.2 源码对照

**`app/page.tsx`**（有状态条件跳转）：

```tsx
// 行 1-32
export default function Home() {
  const router = useRouter();
  const { hasHydrated, hydrate, token } = useAuthStore();

  useEffect(() => {
    hydrate();
  }, [hydrate]);

  useEffect(() => {
    if (!hasHydrated) return;
    router.replace(token ? "/dashboard" : "/auth/v1/login");
  }, [hasHydrated, router, token]);

  return (
    <div className="flex min-h-dvh items-center justify-center text-muted-foreground text-sm">
      <Spinner className="mr-2 size-4" />
      正在进入 AI 测试系统
    </div>
  );
}
```

**`app/(external)/page.tsx`**（无条件立即跳转）：

```tsx
// 行 1-6
export default function Home() {
  redirect("/dashboard");
  return <>Coming Soon</>;
}
```

### 7.3 Next.js 路由组行为

Next.js 路由组 `(external)` 不会产生 URL 前缀，因此两个 `page.tsx` 都映射到 `/`。当用户已登录时，`app/page.tsx` 的跳转逻辑会先执行；未登录时则由 Next.js 的 `(external)` 路由兜底。

以下规则以源码为唯一核对依据：

| 规则 | 依据路径 |
| --- | --- |
| 侧栏一级导航与 `sidebar-items.ts` 完全一致 | `apps/frontend/src/navigation/sidebar/sidebar-items.ts`（行 49-156） |
| 每个路由必须有对应的 `page.tsx` 文件 | `apps/frontend/src/app/` 目录下 Glob 搜索结果（56 个文件） |
| 接口自动化非 Soon，是正式入口 | `apps/frontend/src/app/(main)/automation/api/page.tsx` 存在 |
| 模型评测是 `comingSoon: true` 和 `disabled: true` | `sidebar-items.ts` 中对应项 |
| 不存在 `test-plans` 相关路由 | 全库 Glob 搜索无 `test-plans` 路由 |
| 性能测试通过 `projectScoped: true` 进入项目上下文 | `sidebar-items.ts` + `nav-main.tsx`（行 200-206） |
| SSE 流用于性能测试运行详情 | `apps/frontend/src/lib/api-client.ts` 中 `streamPerformanceRun` |
| `/settings/system` 有路由但不在侧栏 | `app/(main)/settings/system/page.tsx` 存在但 `sidebar-items.ts` 中无此项 |
| 角色过滤通过 ROLE_RANK 数值比较实现 | `nav-main.tsx`（行 33-46） |
| 项目切换器 URL 解析函数 | `project-context-store.ts`（行 21-35）`getProjectScopedUrl` |
| 面包屑通过 Context API 管理 | `workspace-breadcrumbs.tsx`（行 1-84）`WorkspaceBreadcrumbProvider` / `WorkspaceBreadcrumbs` |
| 根路径冲突：两个 `page.tsx` 均映射 `/` | `app/page.tsx` + `app/(external)/page.tsx` |
| 应用壳通过 `WorkspaceShell` 包裹主布局 | `layout.tsx`（行 1-7） |
